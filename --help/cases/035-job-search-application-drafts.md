# UC-035：找到符合工時與薪資的職缺，準備逐份可核對的申請草稿

- 情境：工作
- 標籤：求職、履歷
- 網站標題：找合適職缺，把履歷改成有根據的申請草稿
- 一句話用途：把自己的真實經歷對照職缺要求，整理適合申請的清單與材料，再由本人核准送出。
- 工具：ChatGPT dots／Work（原作者歸屬不明）；兩則 Grok Bot 失敗／險些出錯案例另列，不混為同一產品。
- 分類：求職與職涯
- 證據狀態：社群作者自報；有流程，無公開申請紀錄或結果驗證；整理者改寫的保守流程未實跑。
- 查證日期：2026-10-14；2026-10-15 補第二則 Grok Bot 反例（台灣時間）

## 可以幫你做什麼

這個用途有別於一般履歷潤稿：把求職條件、實際職缺和可證明的經驗連在一起，留下每一份申請使用哪個版本、還缺哪些事實的紀錄。是否適合、是否投遞及回答內容仍由本人決定。

## 怎麼開始（整理者自設，未測）

1. 用刪除聯絡資料的履歷副本或虛構範本試跑，先列工作地點、工時、薪資與不能接受的條件。
2. 只搜尋可公開讀取的職缺，記錄企業官方連結、查閱時間、地點、要求及申請狀態；不猜測未刊薪資或遠距資格。
3. 每一條職缺要求都對照履歷的具體依據。未具備的技能列成缺口，不能改成已有經驗。
4. 人選出候選職缺後，才準備對應履歷及問答草稿，標示所有需要本人確認的敘述。
5. 在送出前逐一核對收件公司、職位、資料欄位、附件版本與聲明內容。只在明確批准該目的地與資料後送出；本案例沒有代投遞。

## 可貼指令（自設未測，非原文）

請根據這份已去除聯絡資料的履歷副本，以及我列出的地區、薪資與工時條件，找五個公開且仍可查看的職缺。每項附官方來源、查閱時間、必要資格、我已有的證據及缺口；不符合硬條件的另列，不要硬湊五個。先給我清單，不登入、不上傳、不投遞。我選定職缺後，再為每個職缺準備履歷改寫和問答草稿，逐項標出改動依據。不要發明年資、作品、資格或薪資。遇到國籍、工作許可、健康、背景查核或其他需要本人判斷的問題，留白請我確認。不要建立持續搜尋排程，除非我另行批准頻率與停止條件。

## 權限、費用與限制

- dots／Work 的可用方案不能從這篇互相修正的留言定案；以自己的帳號介面與 [OpenAI dots 官方介紹](https://learn.chatgpt.com/docs/dots) 核對。原串沒有可核的單次耗用或成本。
- 公開搜尋不等於有權登入求職站、上傳履歷、接受平台條款或投遞。必須核對招聘方及網站真偽，避免將完整履歷散發到無關平台。
- 任何付費訂閱、付費履歷服務或持續排程均需另定預算與範圍。不要把求職者為自己準備申請，混同為替雇主自動篩選求職者。
- 網站可讀取程度、表單與反自動化限制不同；受阻就停，不保證自動填完或送出。所有面試與聘用結果主張均未核實。

## 驗收

抽查職缺是否存在、條件是否真的匹配、履歷是否完全有據、是否保存正確版本，以及是否有任何未授權送出。收到草稿不是已投遞，投遞成功不是已獲面試。


## Grok Bot 反例：不能只確認部分欄位，也不能靠一句「停」驗收（2026-10-14）

由[Bot Store彙整](https://bot.store/academy/what-people-use-grok-bot-for)追到[Reddit原作者Numerous_Finance1498](https://www.reddit.com/r/GrokBot/comments/1w3081y/had_a_really_bad_experience_with_grokbot/)，英文；原串顯示相對時間，精確發布日未核。作者稱搜尋職缺尚可，但代理未核准自訂問答就送出；一次送出後又反覆嘗試同家公司，口頭說停止卻仍操作。這是歷史失敗自报，無完整工具紀錄、根因或修復驗證，不能當現行普遍故障。

本庫新增驗收設計：以「公司＋職缺ID＋申請版本」記錄狀態；核准單須包含所有自訂問題與附件，而非只核基本資料。已送出或结果不明时停止重試，先查實際回執；不要因對話說停了就宣布完成，需確認執行中的作業與排程確已停止。練習只用虛構表單，不重現真實重複投遞，也不推薦直接重設電腦作通用修復。

## Grok Bot 反例二：長對話中轉交其他代理，內部筆記差點貼進申請表（2026-10-15 補充）

- 作者：@aaditya_roy_04；英文；發布 2026-10-14 21:41（台灣時間）
- 網址：https://x.com/aaditya_roy_04/status/2110365316043923658
- 證據：`author-demo`（作者自述＋2 張申請表截圖）；本庫未重現。
- 作者說的情境（改寫）：他刻意在同一個長對話裡，讓 Grok Bot 依履歷連續填多份求職申請，想測上下文容量與幻覺；並允許 Bot 在它認為合適時，把工作轉交 Grok Build、Antigravity 等程式代理。因前面表現不錯，他一度告訴 Bot 可以直接送出，後來才改口要求「送出前先給我看」。
- 作者報告的問題：對話變長後，連原本 Bot 自己就寫得不錯的第一人稱問答，也被轉給其他代理寫；代理的回答連同它自己的備註被直接貼進表單。截圖中，「為什麼想來這家公司」欄位出現了薪資策略說明（職缺薪資區間與自己鎖定的較高區間）和「我會在某平台附上程式連結申請」這類寫給自己看的話，表單停在「Send application」按鈕前。作者說，要不是他後來要求先看，這份就送出去了。
- 作者的改善想法：在 Bot 裡加入明確、以變數界定的規則，避免這種事在任何情況再發生；他也認為處理個人資料的個人代理應內建這類防護。這是作者建議，不是官方已提供的功能。
- 缺口：沒有公開對話紀錄、Bot 設定、哪份申請是哪個代理寫的；本庫不推論普遍故障率。

本庫補充的驗收點（整理者設計，未實跑）：

1. 允許轉交其他代理時，規定「回來的文字只能當草稿」，貼進表單前要先刪掉任何寫給自己或給代理的說明、計畫、括號註記與薪資談判策略。
2. 送出前的核准單要列出每個自訂問答的最終全文，而不是只說「已填好」；對話很長時，先開一個新對話重新核對。
3. 前面說過「可以直接送出」的授權，不因表現好而延伸到後續每一份；每份都重新確認公司、職缺與內容。
