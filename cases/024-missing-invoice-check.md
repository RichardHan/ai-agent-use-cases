# UC-024：找出可能漏開的帳單

- 網站標題：讓 dots 檢查已交付工作，找出可能漏開的帳單
- 一句話用途：將交付紀錄與開單清單交叉比對，準備待確認的請款草稿。
- 工具：ChatGPT dots／指定文件與連接
- 證據狀態：官方轉述早期使用者經驗；未獨立實測
- 查證日期：2026-10-13



### 來源與證據

- 來源：[Introducing dots](https://openai.com/index/introducing-dots/)
- 作者：OpenAI
- 日期：2026-09-29
- 語言：英文
- 證據類型：**官方轉述早期使用者經驗**；不是作者本人操作教學，也不是本次實測。
- **來源支持的核心：** OpenAI 描述一位早期測試者漏向出版單位開單；dot 察覺後準備帳單，取得本人批准才寄出。
- **證據界線：** 官方沒有提供姓名、帳單樣式、會計軟體、稅額處理、收款結果或完整提示詞。以下是由該情境啟發的原創檢查流程。

### 適合誰

接案工作者、自由撰稿人、小型工作室；重點是找出需要本人確認的漏項，不是自動判定債權或替代帳務審核。

### 建議操作步驟（原創，未實測）

1. 從本人挑選的交付記錄與既有開單清單開始，先用去識別化副本試做一次。
2. 以案件編號或明確對應關係比對；名稱近似但無法確定時列入待確認，避免誤判重複或漏開。
3. 對疑似漏項只產出草稿，金額、幣別、付款條件必須來自使用者提供的資料。
4. 本人核對收件人、重複開單與條件。任何寄出、修改帳務系統或催款都是後續另行授權的行動。

### 原創提示詞｜UNTESTED

> 我附上這個月的交付紀錄與已開單清單。請列出「已有明確交付紀錄，但找不到對應帳單」的候選案件，並逐筆引用兩份資料中的依據。證據不足就標待確認，不要判定對方欠款。先針對我選定的案件產出請款草稿；缺少金額、幣別、稅務欄位或付款條件就問我，不自行補值。不要寄信、不要登入付款服務，也不要修改帳務紀錄。

### 權限、費用與限制

- 初次試用可只提供必要資料的副本；避免將銀行資料、稅籍識別碼等不需要的內容帶入範例。
- 如要寄出，需另確認正確收件人與確切內容。官方故事明確保留了批准步驟；不能改寫成「自動發送所有帳單」。
- 費用：適用本頁共通方案說明；第三方帳務工具可能有自己的方案，官方故事未指定工具或價格。
- 編輯建議：不要宣稱符合任何地區電子發票或稅務規範；本案例沒有這方面的驗證。
- 預期可檢查的成果：疑似漏項、比對依據、缺少欄位、待批准草稿。
