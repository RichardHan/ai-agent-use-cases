# UC-046：把關注帳號的貼文整理成每日精選，少刷時間線

- 情境：工作
- 標籤：X、排程、去重、簡報
- 網站標題：不想一直刷 X？讓 Bot 每天把關注的人整理成一份去重精選
- 一句話用途：固定時間讀取你關注的帳號，跟前一天去重，依作者分節列出重點與原帖連結；用來減少刷時間線，不保證涵蓋全部貼文。
- 核心目標：把分散在時間線的高品質貼文，變成可追溯原帖、可抽查覆蓋範圍的定時簡報。
- 工具：Grok Bot（X 讀取＋routine）；社群另有 Notion、Obsidian 輸出與 ChatGPT dots 版本（未核）。
- 分類／標籤：資訊整理／X／排程簡報／去重
- 目標使用者：靠 X 追蹤業界動態、但不想被營銷號和重複轉貼淹沒的人
- 首次收錄／最近查證：2026-10-14／2026-10-14（台灣時間）
- 證據狀態：`author-demo`（作者自述日常使用＋公開提示詞與輸出截圖）＋ `official`（Grok Bot X 讀取與 routine 文件）＋ `designed`（本庫提示詞）；dots 版本 `unverified`
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：要涵蓋的帳號範圍（自己關注的帳號，或明確列出的名單）、語言、時間窗與時區、前一天的精選存檔（用來去重）。
- 輸出：一份私人簡報：開頭 3 句「今日主線」；每位作者一節，2–4 條「主題：重點＋原帖連結」；零碎工具另列；最後交代實際讀了多少帖、時間範圍與去重是否完整。

## 建議操作流程（本庫設計，未實跑）

1. 先手動跑一次：只用明確列出的 10–20 個帳號，不讓 Bot 自行加帳號；指定時區與時間窗。
2. 要求每次把當期簡報存成檔案（含已收錄原帖 ID），下一期用它去重；沒有存檔時，簡報開頭須明講「本期去重不完整」。
3. 每條重點必附原帖連結；推測或 Bot 自己的看法另外標示，不混入作者原意。可保留一句短引文，保留作者語氣。
4. 簡報末尾列覆蓋資訊：讀了幾個帳號、幾則貼文、讀不到的帳號或錯誤。
5. 手動版抽查兩三天沒問題後，再設 routine；第一週每天抽查 2 條原帖是否摘要正確、有無漏掉重要貼文。
6. 輸出到 Notion／Obsidian 時，只給寫入指定頁面或資料夾的權限。


## 所需連接、權限與限制

- Grok Bot：讀公開帳號貼文不需連 X 帳號；讀「我的首頁時間線」要加 X 外掛並登入（見 S-046D）。X API 額度與超出後的費用要另外核對。
- 輸出到 Notion／Obsidian 等需另外的寫入授權；範圍限定在單一頁面或資料夾。
- 精選是摘要，可能漏帖、誤讀諷刺或斷章取義；做決策、轉述或引用前要點回原帖。
- 不要把私訊、私人名單或付費內容放進可分享的簡報。

## 驗收與可重現性

- 隨機抽 3 條重點，點原帖核對摘要與作者原意一致。
- 比對簡報與實際時間線，看有沒有明顯漏掉的重要貼文；連續兩期有無重複收錄。
- routine 啟用後，查最近幾次執行紀錄的實際完成時間（可參考 UC-008 的準時性驗收）。
- 本庫未重現；所有作者版本都是自述或截圖，沒有漏收率或費用數據。
