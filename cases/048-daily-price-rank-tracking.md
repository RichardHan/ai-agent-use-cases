# UC-048：每天自動查商品排名或價格，只在變動時通知

- 情境：省錢
- 標籤：每日、比價、電商、排程
- 網站標題：每天幫你盯商品排名或降價，有變動才通知
- 一句話用途：固定每天早上查一批商品在搜尋結果的排名或價格，存成表格並和前一天比較，只把有變動的項目通知你；退款或聯絡客服要你自己確認。
- 核心目標：把每天重複的手動查價、查排名，變成可抽查的每日紀錄與變動通知。
- 分類／標籤：電商監看／價格追蹤／排程
- 目標使用者：電商賣家（追蹤自家商品排名）、想在降價時申請價差退款的消費者
- 首次收錄／最近查證：2026-10-14／2026-10-15（台灣時間）
- 證據狀態：`author-demo`（X 作者自述＋公開 Bot 範本頁）＋ `official`（Robinhood 代理信用卡說明頁）＋ `designed`（本庫提示詞）
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：商品清單（賣家用 ASIN，消費者用訂單或商品網址）、關鍵字、檢查時間與時區、通知門檻。
- 輸出：每日一列一列的紀錄（日期、商品、關鍵字、排名或價格、來源網址）；和前一天的差異；只有超過門檻才發通知；查不到的項目另外列出，不當作「沒變」。

- 缺口與注意：

  - 作者說在自己的電腦上跑，但沒說明怎麼接本機。

### S-048C：Grok Bot — 每天替嬰兒用品清單找優惠，找到後用限額代理信用卡下單（消費者，2026-10-15 補充）

- 作者：@Kyleolver（英文）；2026-10-15 17:36（台灣時間）；回覆 Elon Musk 建議改到其他網站購物的貼文
- 貼文：https://x.com/Kyleolver/status/2110666164296663143
- 作者自述（翻譯改寫）：他和太太把 BabyList（嬰兒用品願望清單）分享給 Grok Bot，Bot 每天上網替清單裡的大件商品找優惠；找到他們想要的嬰兒推車，在一家他們沒聽過、但作者認為信譽不錯的商店約五折。他請 Bot 下單，並給它一張「有限額的 Robinhood 代理信用卡」，Bot 完成下單。
- 缺口：沒有說明每天幾點查、怎麼比對同款型號、怎麼判斷那家店可信、是否核對了總價與退貨條件，也沒有訂單或到貨證據；「約五折」與「信譽不錯」都是作者說法。卡片怎麼接到 Grok Bot 沒說明。
- 卡片控管（`official`，本庫 2026-10-15 讀取 [Robinhood Agentic Credit Card 說明頁](https://robinhood.com/us/en/support/articles/agentic-credit-card/)，英文）：這是 Robinhood Gold Card 裡的一張專用虛擬卡，代理透過 Robinhood Banking MCP 只能讀這張虛擬卡的卡號、消費紀錄與規則；可設定「每筆都要在 Robinhood App 核准」，不逐筆核准時必須設每月額度，設定只能在 Robinhood App 改。說明頁寫明它**不會替你逛網站或找商品**，代理要自己走到結帳頁才取卡號，購買責任在使用者。說明頁列出的平台沒有直接寫 Grok Bot，只說支援 MCP 的其他平台可接。
- 同日另一位使用者的結帳失敗（作者自述，未核）：@CarloZhang168（英文，2026-10-15 16:17 台灣時間）[貼文](https://x.com/CarloZhang168/status/2110646106342203599)說請 Grok 在一個非主流購物網站結帳時出現「Payment token not sent or invalid」；他請 Bot 查自己的對外 IP，發現每次都不同（列出四個 140.248.50.x 位址），推測從瀏覽商品到跳轉結帳之間 IP 改變，小型網站的付款驗證可能因此失敗，並建議官方在同一結帳流程維持固定 IP。這是作者推論，原因未經官方確認；本庫也未確認他用的是 Grok Bot 還是其他 Grok 介面（貼文同時標記 @grok 與 @bot）。
- 本庫看法：從「每天查價」跨到「直接下單」，風險從查錯價變成花錯錢。若要讓 Bot 下單，至少要有：同款型號與總價核對、商店可信度的具體依據（不是「沒聽過但看起來不錯」）、逐筆核准或額度很低的專用卡，以及結帳失敗時停下來回報、不重試付款。

## 建議操作流程（本庫設計，未實跑）

1. 先挑 5–10 個商品手動跑一次，自己打開網頁核對排名或價格。
2. 決定存放位置（試算表），每天新增一列，不覆蓋舊資料。
3. 設定每天固定時間的排程，寫明時區。查不到時標「無法檢查」，不要沿用前一天的數字。
4. 只在超過門檻時通知（例如排名掉超過 10 名、價格降超過 5%）。
5. 降價退款：Bot 只整理「訂單、原價、現價、商家價差政策」給你，由你決定要不要聯絡客服。
   - 若想讓 Bot 在降價時代為下單（S-048C）：先只通知、你核准單筆後才下單；用逐筆核准或低額度的專用卡，結帳出現付款錯誤就停下回報，不換卡、不重試、不改用其他付款方式。
6. 每週抽查 3 筆紀錄；平台改版時重新測試。

```
和前一天比較，只有［門檻］以上的變動才在這裡通知我；打不開或查不到就標「無法檢查」，不要沿用舊值。

```

## 所需連接、權限與限制

- 公開商品頁只需要讀取。查已購訂單需要購物帳號，屬敏感權限，先只用公開商品頁。
- 大量自動查詢可能違反平台條款或被封鎖，先小量測試。
- 費用：每天大量查詢會持續消耗代理用量；來源沒有可靠的費用數據。
- 聯絡客服、申請退款屬對外動作，必須當次核准。

## 驗收與可重現性

- 隨機抽 3 筆，與網頁實際排名或價格一致；「無法檢查」沒有被算成「沒變」。
- 通知只在超過門檻時出現；紀錄每天都有新的一列。
- 本庫未重現；S-048A／B／C 都是作者自述。S-048C 的下單成功沒有訂單證據；同日另有結帳失敗回報。
