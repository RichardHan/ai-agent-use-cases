# UC-051：把多年報稅資料交給 Bot，複核會計師的申報有沒有漏

- 情境：省錢
- 標籤：報稅、核對、文件整理、核准
- 網站標題：把過去幾年的報稅檔案交給 Bot，找出會計師可能漏掉或算錯的地方
- 一句話用途：把散亂的報稅表、扣繳憑單、房貸與醫療儲蓄帳戶紀錄、和會計師的往來郵件交給 Bot，請它逐年對照找出可能的漏報、重複扣除與缺件；結果交給會計師確認後才修正申報，簽名與送出都由你自己做。
- 核心目標：在不取代會計師的前提下，用 Bot 做第二輪複核，把「可能有錯」的地方整理成有出處、可讓專業人員確認的清單。
- 分類／標籤：個人財務／報稅複核／文件整理
- 目標使用者：有多種收入來源、投資或海外申報、報稅資料散在郵件與資料夾裡的個人或家庭
- 首次收錄／最近查證：2026-10-14／2026-10-14（台灣時間）
- 證據狀態：`author-demo`（作者自測，兩位作者各自在 X 上自述）＋ `designed`（自設未測提示）
- 是否獨立重現：否。本庫沒有任何報稅資料，也未核實作者說的錯誤或省下的金額。

## 輸入與預期輸出

- 輸入：過去幾年的申報書、各類扣繳憑單與投資收益表（來源例子為美國的 K-1、1099）、房貸利息證明、醫療儲蓄帳戶（HSA）紀錄、退休帳戶表單、和會計師的郵件；可以是沒整理過的資料夾。
- 輸出：逐年的「可能問題」清單，每項附：哪一年、哪一欄、依據哪份文件（檔名與頁碼）、可能影響方向（多繳或少繳）、需要會計師確認的問題；另列缺少的文件。會計師回覆修正版後，再逐項比對修正有沒有做對。

## 建議操作流程（本庫設計，未實跑）

1. 先只給「複核」權限：上傳已申報的文件副本，不連銀行、不給報稅網站登入。
2. 要 Bot 先列出它看到的檔案清單和缺件，確認範圍正確再開始比對。
3. 每個「可能錯誤」都要附文件出處與欄位；沒有出處的一律標「待確認」。
4. 把清單交給會計師或自己對照官方說明確認；不要讓 Bot 直接修改或送出申報。
5. 收到修正版後，再請 Bot 逐項比對「原問題 → 修正內容 → 是否一致」，S-051A 就在這一步抓到修正方向錯誤。
6. 結束後刪除或封存上傳的稅務檔案，記錄 Bot 存取過哪些資料。

## 所需連接、權限與限制

- 這是高度敏感的個人財務資料：身分證號、帳號、收入。上傳前確認產品的資料保存與刪除方式；本庫不提供也不保存任何真實稅務資料。
- S-051A 讓 Bot 監看郵件中的會計師回覆，S-051B 讓 Bot 讀銀行帳戶並填表：都需要另外授權，建議從「只複核已上傳副本」開始。
- 寄給會計師、簽名、送出申報、付款或申請退稅，都必須由你本人逐次確認。
- 各國稅制不同；來源都是美國個人報稅，Bot 的判斷不能取代當地合格稅務專業人員。

## 驗收與可重現性

- 抽查至少 3 項 Bot 指出的問題，回到原始文件確認出處和數字。
- 修正版必須逐項比對；任何「修正方向相反」的情況都要退回確認。
- 本庫未重現；兩個來源都是作者自述，沒有公開清單或前後金額。
