# UC-057：用對話讓 Bot 在自己的筆電架 GitHub Actions 自架 runner，並先談好安全邊界

- 情境：開發
- 標籤：CI、本機執行、權限、核准
- 網站標題：PR 檢查想跑在自己的電腦上？讓 Bot 幫你架 GitHub 自架 runner，但先講清楚「哪些情況不准跑」
- 一句話用途：讓 Bot 比較「PR 時在 GitHub 自動檢查」和「Bot 自己在你電腦上跑測試」的差別，選定後由它下載並註冊自架 runner、開工作流程 PR 試跑；註冊權杖由你貼、本機指令由你逐一核准。作者說約 5 分鐘完成，本庫未重現。
- 核心目標：把設定 CI runner 的繁瑣步驟交給 Bot，同時讓「repo 若變公開就不能再跑」這類安全條件在動手前就寫進方案。
- 工具：Grok Bot（本機電腦指令需核准、安全輸入秘密值）、GitHub Actions 自架 runner、Windows 筆電
- 分類／標籤：開發維運／CI 設定／本機權限
- 目標使用者：小團隊或個人開發者，想讓 PR 檢查用到本機已裝好的工具（例如模擬器），又不想每次手動跑
- 首次收錄／最近查證：2026-10-14／2026-10-14（台灣時間）
- 證據狀態：`author-demo`（作者自述＋1 張對話與終端機截圖）＋ `official`（GitHub 自架 runner 安全文件、Grok Bot 本機電腦說明）＋ `designed`（本庫提示詞）
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：目標 repo（作者案例為私有 repo）、要跑的檢查（測試、lint、型別檢查等）、本機作業系統、你接受與不接受的風險。
- 輸出：
  1. 兩種做法的比較與建議（GitHub 上的 runner 讓每次 PR 自動檢查，但需要電腦開著連線；或 Bot 自己在本機跑檢查）。
  2. 本機已註冊、顯示「Listening for Jobs」的 runner。
  3. 一個新增工作流程的 PR，以及一次試跑結果。
  4. 寫進每個 job 的限制條件（作者案例：只在 repo 為私有時才跑）。

### 官方文件對照（`official`，2026-10-14 讀取）

- GitHub [Secure use reference](https://docs.github.com/en/actions/reference/security/secure-use)：自架 runner 不保證每次都是乾淨的隔離環境，可能被工作流程中的不受信任程式碼長期入侵；因此「幾乎不應」用於公開 repo。即使是私有 repo 也要小心：能 fork 並開 PR 的人（通常有讀取權者）都可能危及自架 runner 環境，包括取得 secrets 與 `GITHUB_TOKEN`。文件也提到「每次執行後自動銷毀 runner」不一定有效，並建議考慮只跑一個 job 就移除的 JIT runner；另應盡量減少 runner 機器上的敏感資料。
- GitHub [Self-hosted runners](https://docs.github.com/en/actions/hosting-your-own-runners/managing-self-hosted-runners/about-self-hosted-runners)：repo 層級的 runner 只服務單一 repo；作業系統與軟體更新由使用者自行負責。
- Grok Bot [Use the computer and apps](https://docs.x.ai/grok-bot/computer-and-apps)：Bot 只有在本機能力已開啟、且你依本機政策核准時，才會在你的 Mac 或 Windows 電腦執行指令；遇到支援的安全秘密輸入時，值會被遮蔽、不進入對話。與截圖中的「本機核准提示」「權杖已安全保存」一致。

## 建議操作流程（本庫設計，未實跑）

1. 先問 Bot 比較方案，並要求列出「誰能觸發在我電腦上的執行」；只有自己或信任的協作者能開 PR 時才考慮自架 runner。
2. 只在 repo 層級註冊，並使用專用的本機帳號或虛擬機，電腦上不放與此 repo 無關的金鑰、SSH 私鑰或雲端憑證。
3. 註冊權杖只用安全輸入框提交，不貼在聊天訊息裡；權杖失效後不要再重用。
4. 每個本機指令都看清楚再核准；工作流程改動走 PR，由你審核合併。
5. 驗收：試跑一次成功；把 repo 的可見度條件寫進文件；定期確認 runner 列表裡沒有多出不認識的機器。

## 所需連接、權限與限制

- 需要本機執行能力與逐條核准；GitHub repo 的管理權限（註冊 runner、改工作流程）。
- 整理者推論（未驗證）：若「只限私有」條件寫在工作流程檔中，能修改該檔的 PR 理論上也能改掉條件；GitHub 文件也提醒能開 PR 的人都可能危及自架 runner。條件只能減少意外，不能取代「只讓信任的人觸發」。
- 電腦必須開著並連線，PR 檢查才會跑；電腦關機時 PR 會卡在等待 runner。
- runner 機器的作業系統與軟體更新由你負責。

## 驗收與可重現性

- runner 顯示在 repo 的 runner 列表中且狀態正常；試跑 job 成功並能回溯紀錄。
- 把 repo 暫時改為公開前，先確認對應 job 會被跳過（或直接停用 runner）；本庫建議在測試 repo 驗證，而不是在正式 repo 上試。
