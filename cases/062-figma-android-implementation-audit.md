## 怎麼開始（整理者設計，未實測）

1. 限定一條測試流程、兩個畫面，固定設計版本與程式 commit；先用可公開的示範資料。
2. 只讀建立對照：畫面 ID、元件／文字、token、程式位置及來源；映射不明就列待查，不能硬配。
3. 分開「規格／程式文字能確定的差異」與「需實際執行才知的顯示、互動、無障礙問題」。未跑 App 不能說視覺驗收通過。
4. 人先核准對照規格，再考慮在測試環境建立檢查器；故意放一個缺元件、一個錯 token、一個正確項目，確認能報對且不誤報。
5. 修正只提草稿。Figma 清理、備份、改 repo 與發送簡報各自另批，不能因「找差異」就刪設計稿。

## 可貼指令（原創、未實測）

請只讀這兩頁示範 Figma 設計及指定 Android commit，逐頁建立對照表。每項列畫面／元件 ID、預期值、程式位置、實際可確認值、證據與信心；找不到映射就標未確認。提出一份最小 JSON 對照規格草案，分清靜態可驗證與需跑 App 才能判斷的項目。不要執行程式、改檔、清理圖層或發布；不要把同名元件直接當作同一元件。最後給團隊一頁差異摘要與待決問題，沒有證據不要宣稱符合設計。
