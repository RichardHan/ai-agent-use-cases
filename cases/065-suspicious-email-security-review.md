# UC-065：寄件者驗證全過、卻覺得怪的信，先請 Bot 做安全審查

- 情境：生活
- 標籤：收件匣、資安、釣魚、排程
- 網站標題：官方寄件、SPF／DKIM 全通過的信也可能是釣魚：讓 Bot 拆解連結，再設定持續巡檢
- 一句話用途：收到看似官方但內容可疑的郵件時，請 Bot 只讀分析隱藏連結與郵件結構、解釋為何驗證全過，整理成回報草稿；之後再加一個只標記、不點連結的釣魚巡檢排程。
- 核心目標：在不點擊連結、不回信的前提下，判斷一封「真寄件者」郵件是否夾帶惡意內容，並把發現交給服務商。
- 工具：Grok Bot（作者自述）；郵件帳號連接方式未公開。
- 目標使用者：常收到平台通知信、想在點擊前先確認安全的個人使用者
- 首次收錄／最近查證：2026-10-15／2026-10-15（台灣時間）
- 證據狀態：`author-demo`（作者自述＋截圖）；巡檢提示詞與流程為 `designed`
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：一封你懷疑的郵件（建議提供原始郵件標頭與 HTML 原始碼，或讓 Bot 唯讀讀取該封信）。
- 輸出：①郵件內所有連結的顯示文字與實際目的地對照；②SPF／DKIM／DMARC 結果與「為何通過」的解釋；③可疑點與判斷（不是保證）；④給服務商的回報草稿（由你決定是否寄出）。
- 延伸輸出：之後每封新信的「可能是釣魚」標記清單。

## 為什麼這個用法值得看

一般的防釣魚建議是「看寄件者是否正確、驗證有沒有通過」。這個案例的重點是：**寄件者完全真實時，那些檢查都不能證明內容安全**。服務本身把使用者可控的文字（例如團隊名稱）未經處理放進通知信，就會出現「官方寄出的釣魚信」。這時要看的是信件內容與連結的實際目的地，而不是寄件網域。

## 建議操作流程（本庫設計，未實測）

1. **不要點信裡任何連結或按鈕**，也不要回信。若郵件軟體允許，先下載原始郵件（含標頭與 HTML）。
2. 只把這一封信交給 Bot 唯讀分析；不給寄信、刪信、移動或退訂權限。
3. 要求逐一列出連結：顯示文字、實際網址、網域是否與寄件者服務一致；遇到短網址或轉址只回報，不實際開啟。
4. 要求解釋 SPF／DKIM／DMARC 各自證明了什麼、沒證明什麼，並指出 HTML 中可能是使用者輸入被插入的位置（例如團隊名、顯示名稱、留言內容）。
5. 有疑點時，讓 Bot 起草回報給服務商的安全窗口；回報內容不要附上你的帳號憑證或其他私人郵件。是否寄出、走哪個管道由你決定。
6. 確認單封分析可靠後，才考慮加巡檢排程：**只加標籤或列清單**，不自動刪除、不自動回報、不打開連結。先跑幾天，抽查標記與未標記的信。

## 可複製提示詞（原創設計，未實測）

### 單封安全審查

請只讀我指定的這一封郵件，做安全審查，不要點擊或開啟任何連結、不要回信、不要移動或刪除郵件。請列出：①每個連結的顯示文字與實際網址；②SPF、DKIM、DMARC 的結果，以及它們只能證明「誰寄的」、不能證明「內容安全」的部分；③HTML 中看起來像使用者可控文字被直接插入的地方；④你判斷可疑的理由與不確定之處。如果需要開啟網址才能確認，停下來問我。最後另外起草一封給服務商安全窗口的回報草稿，不要寄出。

### 後續巡檢（排程）

每天［時間、時區］檢查前一次檢查之後的新郵件，只讀。若發現顯示文字與實際網址不符、要求登入或付款的緊急字眼、或寄件者與連結網域不一致，就在信上加「可能是釣魚」標籤並列進報告，附理由。不要點連結、不要回信、不要刪除或移動、不要退訂。沒有可疑信就簡短回報「無」。每週列出被標記的信，讓我抽查誤判。

## 所需連接、權限與限制

- 郵件讀取權限只開到需要的帳號或資料夾；加標籤是寫入動作，先確認你同意。寄信、刪信、轉寄、退訂都不在本流程內。
- 不要把郵件帳號密碼直接貼給代理；使用產品提供的連接授權方式（參考 UC-049 的分級放權）。
- 原始郵件可能含個資或他人資訊；回報給服務商時只附必要的標頭與 HTML 片段。
- 作者未說明方案費用、巡檢頻率與用量；持續巡檢會消耗額度（參考 UC-066 的輪詢成本）。
- Bot 的判斷不是資安保證：漏判時仍可能中招，誤判時可能錯過正常通知。重要帳號的通知仍建議直接從官方網站或 App 進入查看，而不是點信裡的按鈕。
- 本案例只在作者情境中出現在 Grok Bot；本輪沒有找到 Meta Muse 或 ChatGPT dots 的同類實例，不推定它們會同樣處理。

## 驗收與可重現性

- 單封分析：自己用郵件軟體的「顯示原始碼」核對 Bot 列出的連結是否完整、實際網址是否正確；Bot 沒有開啟連結是本流程的必要條件。
- 巡檢：抽查一週內被標記與沒被標記的信，記錄誤判與漏判；確認沒有任何信被刪除、移動或回覆。
- 本庫沒有重現原始事件，也沒有測試任何 routine。
