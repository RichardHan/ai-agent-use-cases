# UC-070：GitHub 帳號被停權時，用 Dot 協調改走本機建置與 Cloudflare 發布

- 情境：開發
- 標籤：部署、故障診斷、核准、跨代理
- 網站標題：GitHub 登不進去了？先保住本機與線上版，再改發布路徑
- 一句話用途：當 GitHub 帳號被停權、客服未回時，用 ChatGPT Dot 協調把網站建置移到自己的 Mac，經預覽與人核准後上傳 Cloudflare，不再依賴 GitHub push。
- 核心目標：在主要托管／CI 路徑失效時，分離「抓取資料」「人工審核」「發布上線」，並用可回退的本機建置完成一次發布。
- 工具：ChatGPT dots／Codex／本機 Mac／Cloudflare
- 目標使用者：網站依賴 GitHub 部署、需要在帳號異常時仍能安全更新公開頁的個人或小團隊
- 首次收錄／最近查證：2026-10-15／2026-10-15（台灣時間）
- 證據狀態：`author-demo`（作者長文自述＋截圖）；本庫未重現
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：既有本機專案、可回退的線上版本、Cloudflare 托管、Dot 可協調本機 Codex／子代理的環境。
- 輸出：①本機變更與線上版快照已保存；②抓取與公開發布分開；③建置、測試、隔離預覽通過；④人核准後由本機上傳 Cloudflare；⑤上線後以公開頁面核對版本，不重複部署。

## 建議操作流程（本庫設計，未實測）

1. 確認「需要更新的公開頁」與「可回退的目前線上版」。先做本機 commit／快照，不要直接改生產。
2. 把流程拆成：資料抓取 → 私人審核 → 建置／測試／隔離預覽 → 人核准 → 上傳托管。任何一步失敗都標「無法完成」，不得宣稱已上線。
3. 若主托管或 CI（例如 GitHub）不可用，只改發布通道，不順便打開自動抓取或自動公開。
4. 預覽通過後才核准上傳；上線後用公開 URL 核對版本與關鍵頁，並記錄實際核對時間。
5. 本機中斷時，約定由雲端代理只做**只讀核對**，不擅自重送部署。
