# UC-077：雲端寫稿排版，再呼叫自己 Mac 上的發布腳本推到公眾號草稿箱並同步知識庫

- 情境：創作
- 標籤：社群、發文、本機執行、核准
- 網站標題：Bot 在雲端排好文章，再用你 Mac 上現成的腳本推到公眾號草稿箱
- 一句話用途：把寫稿、排版、處理圖片放在 Bot 的雲端電腦，需要固定 IP、白名單或本機私有設定的發布步驟交給自己 Mac 上已有的腳本；只推到草稿箱，由人看過再發。
- 核心目標：串起「雲端產出」與「本機既有工具」，又把權限停在草稿、敏感金鑰不進聊天。
- 工具：Grok Bot（雲端電腦＋已連接的本機 Mac）／作者自有公眾號發布腳本／阿里雲代理／飛書 lark-cli
- 分類／標籤：內容發布／雲端與本機協作
- 目標使用者：已經有自己的發文腳本或 CLI、想讓代理接手排版與搬運，但不想讓它直接群發的內容創作者
- 首次收錄／最近查證：2026-10-16／2026-10-20（台灣時間）
- 證據狀態：`author-demo`（作者自述一次完成）＋`official`（Grok Bot 官方雲端電腦與本機電腦文件）；建議流程與提示詞為 `designed`
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入（作者自述）：文章主題或草稿、要用的圖片；作者 Mac 上已設定好的公眾號發布腳本（`publish-wechat.sh`）、阿里雲固定 IP 與公眾號 IP 白名單；雲端電腦上已安裝的飛書 `lark-cli`。
- 輸出（作者自述）：排好版的文章與處理過的圖片 → 從雲端傳到 Mac → 執行本機腳本推進公眾號**草稿箱** → 同一篇文章與圖片同步到飛書知識庫。
- 明確排除：自動群發；把 API Key 貼進對話；本庫未看到草稿箱或飛書頁面的截圖。

### S-077B：Grok Bot 官方說明 — 雲端電腦與本機電腦是分開的

- [Use the computer and apps](https://docs.x.ai/grok-bot/computer-and-apps)（英文，2026-10-16 本庫讀取）：Bot 在持續存在的雲端電腦上工作；你面前的 Mac 或 Windows 是另一台，**只有在啟用本機電腦功能、並依你的本機電腦政策核准後**，Bot 才會在本機執行指令。文件也提醒密碼與一次性驗證碼不要貼進聊天，支援的連接會提供遮罩的安全輸入欄位。
- 這只說明能力邊界，不代表作者的公眾號腳本或代理切換一定可行。

## 為什麼這個用法值得看

很多人的發文流程卡在「只有自己電腦才有的東西」：固定 IP 白名單、私有腳本、已登入的 CLI。這個做法沒有把這些搬上雲端，而是讓雲端負責內容、本機負責最後一哩，並把權限停在草稿箱。作者先「只讀」再「放執行」的逐步授權，也比一次全開更穩妥。

## 建議操作流程（本庫設計，未實測）

1. 先在本機確認發布腳本只會推到草稿（不是直接發布），並確認金鑰從本機設定檔或系統鑰匙圈讀取，不寫在腳本參數或對話裡。
2. 連接本機後，第一輪只讓 Bot 列出腳本路徑、讀腳本說明與參數，不執行。
3. 用一篇測試文章在雲端排版，請 Bot 列出要傳到 Mac 的檔案清單與存放資料夾。
4. 你核准後才執行一次腳本；要求 Bot 回報結束代碼、腳本輸出摘要（遮掉任何金鑰或權杖）與草稿標題。
5. 網路失敗時，只允許改用你事先寫明的代理設定；不要讓它自行找新代理或改系統網路設定。
6. 你到公眾號後台親自看草稿，再決定是否發布；同步到知識庫前，確認目標空間與分享範圍。

## 可複製提示詞（原創設計，未實測）

請在你的雲端電腦把［文章主題／草稿］排版成公眾號格式，並處理圖片。先不要碰我的 Mac。完成後列出要傳到 Mac 的檔案、目標資料夾，以及你打算執行的本機腳本完整路徑與參數，等我核准。核准後：只執行［腳本路徑］推到草稿箱，不要發布或群發；不要讀取、輸出或改動任何 API Key、Token 或密碼；預設網路失敗時只能改用我已設定的［代理名稱］，不要另找代理或改網路設定。完成後回報腳本結束代碼、輸出摘要（遮掉敏感值）與草稿標題。同步到［知識庫空間］也要先列出目標位置與分享範圍，等我確認。

## 所需連接、權限與限制

- 需啟用 Grok Bot 的本機電腦功能；每個本機指令依你的本機電腦政策核准。執行腳本、上傳到公眾號、寫入知識庫都屬外部變更。
