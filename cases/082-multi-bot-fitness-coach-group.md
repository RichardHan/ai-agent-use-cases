# UC-082：開一個健身群組：管家、教練、營養師分工，飲食拍照、訓練計畫與睡眠上報

- 情境：生活
- 標籤：健康、多代理、運動、每日
- 網站標題：讓三個 Bot 當管家、教練、營養師，一起管飲食、訓練與睡眠
- 一句話用途：在 Grok Bot 裡拉一個多代理群聊，分別扮演管家（彙整與確認）、教練（讀文獻／技能訂訓練計畫）、營養師（看飲食照片與熱量蛋白）；睡眠則用手機捷徑彙總後送到作者自稱的 Grok 介面。作者附群聊與技能匯出截圖，本庫未重現。
- 核心目標：把「飲食／訓練／睡眠」拆成專責角色，用群聊交接，而不是一個聊天框什麼都問；醫療診斷與用藥仍不在範圍內。
- 工具：Grok Bot（多 Bot 群聊）；第三方「訓記」類技能／匯出檔（截圖）；iPhone 捷徑彙總睡眠後呼叫作者設定的介面
- 分類／標籤：個人健康／多代理協作／運動飲食
- 目標使用者：想固定訓練與飲食紀錄、願意每天拍照與上報睡眠，但不希望自己當所有角色的中轉站的人
- 首次收錄／最近查證：2026-10-16／2026-10-19 20:40（台灣時間，新增單 Bot 每日教練版本 S-082B）
- 證據狀態：`author-demo`（作者貼文＋三張截圖）；建議流程與提示詞為 `designed`；第三方技能與捷徑端點安全性 `unverified`
- 是否獨立重現：否

## 為什麼這個用法值得看

多代理群聊把「誰負責訂計畫、誰盯吃的、誰做總確認」分開，減少單一對話裡角色混亂。作者也展示了**技能匯出**與**手機捷徑上報**兩條邊線整合，這在公開分享裡相對少見；但正因如此，金鑰與健康資料外送的風險要寫清楚。

## 建議操作流程（本庫設計，未實測）

1. 先寫一頁「角色憲章」：管家只彙整與問確認；教練只談訓練計畫與文獻摘要；營養師只談飲食紀錄與巨量營養素估計；任何醫療診斷、傷痛處置、停藥／用藥一律拒答並請你找合格人員。
2. 建立三個 Bot（或同等角色）並開群聊；預設所有對外動作（改日曆、購物、發訊給真人）需你核准。
3. 訓練：只用你有權使用的公開文獻或已購買課表；教練輸出「本週計畫＋文獻／來源連結＋需要你確認的傷痛假設」。
4. 飲食：拍照前遮商標與可辨識他人臉；營養師回「估計」並標不確定，不開處方式禁忌清單冒充醫療。
5. 睡眠：捷徑只送彙總分鐘數等最小欄位；端點用你自己可控的收件（例如私人 Bot webhook），不要把未審過的第三方 URL 與長期 API Key 寫死在捷徑。
6. 技能／Key：能不匯出金鑰就不匯出；若工具硬要帶 Key，用可吊銷的短效權杖，並在截圖 2 那種畫面裡確認可「吊銷目前 Key」。
7. 每兩週人工回顧：體重／訓練完成率／是否出現代理擅自加量或恐吓式語氣；不滿意就停用。

## 可複製提示詞（原創設計，未實測）

你們三個在這個群組的分工如下，直到我更改為止：＠管家只負責摘要現況、列出待我確認的事項，不直接改計畫；＠教練只根據我提供或公開可查的訓練來源提出／調整課表，輸出須附來源；＠營養師只根據我上傳的餐食照片做巨量營養素「估計」，標不確定項。禁止診斷疾病、建議處方藥或叫我停藥。任何寫入訓練日誌、改日曆、對外傳訊前，先由管家列確認單等我回覆「核准」。不要索取身分證、健保卡或完整醫療紀錄。
