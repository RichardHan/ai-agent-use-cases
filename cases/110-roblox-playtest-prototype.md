# UC-110：讓 dots 做遊戲雛形，再用真人試玩找出不好玩的地方

- 網站標題：想做 Roblox 小遊戲？先做能玩的雛形，再修節奏
- 一句話用途：作者讓 dots 產出烘焙店經營遊戲，自己在 Roblox Studio 試玩，找出初版缺地面、玩法單薄及進展太快等問題。
- 情境：創作
- 標籤：遊戲原型、人工試玩、驗收
- 工具：ChatGPT dots／Roblox Studio
- 分類／標籤：創作／遊戲原型／人工試玩／驗收
- 證據狀態：B 級作者實作自述；文章已讀，內嵌影片未看，未獨立重現。
- 查證日期：2026-10-17（台灣時間）

## 作者做了什麼

日本作者シブシブ先請 dots 製作 Roblox 世界，再依實際試玩的問題迭代成烘焙店經營原型。作者取得檔案後在 Studio 開啟，確認製作、販售與設備升級能跑，卻發現進展過快。這顯示「程式可跑」和「遊戲好玩」需要不同驗收。

作者說本次 dots 無法直接在 Studio 完整試玩；人工回饋不可省略。進度儲存未啟用；十階段、約一小時的版本仍在設計，不能寫成已完成。原型沒有公開上架、玩家數或收入證據。

## 建議步驟（本庫設計，未實測）

1. 只做一個最小循環：生產、獲得遊戲內點數、升級、回到生產。不含真實交易。
2. 先要求場景有安全落點、基本地面和可辨認的下一步，提供檔案、版本與測試清單。
3. 由有權使用該環境的人開啟試玩，記錄卡住、無聊或進展太快的時間點；不要把生成者的自評當實際遊玩結果。
4. 把觀察轉成可驗收修改，例如「升級效果看得見」「到下一個目標需要多久」，一次只調少數參數。
5. 分開記錄程式檢查、人工單人試玩、多人／裝置測試；未測項目保留。
6. 發布、付費素材或交易功能需另行決定與授權。本庫沒有執行或下載原型。

## 可貼指令（原創設計，未實測）

請為一個虛構烘焙店設計最小 Roblox 遊戲原型規格。限一個生產→遊戲內點數→設備升級循環，沒有真實金錢、外部資料或公開發布。列出場景落點、每一步玩家看到的回饋、預計等待時間，以及人工試玩檢查表。把程式檢查和真正玩過分開；未取得人工試玩結果前，不宣稱好玩或完成驗收。

## 權限、費用與可用性

- 本案例是作者使用本機 Studio 的報告，不能泛化成 dots 的雲端能直接操作或完整玩完 Roblox。
- dots 方案、用量及素材費未交代；不保證零成本。不要下載或執行不可信來源的遊戲檔案。
- Roblox 官方提供不同 Studio 測試模式，並要求發布前測試；官方文件不證明本作者案例品質或 dots 支援程度。
- 公開多人遊戲、使用第三方素材與任何交易需要另核平台規範及權利。本案僅研究，不包含這些動作。
