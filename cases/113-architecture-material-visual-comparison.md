# UC-113：把建築模型變成可旋轉方案，再比較外牆與室內風格

- 一句話用途：作者用 Grok Bot 處理公開模型與視角，再交給圖片生成Bot用Sunburst製作室內方案；保留單位、格式與生成細節失真的失敗紀錄。

## 作者實作

Satoru / Toko用公開虛構建築模型代替實案，讓Grok Bot產出可旋轉展示、外牆方案與不同視角，再由圖片生成Bot用Sunburst做室內風格比較。

過程中原格式讀取失敗，作者改交COLLADA；人眼視點出現單位錯誤，另有記憶體不足。作者還指出生成圖自行添加小物。因此成果適合比較視覺方向，不能拿來確認實際尺寸、構造或施工細節。換時段與家具配置的延伸構想尚未實作，不另計案例。

## 建議步驟（本庫設計，未實測）

1. 以有使用權的公開或自建虛構模型開始，先記模型格式、單位及授權。
2. 先檢查邊界尺寸、樓層、視點高度與缺失材質，通過後才產出可旋轉預覽。
3. 固定幾何與相機，分開比較少量外牆材質，保留每一版參數。
4. 截取室內基準視角後，再向有權使用的生圖工具提出風格提案。
5. 將新增、刪除或變形元素標出；生成圖與原模型並排，不能用漂亮程度取代忠實度。
6. 原模型不可讀、資源不足或尺寸不合理時停止該步，保留原因與人工處理需求。

## 可貼指令（原創設計，未實測）

請先檢查這個有權使用的虛構建築模型之格式、單位、整體尺寸與相機高度，再設計三個固定視角的外牆材質比較方案。不更動幾何、不補造缺失房間、不公開上傳、不呼叫付費工具。後續若做生成示意圖，要逐項標示與原模型不同或無法確認的地方；成果不得稱施工圖或尺寸驗證。

## 權限、費用與限制

- 作者由手機Grok Bot App交辦，但模型處理與Sunburst生圖是不同環節，不能泛化成Bot原生完整生圖能力。
- 作者未公開完整費用或用量；生圖、模型處理和儲存皆需另確認方案與授權。
- 實際建築檔可能暴露地址、格局或業主資訊；公開示例應使用虛構模型並確認素材權利。
- 圖片生成可能更動物件與比例；不得用於取代專業設計、安全或法規審查。
