# UC-126：把屋頂工程開工前的許可、檢查與通知整理成同一行政流程

- 一句話用途：屋頂承包商自述用Grok Bot處理線上許可、屋頂檢查預約及保險工作通知，實際核准文件未公開。

- 標籤：工程、表單、預約、核准
- 工具：Grok Bot／政府與服務表單／電子郵件
- 證據狀態：B級作者實作自述；無提交收據、最終核准及完整人工介入紀錄，未獨立重現。

## 作者實作

Price Foulger說過去兩天以Grok Bot處理屋頂許可、含CAPTCHA的檢查預約表單，以及兩份寄給保險公司的工程通知。原帖另列合約、變更單、報價與供應商申請；本案只計一次開工行政協調，不將九個清單項目拆九案。

作者的用語不等於本庫已看見政府核准或檢查通過。是否本人處理CAPTCHA、登入、電子簽名或最終確認也未交代。

## 操作步驟（本庫設計，未實測）

1. 以虛構工程資訊建立行政清單，辨識地方主管機關、檢查單位與保險通知各自要求。
2. 只讀核對官方表單版本、必填欄與截止日，不能套用別地規則。
3. 將資料來源、缺漏與需簽署／付款／確認的步驟列出，準備供合格負責人審查的草稿。
4. 政府申請、保險或合約承諾由有權人員依規定完成；遇到驗證或安全限制交人工處理。
5. 以正式收據區分已填、已提交、已受理、已批准；檢查預約不代表檢查通過。
6. 只有核實各項狀態後才更新工程待辦，不自動推定可以開工。

## 可貼指令（原創設計，未實測）

請把這份虛構屋頂工程資料整理成行政準備清單，分許可申請、檢查預約和保險通知。只列官方來源、所需欄位、缺漏、期限與需負責人確認項目。不登入、不提交、不簽名、不付款、不處理CAPTCHA、不宣稱允許開工。

## 權限、費用及限制

- 地點、主管機關與適用規範未知，沒有核實具體法律要求；不能當法律或施工許可意見。
- 對政府、保險公司或承包商發送內容可能有重大責任，必須明確授權並由適格人員核准。
- 工程地址、保險／信用資料與合約不公開；本例只使用虛構資料。
- 代理費用、許可費與節省時間未核，沒有實際執行任何表單或外部動作。
