# UC-128：問測試資料庫每月營收，連取消單與貸項一起列待核

- 網站標題：自然語言問每月營收，先看查詢怎麼算、別直接入帳
- 一句話用途：JTL論壇作者讓Grok Bot讀測試SQL資料庫，收到按月份與稅類的營收答案，但明說查詢仍待自己核對。
- 情境：工作
- 標籤：資料庫、營收、測試、核對
- 工具：Grok Bot／測試SQL資料庫
- 證據狀態：B級作者實際測試自述；SQL、數字與權限配置未公開，未獨立重現。
- 查證日期：2026-10-17（台灣時間）

## 作者實作

ple（署名Christian）說透過VPN讓Grok Bot接觸測試資料庫，要求只讀理解結構，再問各月、各稅類營收。作者已收到答案，稱選對資料表並辨識取消單與貸項，但明確說SQL還要自己檢查。因此只證明測試查詢有輸出，不證明會計數字正確或帳號真的強制只讀。

## 操作步驟（本庫設計，未實測）

1. 使用合成、去識別且隔離的測試資料，不直接連正式商業資料庫。
2. 由管理者以資料庫權限實作只讀、欄位範圍與查詢限制，不能只寫在提示詞。
3. 明確定義月份、時區、稅類、取消單、貸項及重複列的計算方式。
4. 先產出SQL草案與欄位說明，人工檢查join是否擴增筆數、退款是否重扣。
5. 經核准的測試才執行，與已知小樣本及控制總數核對，保留錯誤與例外。
6. 未驗證前只當研究輸出，不入帳、不報稅、不寄正式報表。

## 可貼指令（原創設計，未實測）

請依這份虛構資料表結構提出月別／稅類營收的只讀SQL草案，不連資料庫、不執行查詢。先問清取消單、貸項、含稅與時區定義，列出可能join重複與需要人工核對的控制總數。不新增、不刪除、不更新任何資料。

## 權限、費用及限制

- 原作者用VPN是個人配置，不能解讀為應直接開放公司網路或資料庫；持續存取與憑證需另外核准。
- 提示詞檔不是強制存取控制，共用代理環境也不能當安全隔離。
- 同串其他人談OpenClaw或第三方MCP的案例不拼成Grok Bot已驗功能。
- JTL版本、資料表相容性、代理成本與查詢效能未核；不採論壇價格或模型宣傳為當前事實。
