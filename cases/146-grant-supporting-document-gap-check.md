# UC-146：對照補助申請要求，找出承包商來信的佐證缺口

- 網站標題：補助文件看似齊了？先核每一項要求有沒有證據
- 一句話用途：作者自述dots指出承包商來信不符正在申請的水管更換補助要求；沒有公開缺項、補件或核准結果。

- 工具：ChatGPT dots／Google帳號資料

## 作者實際發現

Harry Guinness在Zapier文章中描述連接自己的Google帳號並使用dots數天後，dots提醒承包商寄來的email，不符合他正在申請的鉛水管更換補助要求。

文章沒有公開承包商來信、具體缺欄、補助機關或正式核准結果。可收錄的是「現有佐證與既定要求比對後發現缺口」；不代表已補件、符合資格或取得補助。作者同時描述漏掉重要郵件的情況，不能把一項發現當完整查漏保證。

## 操作步驟（本庫設計，未實測）

1. 先鎖定指定申請與官方要求的版本／日期；沒有明確計畫就停在待核，不套用別地規定。
2. 用合成或獲授權去敏文件做要求—證據對照：每一項保留來源定位及是否完整。
3. 區分缺少、互相矛盾、需要專業解釋、尚未能判定，不自動補造資料。
4. 產出待補件清單和可給承包商核對的草稿，不自行寄出。
5. 由本人及合適專業人員判定資格與申報內容；後續申請、簽名、聲明、條款與提交另處理。
6. 補件後重新逐項核對，以官方回覆確認受理／核准狀態。

## 可貼指令（原創設計，未實測）

請用虛構補助要求和虛構承包商信件建立佐證核對表，列每項要求、文件位置、缺漏、矛盾與待確認。不可猜法定資格或補造證明。只準備清單，不寄信、不填申請、不簽署、不提交任何文件。
