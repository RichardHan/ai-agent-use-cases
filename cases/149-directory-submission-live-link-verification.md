# UC-149：把投稿回執、待審與真正上線的連結分開驗收

- 網站標題：投稿說送出了，頁面真的上線了嗎？
- 一句話用途：作者親自核到一個可點目錄條目；送出、收件、審核及上線分開記，不把行動次數當商業成效。
- 情境：工作
- 標籤：投稿、狀態核對、連結、驗收
- 工具：ChatGPT dots／公開目錄
- 證據狀態：A級原作者使用紀錄與公開頁檢查；投稿過程部分來自代理回報，未獨立重現。
- 查證日期：2026-10-17（台灣時間）

## 原作者核到的結果

Ramanpal Singh描述dots協助Promptslove投稿及聯絡。2026-09-30 19:06 IST檢查點是13項已回報行動、零個驗證上線連結；稍後作者親開Full Stack Journalism的Baserow目錄、匹配記錄與目的頁，確認首個可點條目。

那是工具作者自行投稿的目錄連結，帶nofollow；編審仍未確認。13不是13個案例，1/3不是三項全部完成；沒有排名、流量或營收成效驗證。實際提交歷史來自代理回報，作者親核的是當時公開頁與目的連結。

文章也記沒有送出確認的表單不重送、驗證受阻及投稿待審等狀態，保留未知比把「按過送出」寫成完成更可核對。

## 操作步驟（本庫設計，未實測）

1. 僅拿已授權投稿清單做盤點，保留來源、目的頁及原始送出證據。
2. 分未送出、結果不明、已收件、待審、公開可讀；每次更新附日期。
3. 讀公開條目及目的連結，核標題、資源相符與連結類型。
4. 不把投稿者可見內容當編輯批准，不把nofollow連結當搜尋排名信用。
5. 未確認送出結果先查已有回執，不自行再次提交；新對外聯絡另獲授權。
6. 把商業成效放另一張有數據的表，不能從上線狀態直接推導。

## 可貼指令（原創設計，未實測）

請只讀一份虛構的已投稿清單，設計送出／收件／待審／公開上線的驗收表，列證據時間、來源頁與目的頁、結果不明。不要寄信、提交表單、購買連結或大量外聯，不將上線數換算成流量或收入。
