# UC-156：郵件系統移轉後，分別核歷史資料與新信路由

- 網站標題：信箱搬到新平台了，舊信和新信都真的正常嗎？
- 一句話用途：作者自述Grok Bot協助從舊郵件伺服器移往Microsoft，包含搬資料與MX切換；沒有完整信件數或收發驗收。
- 情境：開發
- 標籤：郵件、移轉、驗收、備份
- 工具：Grok Bot／作者未指明的遷移工具／Microsoft郵件服務
- 證據狀態：B級原作者公司實作自述；資料完整性與正式服務結果未核。
- 查證日期：2026-10-17（台灣時間）

## 作者自報的完成範圍

u/nighthawk5300自述替建築公司從舊郵件伺服器移往Microsoft，已處理授權購買、遷移軟體搬資料、MX切換、公司簽名及品牌標誌。

未交代舊系統、Microsoft產品版本、移轉方法、郵件數、遺失率或收發測試。不能把作者認為切換前安全的說法當成無風險證明；另設Safety Bot也不代表強制隔離。

## 操作步驟（本庫設計，未實測）

1. 僅用合成信箱清單設計前後核對：信箱、資料夾、數量、日期範圍與例外。
2. 在真實遷移前由管理者確認備份、目標信箱、權限、服務時間窗和回復方案。
3. 歷史資料搬移與新信路由分開驗收，包含寄出、外部寄入及內部信測試計畫。
4. 把地址、別名、簽名與品牌設定列獨立檢查，不拿外觀正常當信件完整。
5. 正式DNS、帳號、付費、授權或安全設定由具權限管理者另行核准處理；本指令只產計畫。
6. 依原始對照表記缺漏與未知，不憑「搬完」訊息直接停用舊服務。

## 可貼指令（原創設計，未實測）

請以虛構公司信箱製作遷移驗收清單，分歷史信件、目標帳號、寄入／寄出、別名、簽名及回復方案。不要連線、改MX、建帳號、購買服務、輸入憑證或停用舊系統。把無法確認的數量及版本標待管理者核對。

## 權限、費用與限制

- 如果目的平台是Microsoft 365，官方說明要求MX變更前準備目標信箱；MX影響新郵件路由，舊信仍在原服務。這是條件式背景，不代表作者確用365。
- 來源未披露授權費、席次及遷移工具；不猜價格或採購內容。
- 真實郵件可能含機密與個資，研究未取得任何公司信件或憑證，也未操作公司系統。
- Grok官方安全說明要求正式系統／權限變更有適當批准；認證交本人，多Bot不構成安全隔離。原作者授權細節未核。
- 本庫沒有執行遷移、安裝、付費、DNS或安全設定操作。
