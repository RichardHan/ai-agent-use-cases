# UC-167：把網站無障礙疑點變成可覆核的證據包

- 網站標題：選單看得到卻按不到？先留下位置、畫面和程式證據
- 一句話用途：讓代理檢查指定頁面的可及性疑點，交出能讓人重查的紀錄。
- 情境：開發
- 標籤：無障礙、網頁、證據、驗收
- 工具：Grok Bot／Blocks.ai／Chrome
- 證據狀態：V，廠商員工實際測試自述；原報告包未公開，未獨立重現
- 查證日期：2026-10-16

## 問題與原作者實作

Blocks.ai 的 Nicolis Miller 記錄了一次測試：參考 W3C 的前後對照示範，檢查已登入的產品儀表板。經主人確認後，Grok Bot 在雲端 Chrome 讀取頁面及 HTML，產出筆記、截圖與頁面副本。作者報告了圖片式導覽的鍵盤操作問題、沒有標籤且變更便導頁的選單，以及缺少有效可及文字的圖片／連結。

這是供應商對自己產品整合的使用報告，有商業利益。沒有公開完整證據包、輔助科技實測、修復後結果或合規認證。其連線測試曾只收到確認文字而未喚醒 Bot；收到請求不等於完成檢查。原文三次測試的通道、核准和持久檔案不拆成額外案例。

## 可參考的操作步驟

以下為本庫設計的只讀驗收流程，未執行：
1. 由擁有者指定可檢查的測試頁、範圍及允許保留的資料；優先匿名測試頁，不自行建立連線或擴權。
2. 分別記錄鍵盤可達性、焦點、欄位標籤與替代文字。對每個疑點留下頁面位置、觀察時間、最小 HTML 片段與去識別截圖。
3. 區分已重現的操作障礙、僅由標記推測的疑點，以及尚未測的螢幕閱讀器行為。
4. 人工在相同版本重查；修復後重新驗證。未測範圍保持未測，不由少數通過項推論整站合規。

## 可貼指令（自行設計，未測）

只讀檢查我指定且已授權的測試頁。不要安裝工具、修改頁面、建立憑證或傳送資料到其他服務。對每個無障礙疑點列出位置、可重現操作、實際觀察、最小證據及狀態：已確認、疑似、未測。沒有測過鍵盤或螢幕閱讀器就明說。保存內容前先去除帳號和私人資料。最後列未涵蓋的頁面與操作，不宣稱符合完整WCAG，也不要只以任務已收到當完成。

## 權限、費用與可用性

- 原實驗持有登入工作階段，跨代理通道及持續憑證另有權限風險；本案例不提供啟用指令或授權。多個 Bot 不等於隔離不同帳號權限。
- 原文把測試路由設為私人及免費，不能推論 Grok Bot、平台、模型或運算總成本為零；本文沒有核價或提供預算承諾。
- W3C 的 BAD 示範採 WCAG 2.0、只涵蓋部分障礙；它是教學素材，不能替代現行需求和完整評估。
- W3C 說明工具本身不能判定網站是否達標，仍需有知識的人類評估。實際障礙也應由適當的輔助科技與使用者測試驗證。
- 已登入畫面、副本與截圖可能含私密資料；只在原已授權範圍保存，不公開實際客戶或帳號內容。
