# UC-178：掃描頁圖文重建與完整性核對

- 網站標題：掃描稿轉成圖文檔，插圖和文字還完整嗎？
- 一句話用途：重建掃描頁時逐頁核對文字與圖塊，避免格式看似完成卻裁掉插圖或漏內容。
- 情境：工作
- 標籤：掃描、圖文、完整性、失敗
- 工具：Grok Bot／PDF／Markdown
- 證據狀態：B，作者失敗實作自述；原檔與成品未公開，未重現
- 查證日期：2026-10-16

## 原作者實作

LINUX DO使用者Cryo自述，已把掃描PDF交給Grok Bot，要求重建為圖文PDF與Markdown，並特別要求逐頁校對和保持格式。檢查成品時，仍發現不少插圖裁切不完整及內容遺漏，後續同作者再次確認PDF處理結果不佳。

這是失敗實作紀錄。沒有原掃描件、成品、頁數、OCR引擎或錯誤比例，不能評定整體產品準確率，也不推測後端模型或容量根因。「圖文格式」不擴寫成已驗證可編輯、可搜尋或符合無障礙規範。

兩種輸出視為同一重建流程，不拆PDF和Markdown兩案；它與抽取指定欄位進Excel或重排教材省紙的終點不同。

## 可參考步驟（自行設計，未執行）

1. 只用有權使用的合成掃描頁，先建立原頁碼與圖塊清單。
2. 將識別文字、圖塊邊界及輸出位置逐項對照原頁，標記裁切、漏字、漏段或順序不明。
3. 若表格、註腳、跨頁圖片或多欄文字無法可靠重建，保留原影像並標待人工校核，不補寫不存在的內容。
4. 分別檢查PDF與Markdown的同頁對應，但仍以同一原稿完整性驗收。
5. 沒有完成逐頁比對前，不宣稱無遺漏或轉換成功。

## 可貼指令（自行設計，未測）

請只分析這份合成掃描頁與合成重建樣本，列出每頁文字區、圖塊邊界、輸出對應及疑似遺漏。指出裁切、漏段、讀序和未能判定的地方，保留原頁碼。無法辨識不要猜字，不新增原稿沒有的內容。不執行轉檔程式、不安裝OCR、不上傳到第三方。最後列待人工逐頁核對項目，不宣稱可編輯、可搜尋或無障礙合規已驗證。
