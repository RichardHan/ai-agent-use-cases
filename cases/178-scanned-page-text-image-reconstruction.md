# UC-178：掃描頁圖文重建與完整性核對

- 網站標題：掃描稿轉成圖文檔，插圖和文字還完整嗎？
- 一句話用途：重建掃描頁時逐頁核對文字與圖塊，避免格式看似完成卻裁掉插圖或漏內容。
- 情境：工作
- 標籤：掃描、完整性、失敗、電子書
- 工具：Grok Bot／PDF／Markdown
- 證據狀態：B，作者失敗實作自述＋另一作者成功自述（掃描PDF轉EPUB附校對紀錄）；兩者原檔與成品皆未公開，未重現
- 查證日期：2026-10-16；2026-10-19 新增來源B

## 原作者實作

LINUX DO使用者Cryo自述，已把掃描PDF交給Grok Bot，要求重建為圖文PDF與Markdown，並特別要求逐頁校對和保持格式。檢查成品時，仍發現不少插圖裁切不完整及內容遺漏，後續同作者再次確認PDF處理結果不佳。

這是失敗實作紀錄。沒有原掃描件、成品、頁數、OCR引擎或錯誤比例，不能評定整體產品準確率，也不推測後端模型或容量根因。「圖文格式」不擴寫成已驗證可編輯、可搜尋或符合無障礙規範。

兩種輸出視為同一重建流程，不拆PDF和Markdown兩案；它與抽取指定欄位進Excel或重排教材省紙的終點不同。

## 來源B：掃描版PDF轉成可重排的EPUB，附校對紀錄（作者成功自述）

- @LiangZzzz／X／簡體中文：[原帖](https://x.com/LiangZzzz/status/2112137868122767731)，2026-10-19 11:04 UTC（台灣時間 19:04）；無附圖。
- 作者自述（翻譯改寫）：想讀的書只找得到掃描版PDF，放進Kindle字太小又不能重排；把PDF交給Grok Bot，約兩小時後拿回一本有目錄、能正常翻頁的EPUB，還附一份校對紀錄，寫明哪些地方改了、哪些地方還不確定。作者自己只做了交出檔案、收回成品兩件事。
- 與來源A的關係：同樣是「掃描稿重建成可讀文字檔，並交代哪裡可能有誤」，輸出格式由圖文PDF／Markdown換成EPUB，屬同一流程的版本，併入本頁不另計。兩位作者結果不同（A發現插圖裁切與漏內容，B自述成功），並列保留，不互相抵銷。
- 值得參考的一點：B的成品附「改了什麼、還拿不準什麼」的紀錄，正好對應本頁強調的逐頁完整性核對；但作者沒說是否逐頁比對過原稿，也沒公開頁數、錯誤數或校對紀錄內容。
- 未核：書的版權狀態與來源（本庫不推斷，也不鼓勵轉換無權使用的掃描檔）、EPUB是否保留插圖與註腳、校對紀錄的完整度。

## 可參考步驟（自行設計，未執行）

1. 只用有權使用的合成掃描頁，先建立原頁碼與圖塊清單。
2. 將識別文字、圖塊邊界及輸出位置逐項對照原頁，標記裁切、漏字、漏段或順序不明。
3. 若表格、註腳、跨頁圖片或多欄文字無法可靠重建，保留原影像並標待人工校核，不補寫不存在的內容。
4. 分別檢查PDF、Markdown或EPUB的同頁對應，但仍以同一原稿完整性驗收；要求另附「已修改／不確定」清單（來源B做法），逐項回原頁核對。
5. 沒有完成逐頁比對前，不宣稱無遺漏或轉換成功。

## 可貼指令（自行設計，未測）

請只分析這份合成掃描頁與合成重建樣本，列出每頁文字區、圖塊邊界、輸出對應及疑似遺漏。指出裁切、漏段、讀序和未能判定的地方，保留原頁碼。無法辨識不要猜字，不新增原稿沒有的內容。不執行轉檔程式、不安裝OCR、不上傳到第三方。最後列待人工逐頁核對項目，不宣稱可編輯、可搜尋或無障礙合規已驗證。
