# UC-182：依閱讀需求選書與圖書館預約

- 網站標題：想讀的書先幫你挑，再確認圖書館真的可以領
- 一句話用途：把閱讀需求轉成借書候選與預約，清楚區分排隊、到館通知及實際領取。
- 情境：生活
- 標籤：閱讀、圖書館、預約、驗收
- 工具：Meta Muse／作者未具名的圖書館帳戶；Grok Bot／ブクログ（讀書紀錄）／作者未具名的圖書館（2026-10-17補）
- 證據狀態：B，作者預約及收到可取通知自述；Grok Bot版本有選書對話截圖、預約與期限管理為自述；皆無館藏與通知紀錄，未重現
- 查證日期：2026-10-16；2026-10-17補Grok Bot版本（台灣時間）

## 原作者實作

Eleanor Konik於2026-10-12文章的「Library books and a dead dishwasher」段描述：請Muse依閱讀需要找書、挑選書名並提出圖書館預約，幾天後收到郡方的可取書通知。原例是尋找適合較年幼讀者的西洋棋書。

可取通知是圖書館寄給作者，沒有證據是Muse監看或驗證通知。作者明說發文後才要去取書，因此不能寫成已領到、讀完或符合閱讀程度。文章未給館名、書名、版本、館藏紀錄或通知內容，也未核代理如何取得帳戶權限。

這是借閱候選到館藏預約的流程，與付費買書、教材製作、課程規劃或公共列印排隊不同。一本或多本書合計一例。

## Grok Bot版本：從讀書紀錄App的想讀清單挑書，查館藏與電子書價（2026-10-17補）

- 作者：@Gatherinfo4I（X，日文）。[原帖](https://x.com/Gatherinfo4I/status/2111381334518063277)，2026-10-17 08:58 UTC（台灣時間16:58）。API讀到完整文字與一張對話截圖。
- 作者自述：讓Grok Bot登入讀書紀錄App與圖書館後，只要說「想讀某類書」，Bot就從想讀清單挑出合適的書並完成預約，也會檢查歸還期限、避免借太多；作者只需把書加入想讀清單、告訴Bot當下心情。下一步打算讓Bot在Kindle購買（未做，不收錄為已完成）。
- 截圖可見：作者說「想讀推理」；Bot表示ブクログ書櫃設為不公開、外部讀不到，所以在自己電腦的瀏覽器以登入狀態打開想讀清單並抄出93本；從中找出10本推理，其中9本在作者所在地的圖書館可立即借、無人排隊；依作者先前說過「第一次讀的作者想先在圖書館試讀」，挑出5本，附館藏頁連結與Kindle版價格。館名與網址已打碼。
- 與上方Muse版本的差異：輸入是使用者自己維護的想讀清單，而不是一次性的閱讀需求；多了「館藏可借／排隊人數」與「電子書價格」並列比較，以及作者自述的歸還期限與借閱數量管理。截圖只到選書與館藏查詢，預約完成、期限提醒與借閱上限檢查沒有畫面，維持作者自述。
- 授權邊界：Bot在自己的雲端電腦保留讀書App與圖書館的登入狀態；借閱帳戶與閱讀紀錄屬隱私資料，預約、取消與任何購買都應逐次或依明確規則核准。Kindle購買屬付款動作，本頁不提供代購流程。
- 去重判斷：同為「依閱讀需求選書→圖書館預約」的工作，併入本頁作為工具與輸入來源變體，不另立案、不另計數。

## 可參考步驟（自行設計，未執行）

1. 使用不含個人或孩童資訊的虛構閱讀需求，列主題、語言、難度及格式。
2. 在公開館藏資料中草擬候選，附書名、版本、作者與可見狀態；不能確認就保留未知。
3. 由本人確認借閱資格、取書地點、期限及預約限制，再另行決定是否登入和提交。
4. 分開記錄候選、待本人核准、預約成功、運送或排隊、可取、已領、過期；每一步需相應證據。
5. 收到通知後由本人確認來源與期限；不要用預約成功畫面宣稱已可領取。

## 可貼指令（自行設計，未測）

請依這份虛構閱讀需求整理公開館藏候選，不登入、不借閱、不預約、不聯絡圖書館。列出書名、作者、版本、來源及資料中的可借狀態，不推斷適讀性或庫存。另做預約到取書的狀態表，說明每一步要看到什麼證據；沒有通知不能標可取，沒有本人確認不能標已領。不要收集孩童資料或借閱卡號。
