# UC-196：私人陪練對局的控制角色與事件紀錄驗收

- 網站標題：陪練跑完了，先確認誰在控制、紀錄能不能分析
- 一句話用途：讓代理協助維護私人遊戲測試環境，核對對局條件、時間與訊息紀錄，避免把腳本表現當模型能力。
- 情境：開發
- 標籤：遊戲、測試、事件紀錄、驗收
- 工具：Grok Bot／StarCraft II／PlaybotSparBot／burnysc2
- 證據狀態：B，作者使用自述及公開對局、測試產物；未獨立重跑
- 查證日期：2026-10-16

## 問題與已完成的實作

EdwinKestler 的公開專案從已運作的 Ubuntu／Proton 陪練環境整理而來。Grok Bot 協助主機工作與聊天；實際操控遊戲單位的是 PlaybotSparBot 腳本，不能把兩者混寫成模型自主打遊戲。

庫內一局紀錄顯示2026-09-14 23:14:09–23:37:32 UTC的即時私人對局，人類勝、腳本敗。這是已存紀錄，不是本庫觀賽或驗證過的模型競技成績。後續加入條件及資料格式檢查，修正事件時鐘與聊天重複；提交的測試輸出分別記73及78項通過。

重要反例：現存實戰樣本仍是修正前的全零時鐘。修後測試資料通過，不等於已在新真實對局驗收。策略模型、受控比較與排名仍是待辦，不能把聊天模型當策略控制器，也不能宣稱策略進步。

## 可參考步驟（本庫自行設計，未執行）

1. 只讀合成對局清單，先分清主機協作代理、聊天模型、腳本控制器及人類各自做什麼。
2. 核對對局條件、版本、完整或中斷狀態；條件不同的樣本不要合併排名。
3. 用人工製造的小型事件資料檢查時間遞增、訊息來源及重複；保留真正的重複發言。
4. 將單元測試、已存對局、修後新對局分欄。缺回放或新對局證據就保持未驗，不以通過測試替代。
5. 由擁有者決定下一步；本範例不啟動遊戲或連線服務。

## 可貼指令（自行設計，未測）

只讀我給的合成對局清單與事件資料，不安裝、啟動遊戲、連API或帳號。先列每個控制角色，再核時間是否遞增、訊息來源、重複與缺件。分開作者聲稱、原始紀錄、單元測試及修後真局證據。若只有腳本控制或聊天，不稱為模型策略；若修後沒有新真局，不稱已驗收。不要讀私人聊天、公開主機路徑或替任何模型排名。

## 權限、費用與可用性

- 本案是私人陪練／研究資料驗收，不是公開競賽自動化教學。遊戲、地圖、回放及聊天的使用和公開範圍需各自核准。
- Blizzard 的官方協定庫說明 API 可供腳本、研究及回放工具使用；協定程式授權不等於所有遊戲資產或平台操作都獲授權，也不認證本專案。
- Grok Bot、模型呼叫、主機與遊戲的帳號、費用及可用性需另核。來源沒有可採用的本案總成本或現行方案保證。
- 不提供安裝、持續憑證、遠端存取或遊戲控制指令。公開紀錄前仍需確認參與者同意、去識別及授權。
