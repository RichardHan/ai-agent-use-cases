# UC-225：先補齊收據，再把每筆交易配回憑證

- 情境：工作
- 標籤：收據、對帳、缺件、核准
- 網站標題：月底不用翻遍網站：先列缺哪些收據，再配回交易
- 一句話用途：把已存憑證、待取得文件及交易候選分開，讓人工核准有明確依據。
- 工具：Grok Bot／Codex／Money Forward Cloud Expense／Google Drive
- 證據狀態：B，作者實際使用自述；原始帳單、程式與匹配結果未公開，本庫未重現。

作者交辦Grok Bot，由另台Mac的Codex取得卡片CSV；先查經費軟體現有文件，再補缺件。文件重新命名、存Drive及經費系統，按日期、金額、商戶提出配對候選；人核准匹配及正式匯入。平日報告保存、配對、未配對、缺件數和明細截至日。

每週自動抓明細仍在測試，銀行交易也未定期取得；不能稱全自動結帳。作者沒有公開逐筆驗收或精確成本。也不能把「進到經費處理」寫成報銷付款完成。

## 小範圍試法（本庫設計，未執行）

1. 用十筆合成交易及七張虛構收據，先列哪些文件已存在；保留原始檔，不重複收集。
2. 分別比較交易日期與入帳日期、幣別、商戶及金額；同額同日不能單憑兩欄確認。
3. 將一對一候選、合併付款、分拆收據、退款及未找到分列，保留來源列號。
4. 人工確認後才另行討論正式寫回。報告顯示已讀期間與截止日；沒有新明細時不得沿用昨日數字稱今天已完成。
