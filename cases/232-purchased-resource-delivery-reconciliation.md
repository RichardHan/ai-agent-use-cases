# UC-232：教材說下載好了，怎麼核對真的到齊？

- 網站標題：核對已購教材到檔，找出漏下或被漏看的檔案
- 一句話用途：把代理回報與目的地檔案對起來，分清受阻、已存在和仍未知，避免把一次錯誤當成整批失敗。
- 情境：學習
- 標籤：檔案盤點、下載驗收
- 分類：學習／檔案盤點、下載驗收

## 原作者實際完成什麼

作者讓 dots 整理已購英語教材，先確認保存位置與向下載頁提供購買 email 的許可。回報 ZIP 遭 Chrome 阻擋後，代理沒有自行改安全設定；稍後更正為漏看已存的 ZIP。作者親自數目的資料夾，主要檔案為 164 個 MP3、4 個 ZIP、1 個 PDF，與最終報告一致。

這支持「到檔盤點有經作者核對」，沒有證明每個檔案可播放、壓縮包完整或內容無重複。原文沒有展示正式三方 manifest；下面的三清單核對是本庫設計，不能歸給作者。單次錯誤碼也不足確診是哪個擴充或保護功能造成阻擋。

## 怎麼開始：自設只讀練習，尚未實測

1. 準備合成的預期教材清單、下載狀態紀錄、目的檔案清單，不使用購買信或帳號資料。
2. 用穩定 ID、檔名與格式配對；ZIP 與其內部可能包含的 MP3 分列，不能假設兩者是不同內容。
3. 分出已存在、缺件、重複、受阻及未知。紀錄與目的檔矛盾時交人核對，不自行重下或刪檔。
4. 交付差異清單和證據缺口。檔數相等只證盤點一致，內容驗收需另外安排。

## 可貼指令（本庫自行設計，未執行）

請只讀提供的三份合成清單：預期項目、下載狀態、目的檔案。逐項列匹配依據、已存在、缺件、重複及未知。ZIP 與可能的包內單檔分列，不將它們當成不同教材。紀錄說受阻但目的地有檔時，標矛盾待核，不認定成功或再次下載。列出缺少 hash、未解壓、未播放等驗收缺口。不要登入、下載、執行檔案、刪除、改安全設定或傳帳號資料。
