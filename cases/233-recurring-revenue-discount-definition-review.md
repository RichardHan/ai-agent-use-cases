# UC-233：訂閱營收看起來不對？先核折扣有沒有算進去

- 網站標題：找出訂閱營收漏算折扣的地方
- 一句話用途：對照既有 MRR／ARR 的定義與折扣資料，列出需要人工覆核的差異，避免漂亮數字建立在錯誤假設上。

## 作者實際發現什麼

Barry 說自己已用 dots 複核經常性收入資料，過程發現早先部分 MRR 與 ARR 計算沒有妥善反映折扣。這是已發現問題的自述，沒有公開折扣類型、影響金額、原表或更正後結果；不能寫成已修正正式帳務或完成財務審計。

作者也描述客服知識整理，另有未來產品構想，均不計入本例。本文只取已發生的指標核對終點。

## 自設只讀流程（未實測）

1. 提供合成訂閱資料、合成折扣資料、既有 MRR／ARR 表及人工核定的指標定義。
2. 核對服務期間、幣別、訂閱狀態與折扣起迄；定義缺漏先列問題。
3. 逐列對照既有計算，列出疑似未按指定定義反映折扣的項目及依據。
4. 區分資料缺漏、計算差異與定義差異，交由負責人決定；不修改訂閱、優惠或正式報表。

## 可貼指令（本庫自行設計，未執行）

請只讀這份合成訂閱資料、折扣資料與既有 MRR／ARR 表。先列目前使用的指標定義及缺漏，再指出折扣是否依指定口徑反映，每項附資料列號、期間與待核原因。不要自行決定一次性折扣、逾期訂閱或跨幣別的處理。若兩種定義各自成立，列差異而非直接判錯。只交核對清單，不寫回資料、不寄報表、不更改訂閱或付款，不聲稱審計完成。

## 官方背景與限制

[Stripe 的訂閱分析文件](https://docs.stripe.com/billing/subscriptions/analytics) 說明 MRR 的一次性與週期折扣處理可依設定不同，永久週期折扣則會扣除；預製匯出與圖表時區也可能不同。因此不能一概把「沒有扣任何折扣」等同錯誤。先確認原系統定義、日期基準及資料，再談計算。

[ChartMogul 指標詞彙](https://help.chartmogul.com/article/166-subscription-analytics-glossary) 提供服務期間正規化及 ARR 年化估計的背景。年化指標不代表全年已收到現金。兩份文件均非作者使用這些產品的證據，也沒有驗證作者原表。

只需合成或已適當去識別且獲准處理的資料。不得將真實客戶帳務、個人財務或患者紀錄貼到公開案例庫。本案例沒有精確方案費用、連接方式或每次消耗證據；不保證所有帳號可用，不授權建立金融連線或修改會計政策。
