# UC-240：把模糊概念整理成雙語詞彙，再匯出給其他系統使用

- 網站標題：同一個詞各說各話？做出能交換的雙語詞彙表
- 一句話用途：讓代理協助固定概念、例外與關係，交付有版本的語意資料；內容是否合理仍由人審。
- 情境：學習
- 標籤：知識整理、資料交換、驗收
- 分類：學習／受控詞彙
- 適用工具：Grok Bot；公開 YAML、SKOS、JSON-LD 產物
- 證據：A，作者使用自述與公開產物；未獨立重現，沒有科學有效性或完整驗證通過證據。
- 作者／語言：Lomig Unger（BLOmiG）；法文，產物含法文／英文。
- 原文日期：2026-10-14 11:03:56 UTC；固定產物版本 b3db86e25e18d23255a42e5e272107a02bb3ec68，2026-10-16。
- 查閱日期：2026-10-16 UTC。

## 可以幫你做什麼

將團隊含糊用語整理為固定 ID、雙語名稱、定義、反例與關係，讓人能討論同一概念，也讓其他系統讀取。此案的終點是可交換的受控詞彙，不是概念起源考證（UC-205）、圖片分類（UC-121）或既有資料表補欄（UC-212）。

## 原作者實際做了什麼

作者描述以感知特性詞彙 brief 與 Grok Bot 團隊合作，審閱初版與邏輯問題，加入解說工作並公開 beta。公開 README 明確署名作者與 Grok Bot。規格也列工作坊及較早草案，因此不將「以 brief 起始」擴大為完全沒有其他材料。

本次直接核對固定版本 README、hue 詞條與規格修訂；並抽讀公開匯出檔。可見固定概念 ID、法英標籤、定義、不適用例與易混淆關係。規格記錄補版本標識、調整檢索標籤及重新匯出的工作。這些支持資料建構與修訂已發生，不能證明所有概念正確。

## 怎麼開始

以下是本庫自行設計、未執行的低風險練習：
1. 選少量合成概念，先說清用途、使用者與不打算評判的事項。
2. 各概念分配穩定 ID，列兩種語言的名稱、定義、反例與不適用條件。
3. 分開上下位關係、近義詞及容易混淆的概念，不讓代理自行把它們合成同一類。
4. 產出可讀表與語意資料草稿，逐筆對照 ID、標籤、關係及版本。
5. 人審歧義與修改理由；發布前另確認授權，未通過項保留待審。

## 可貼指令（自行設計，未測）

請用我提供的合成概念建立小型雙語受控詞彙草稿。每項列穩定 ID、兩種語言名稱、定義、反例、不適用條件與關係。先列衝突供我決定，不自行用漂亮或正確等評價詞替代描述。另給 YAML 與 SKOS 表示草稿，逐項核對兩份內容是否一致，記錄版本差異。不要執行程式、安裝套件、發 issue 或發布。格式可解析與內容成立分別標示；缺乏檢查證據時寫未驗證。

## 要注意什麼

- README 明言詞條尚未經實驗，部分未完成；試驗目錄只有說明與模板。不能宣稱感知分類已獲科學驗證。
- 規格提到驗證工具與報告，但該版本公開樹未取得所指驗證報告；本庫沒有跑程式。不能把作者寫「已驗證」當測試通過證據。
