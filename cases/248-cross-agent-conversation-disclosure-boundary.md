# UC-248：跨代理群聊的資料揭露邊界與單向交接

- 網站標題：把幾個AI拉進同一群後，私人背景也被傳出去？先縮小交接內容
- 一句話用途：從作者實際群聊失誤，整理接收者、可分享欄位與單向摘要交接的驗收方式。
- 情境：工作
- 標籤：跨代理、隱私、群聊、驗收
- 工具：Meta Muse／Telegram／OpenClaw
- 證據狀態：B＋V，作者實際群聊及改架構自述；無完整日誌，隔離效果未驗證
- 查證日期：2026-10-16

## 原作者實作與結果

Loni、Clinton Stark把兩個Muse與自管OpenClaw代理放進Telegram群。作者回報，後者分享了本人不預期交給Muse的私人背景，因此移出高權限代理，改由低權限代理定期整理逐字內容供其讀取；這項交接仍在初步階段。也自述群內內容能延續到Muse App對話。

來源是本人對談整理，作者另有代理記憶產品與研究事業；並無完整群聊、配置或隔離測試。未公開的私人內容不重述，不認定是Muse主動竊取、官方漏洞或已修復。稿中討論的注入檢查方案不能當成已驗證有效。

## 可參考步驟（本庫自行設計，未執行）

1. 只用合成對話，列出每名接收者、所在服務與允許分享目的。
2. 標記每段內容可分享、需本人核准或不可分享；加入一段與任務無關的合成背景作拒絕測試。
3. 產出最小摘要及來源行號，讓本人檢查後才討論傳送；不直接傳整份聊天或記憶。
4. 檢查摘要是否混入被排除欄位，以及下游要求補資料時是否停下重新確認。
5. 記錄來源版本、接收者與核准範圍。單向設計只是降低接觸面，不保證接收端不再轉傳。

## 可貼指令（自行設計，未測）

只分析以下合成群聊及允許分享清單，產出一份尚未傳送的摘要。每句附來源行號、接收者與允許目的；被排除內容只記「已省略」，不複述。若接收者、資料範圍或目的不清楚，列待確認。不要聯絡其他代理、加入群組、讀私人記憶、建立連接或傳送任何訊息。另列一段越界索取的合成測試及應停止的條件。

## 權限、費用與可用性

- [Muse Connector官方指南](https://platform.muse.ai/docs)要求最小資料範圍，並區分讀取與分享／送出行為；連接帳號不代表批准每項動作。這是平台原則，不證實作者的Telegram介面、配置或其安全效果。
- 對外代理交接須先核對接收方、內容與目的；新增連接或持續存取另需適當批准。本庫未建立群組、安裝或傳送。
- 作者沒有完整費用或適用方案資料；不能認定此架構免費或對所有帳戶可用。
