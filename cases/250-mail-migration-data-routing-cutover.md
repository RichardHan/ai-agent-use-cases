# UC-250：郵件資料搬遷與收信路由接管驗收

- 網站標題：信箱搬家了，舊信與新來的信都有到對地方嗎？
- 一句話用途：兩位作者回報Grok Bot協助郵件搬遷，重點是把資料複製與新信路由切換分開核對。
- 情境：工作
- 標籤：郵件、搬遷、路由、驗收
- 工具：Grok Bot／Microsoft／MXroute
- 證據狀態：B，原作者完成自述；無原始對帳或停機紀錄
- 查證日期：2026-10-16

## 原作者實作與成果

u/nighthawk5300在Reddit回報其舊郵件系統已搬至Microsoft，提到遷移軟體、MX切換及公司簽名。這支持作者曾實際使用的敘述，不能認定所有信件完整、授權合規或沒有中斷；本庫沒有原始信箱、對帳、收發測試或切換日誌。

另一位u/Ecstatic_Builder8325回報舊VPS郵件搬往MXroute，稱約兩日完成。其無漏信及規模說法未獨立驗證，也沒交代MX切換，不能借第一位作者的步驟補成同一次流程。

兩個供應商版本合併一案；不將購買授權、簽名圖樣及其他網站搬遷各算新案例。

## 可參考步驟（本庫設計，未執行）

1. 用合成清單分列來源與目標信箱、資料夾、信件識別與時間範圍，標出未能比對項。
2. 分開檢查歷史信件複製與搬遷期間增量；只看總量相同不足以證明無遺漏或重複。
3. 另列新信目前路由、切換證據、收發測試結果與舊服務保留狀態。缺證據就標未知。
4. 將資料完成、路由接管、人工驗收設成不同欄位，不讓任一成功訊息替代全案完成。
5. 把差異與待核事項交IT；真正登入、傳輸私信、改密碼、改DNS及關停舊服務另行授權與安排。

## 可貼指令（自行設計，未測）

只讀我提供的合成來源／目標郵件manifest及合成路由狀態，準備搬遷驗收清單。分開歷史資料、增量信件、資料夾、缺件或重複、MX接管證據及收發測試。不要因總數相同就寫無漏信，缺資料標未知。不要登入、傳真實郵件、建立憑證、重設密碼、改DNS、寄測試信或關閉服務。輸出待IT覆核差異及缺口。

## 權限、費用與可用性

- 郵件包含敏感內容，複製與授權本身已有風險，不是等到改MX才需要注意；本案不建議交出密碼或持續憑證。
- 作者提及付費授權與遷移軟體，但未提供完整費用，不能認證節費。Grok Bot方案與特定企業環境相容性未核。
- [MXroute遷移文件](https://docs.mxroute.com/docs/migrate-to-mxroute.html)提醒核驗轉入郵件、路由與客戶端設定並保留過渡期；不代表作者採用了文件中的工具。
- [Microsoft IMAP遷移文件](https://learn.microsoft.com/en-us/exchange/mailbox-migration/migrating-imap-mailboxes/migrate-other-types-of-imap-mailboxes)區分信件核對、收發與MX切換，DNS傳播期間不能過早停止同步。未核作者使用IMAP，這是驗收背景，不能當其完整操作紀錄。
- 本庫僅研究公開敘述，沒有搬信、寄信、購買或操作DNS。
