# UC-268：網站、圖文與影片綁成同一核准包，再驗收草稿交接

- 情境：工作
- 標籤：行銷、多代理、核准、驗收
- 網站標題：替客戶做一套行銷素材：網站、貼文圖、短影片一起做，核准後只交草稿、讀回再清理
- 一句話用途：用同一份客戶簡報，讓網站、設計、影片、廣告研究、社群五個 Bot 依序產出，最後把文案、圖片、影片和發布目的地打包成一份給客戶核准；任何一處改動就要重新核准。
- 核心目標：讓多個 Bot 共用同一份已核准的訊息與報價入口，避免網站、圖文與影片各說各話，並把「客戶核准的版本」和「實際交出去的草稿」綁在一起。
- 分類／標籤：行銷代理工作流程／多 Bot 交接／客戶核准
- 適用工具：Grok Bot（作者自製五個可匯入模板）；作者在現場用 Codex computer use 代為建立 Bot；Zernio（發布草稿交接）；Next.js、Remotion（作者模板產出的網站與圖片／影片格式）
- 目標使用者：小型行銷工作室、接案者、要替客戶重複產出同一套活動素材的人
- 首次收錄／最近查證：2026-10-17（台灣時間）
- 證據狀態：author-demo。作者現場示範自述＋公開產物、核准包與草稿讀回／清理回條可讀（混合執行）；客戶為作者虛構的清潔公司，非真實客戶成效。
- 是否獨立重現：否。本庫未匯入模板、未產生素材、未連接 Zernio。

## 輸入與預期輸出

- 輸入：一份客戶簡報（服務項目、可公開的事實、照片、地區、報價入口）；客戶提供的最終審稿意見。
- 產出（作者流程）：一個含報價表單的網站與共用簡報 → 一張靜態社群圖（含同一句主張與報價 CTA）→ 研究廣告參考後的兩個概念與分鏡 → 一支約 15 秒短影片 → 一份「審核包」（確切文案、媒體、連結、客戶、發布目的地）→ 客戶核准後才以草稿形式交給 Zernio。
- 不包含：自動排程上線、投放預算、成效保證。作者簡報明寫 Zernio 草稿之後還要另做排程決定。

- 簡報頁可讀的流程細節：
  1. 五個 Bot：Site Builder（網站與報價流程，並分享已核准簡報）、Social Media Manager（規劃自然貼文、審查活動並把核准稿交給 Zernio）、Performance Marketer（研究廣告，簡報提到 Meta Ads MCP）、Content Creator·Design（網站圖片與靜態圖）、Content Creator·Video（分鏡、算圖、修改影片）。
  2. 一個 Bot 負責一件事、技能保存方法、人核准結果；先用「Desert Shine 範例乾跑」演練，流程穩了才存成 routine。
  3. 靜態圖先做一張好的、拿到回饋才做變體；影片先提兩個概念與分鏡給人核准，再出 15 秒版本，看完整支再回饋。
  4. 審核包把確切文案、媒體與目的地一起核准；簡報內的示意互動說明「改了文案就重設核准」，該示意是本機模擬、不連帳號。
  5. 成效檢查建議：活動連結加標記接到報價表單，記錄哪些詢問變成實際訂單，並在投放前先定預算與可接受的取得成本。
- 失敗點與限制：客戶、地區與服務清單都是示範假設；簡報頁的核准互動是模擬；作者稱已發布到自家 X 帳號，但本庫未逐一核對那些貼文；未公開用量、費用或修改輪數。

## 建議操作流程

以下為本庫依來源整理的設計，未實跑：

1. 先只開兩個 Bot（網站＋設計），用虛構客戶簡報乾跑；確認共用簡報檔的位置與版本號。
2. 網站核准後才產圖；每張圖與影片都回指簡報版本，主張與 CTA 一字不差。
3. 影片先交概念與分鏡，不直接算圖；算出後人看完整支才算可審。
4. 做審核包：一列一個發布項目，欄位為文案、媒體檔名、連結、目的地、簡報版本、核准人、核准時間。任何欄位改動就清空核准。
5. 核准後只建立發布草稿，不排程、不投放；排程與預算是另一個決定。
6. 用標記連結追蹤詢問→成交，不用按讚數當成效。

## 所需連接、權限與限制

- 連接：本次可讀回條使用既有本機 Zernio 連接完成交接；原生 Grok Bot–Zernio 尚未設定，Meta Ads MCP 尚待重連與唯讀檢查。不能寫成五個 Bot 端到端自行發布。
- 核准點：發布、排程、廣告花費、用客戶名義對外發言都要客戶與本人另行核准；草稿交接不等於上線授權。
- 客戶資料：照片與服務事實要客戶提供並同意使用；不要用生成圖冒充真實施工成果。
- 官方背景：[Grok Bot Bots 文件](https://docs.x.ai/grok-bot/bots)說明可建立多個專責 Bot；[skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)說明先把一次性任務做穩、再存技能、最後才自動化，與作者「先乾跑再存 routine」一致。這只說明功能存在，不證明作者成果。
- 本庫未核 Zernio 的權限範圍、費用或草稿行為。

## 驗收與可重現性

- 抽查網站、圖、影片是否用同一句主張與同一個報價入口。
- 改審核包任一欄後，確認核准狀態被清空。
- 確認交出去的是草稿而非已排程貼文。
- 本庫已讀貼文、公開簡報、核准包與作者託管的草稿讀回／清理回條；作者產物不等於服務端獨立稽核，與會者使用與實際發布仍未核。
