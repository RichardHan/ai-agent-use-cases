# UC-270：每月掃一次發票，找出能自己做的訂閱，先盲測品質再決定要不要退訂

- 情境：省錢
- 標籤：訂閱、自建替代、盲測、每日
- 網站標題：每月讓 Bot 看發票：哪個付費工具可以自己做？先做替代品、盲測打分，夠好才退訂
- 一句話用途：每月請 Bot 讀 Gmail 裡的訂閱發票，挑出核心功能只有一兩項、可能自己做得出來的服務，組一組 Bot 做替代品，再交給另一個「評分 Bot」盲測比較；作者用這方法把一個每月 399 美元的 AI 能見度工具換成自建流程，每天量測、每月約 45 美元。
- 核心目標：把「這個訂閱值不值得」從感覺變成有比較基準的決定：替代品要在盲測裡達到可接受品質，並算清楚替代後的實際成本，才退訂。
- 分類／標籤：訂閱費用／自建替代／品質評估
- 適用工具：Grok Bot（多個 Bot＋獨立評分 Bot）；Gmail（發票）；作者另用 @treg_ai 的計費服務追蹤提示；被替代的是 Profound（作者描述為讓產品更常被 ChatGPT 提到的 AI SEO 工具）
- 目標使用者：小公司創辦人、獨立開發者，訂閱一堆 SaaS 又懷疑有些只用到一兩項功能的人
- 首次收錄／最近查證：2026-10-17（台灣時間）
- 證據狀態：author-demo。作者第一人稱自述與完整月度提示詞；品質百分比、成本與流量成長皆為作者自報，無原始評分或帳單。
- 是否獨立重現：否。

## 輸入與預期輸出

- 輸入：Gmail 中的訂閱發票；被比較服務的 1–2 項核心功能與價格；作者的人工回饋。
- 每月輸出：可考慮自建替代的訂閱清單、每項替代品的盲測結果，以及「值得繼續」的回報。
- 作者替代後的日常輸出：每天量測自家產品在 AI 助理回答中的能見度、針對缺口寫文章、反覆修改文章直到開始被 ChatGPT 與 Claude 提到。

## 建議操作流程

以下為本庫設計，未實跑：

1. 先只讀：讓 Bot 從發票整理訂閱清單（服務、月費、續約日、你實際用到的功能）。不登入廠商後台、不取消。
2. 挑一個候選，寫下「最少要做到什麼」的驗收清單與測試題（例如 20 個要追蹤的查詢）。
3. 替代品與原服務用同一組測試題各跑一次，輸出去掉來源標記，交給另一個沒參與製作的評分 Bot 依清單打分；人再抽查。
4. 算總成本：外部 API 計費＋Bot 用量＋你花的修正時間，與原訂閱月費並列。
5. 只有盲測達標且成本確實較低時，才由你自己決定退訂；退訂前確認資料匯出與合約期限。
6. 替代品上線後若設定每日量測，保留每天的原始查詢結果，避免只看 Bot 摘要。

本庫原創設計，未實跑：

> 請只讀我 Gmail 中標記為「發票」的郵件，整理過去 3 個月的訂閱：服務名稱、月費、續約日、從郵件可看出的用途。不要登入任何服務、不要取消或回信。接著挑出最多 2 個「核心功能看起來只有一兩項」的服務，各寫一份替代評估計畫：要保留的功能、驗收清單、20 題測試、要用的工具與預估月成本（分開列外部 API、Bot 用量、我需要投入的人工時間）。評分要交給另一個沒參與製作的 Bot，以去除來源標記的方式盲測。全部只是計畫，等我核准才開始做。

## 所需連接、權限與限制

- 連接：Gmail 只需讀取發票；替代品可能需要外部 API 或外掛，每一個都有自己的費用與資料流向。
- 核准點：建立新付費服務、退訂原服務、以產品名義發文章都要本人決定；作者流程中「反覆修改文章直到被提到」會持續對外發布內容，需留意品質與平台規範。
- 評估偏誤：同一個模型家族同時製作與評分仍可能有偏好；盲測只降低、不消除偏誤，關鍵指標要人抽查。
- 授權：自建替代不能複製原服務的受保護內容或違反其條款。
- 官方背景：[Grok Bot Bots 文件](https://docs.x.ai/grok-bot/bots)說明可建立多個專責 Bot；本庫未核作者所用外掛與 treg 服務的實際價格或條款。
