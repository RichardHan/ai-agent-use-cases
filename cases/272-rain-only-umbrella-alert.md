# UC-272：每天早晚各查一次天氣，只有會下雨才提醒帶傘

- 情境：生活
- 標籤：每日、天氣、提醒、排程
- 網站標題：不想每天被天氣訊息洗版？讓代理早晚各查一次，有雨才傳訊提醒帶傘
- 一句話用途：設定兩個固定時間（早上查當天、晚上查隔天）去查指定行政區的官方預報；只有預報有雨才發訊息，沒雨就完全不出聲。
- 核心目標：把「每天看天氣」改成「有事才通知」的條件式排程，減少無用推播，同時附上預報出處方便自己判斷。
- 分類／標籤：日常提醒／條件式通知／排程
- 適用工具：作者稱 Grok Bot、ChatGPT dots、Meta Muse 都能用這段提示詞；截圖未顯示是哪一個產品執行，本庫不推定
- 目標使用者：通勤、接送小孩或常騎車外出，只想在需要時收到提醒的人
- 首次收錄／最近查證：2026-10-17（台灣時間）
- 證據狀態：author-demo。作者自述每天使用，附 1 張實際執行的訊息截圖（前晚 20:59 與當天 08:03 兩則）。
- 是否獨立重現：否。

## 輸入與預期輸出

- 輸入：一個地區（作者範例為深圳市寶安區）、兩個時間點（08:00 查當天、21:00 查隔天）、「有雨才通知，沒雨不說話」的條件。
- 輸出：有雨時傳一則簡短訊息：預報內容、建議帶傘、官方是否給出降雨時段或機率、預報發布時間與出處連結；沒雨時不發任何訊息。

## 建議操作流程

以下為本庫設計，未實跑：

1. 指定一個明確地區與一個官方氣象來源（例如台灣用中央氣象署的鄉鎮預報），避免它每次換來源。
2. 寫清楚觸發條件：降雨機率達多少％或預報文字含「雨」才算；兩個時間各自對應「當天」與「隔天」。
3. 要求每則訊息附預報發布時間與連結，並區分「官方有給降雨機率」與「只有文字描述」。
4. 先跑一週：每天自己對照一次，確認沒雨的日子它真的沒發訊息、有雨的日子沒有漏報。
5. 確認無誤後再增加地點（例如住家與公司）或特殊條件（高溫、空汙）。

## 所需連接、權限與限制

- 只需要公開氣象網站與傳訊通知；不需要位置權限或個人帳號。若要用即時位置，應另外評估隱私。
- 「沒有通知」可能是沒雨，也可能是排程失敗；重要行程前仍應自己看一次預報。
- 預報本身有不確定性；代理只轉述官方預報，不應自行預測。
- 各產品的排程與通知方式不同，本庫未核三個產品是否都能完整執行同一提示詞。
