# UC-276：替每位同事做代理入口，卻被輪詢耗盡額度

- 網站標題：每人只看自己的代理工作區？先驗證存取邊界，再計算輪詢成本
- 一句話用途：從作者已做出的分人員入口與失敗回報，檢查「看不到別人的頁面」是否真的限制後端資料，以及空跑輪詢是否值得。
- 情境：開發
- 標籤：權限、多人入口、輪詢、失敗復盤
- 分類／標籤：代理工作區／存取邊界／用量
- 工具：Grok Bot／Base44／Claude
- 證據狀態：B，作者第一人稱實作與失敗自述；無程式、用量紀錄或隔離測試，未重現
- 查證日期：2026-10-17

## 原作者實作與結果

Reddit作者u/The_Bossman77希望同事各自只能使用指定代理，於是用Claude及Base44建登入入口，分出業務、行銷與主管的聊天工作區，再讓各Grok Bot只去指定入口。作者設定每15分鐘查看一次；代理回覆後，接下來15分鐘每分鐘查看有無新回覆。後來改做未讀訊息看板，由協調代理檢查並通知對應代理，仍回報耗盡額度，求助如何完成同一組織的分人存取。

這是已嘗試但未達目標的案例。作者稱前端入口限制成功，並未提供後端授權測試；不能說明敏感資料已隔離，也沒有實際洩漏證據。「耗盡」沒有金額、用量或測量區間，不換算節省比例。作者對當時產品席次的理解不當作現行產品規格。

## 可參考步驟（本庫設計，未執行）

1. 只用兩名虛構人員、兩個測試工作區及合成訊息，列出誰可以讀取、回覆哪些資源。
2. 分開檢查前端可見性、後端請求授權、代理可讀檔案及共用登入；角色提示詞不是權限控制。
3. 準備正常請求、跨工作區請求與直接資源網址的測試清單。未取得系統所有人授權，不執行測試。
4. 先算排程上限與空跑比例；分開記錄查未讀、載入背景、派工及回覆成本，不先假設改成協調代理就便宜。
5. 留下待解問題與人工接手方式。未有存取與用量證據，不接真實同事帳號或資料。

## 可貼指令（原創設計，未測）

請只用以下虛構人員、工作區及訊息，做分人存取與輪詢成本的離線審查。列出前端可見性、後端授權、共用登入、代理檔案存取各自要驗證的事項；再依提供的排程算每天最多檢查次數，缺少用量單價就標未知。不要建立帳號、連接信箱、設定OAuth、部署、改權限或傳訊。不要把角色提示當作存取控制證據。

- [Grok Bot官方安全文件](https://docs.x.ai/grok-bot/approvals-security-and-privacy)於本輪可讀，頁面標示2026-10-12更新：同一使用者的Bots共用雲端電腦，檔案、瀏覽器登入與命令列憑證可跨Bots使用，不能把分開的Bot視為安全邊界。此文件不驗證作者Base44入口的設定。

- 正式服務的方案、組織控制與費用可能變動；本案無可比較的完整成本資料。
