# UC-310：記錄每次雲端代理執行，把錯誤歸因到協調、指令或模型

- 情境：開發
- 標籤：多代理、模型評估、失敗、驗收
- 網站標題：代理出錯是模型不行，還是派工出問題？用執行紀錄自己算
- 一句話用途：由專案經理 Bot 派出並記錄每一次雲端程式代理的執行，對每個錯誤標註類型與原因（協調、指令、模型），產生儀表板，每週建議各角色該用哪個模型。
- 分類：多代理／執行評估
- 工具：Grok Bot（PM Bot）／Cursor Cloud Agents／@poteto 的 /poteto-mode 技能／JSONL 紀錄＋儀表板腳本
- 證據狀態：`author-demo`（作者自述實測＋儀表板截圖）；本庫流程與提示詞為 `designed`（自行設計未實測）
- 查證日期：2026-10-18（台灣時間）
- 獨立重現：否

## 輸入與預期輸出

- 輸入：每次代理執行的紀錄（模型、角色／工作、PR、核准結果、發現的問題）；每個錯誤的描述、證據（commit、PR 編號）與人工或 PM Bot 標註的原因。
- 輸出：執行數、錯誤數與錯誤率；依模型、依錯誤類型（白跑、沒照規則、重複執行）與依原因（協調、指令）分組；近期錯誤清單附證據；每週的角色—模型配置建議。

## 建議操作流程（本庫設計，未實跑）

1. 先定義紀錄欄位：執行 ID、角色、模型、PR／分支、開始結束時間、核准狀態；錯誤另存：類型、原因（協調／指令／模型／環境）、證據連結、誰標註。
2. 只讀方式回填一天的既有執行紀錄，人工標註原因，確認分類可用。
3. 讓 PM Bot 每次派工後自動寫一筆紀錄；錯誤原因由 Bot 初標、人工抽查改正。
4. 產生簡單儀表板：依原因、模型、類型分組；每筆錯誤可點回 commit 或 PR。
5. 每週只產出「建議」：哪個角色換模型、哪個協調規則要改（例如合併即停止修復代理、未看截圖不得合併）；改動由本人核准。

## 可複製提示詞（本庫原創，未測）

請只讀今天所有雲端程式代理的執行紀錄與相關 PR，整理成兩個 JSONL：一筆一個執行（角色、模型、PR、狀態、核准），一筆一個錯誤（類型、原因：協調／指令／模型／環境、證據連結）。原因不確定就標「待判定」，不要猜。然後產出摘要：依原因與模型分組的錯誤數、三個最常見的協調問題、建議新增的停止規則。不要重新啟動或停止任何代理、不要合併或關閉 PR、不要更改代理設定。

## 所需連接、權限與限制

- 需讀取代理執行紀錄與 GitHub PR；若要讓 PM Bot 實際停止代理或調整模型，屬寫入動作，須另外授權。
- 一天 5 次執行的樣本太小，不能據此判斷模型優劣；原因標註本身也可能由出錯的協調者（PM Bot）自評，需人工抽查。
- 來源未提供費用；白跑的代理會消耗用量，這正是此紀錄的價值之一，但本庫未核金額。

## 驗收與可重現性

- 每一筆錯誤都必須有可點開的證據（commit、PR、訊息）。
- 統計欄位前後一致（例如「有錯的執行數」與各模型錯誤數能對上）；作者截圖即有一處對不上，可作為驗收反例。
- 每週建議要能回溯到哪些紀錄。
