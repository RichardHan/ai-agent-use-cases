# UC-317：夜巡小隊：每天凌晨自己選題、做出原型、互相驗收，早上交報告

- 情境：開發
- 標籤：每日、排程、多代理、驗收
- 網站標題：讓四個 Bot 半夜輪班做一個小作品：選題、實作、獨立檢查，早上看成果報告
- 一句話用途：每天凌晨 3 點啟動一組分工的 Bot：探索者提出最多三個題目並選一個、實作者做出能跑的原型、審查者照 README 從頭重跑並分級找問題、隊長控管時間與邊界並寫晨報；全程只在沙盒目錄裡，不碰正式專案。
- 核心目標：把「半夜自主做實驗」變成有時間窗、交接順序、誠實驗收與失敗標示的例行流程，隔天能直接看結果。
- 分類：自主原型實驗／多代理交接
- 工具：Grok Bot（四個 Bot＋群組 routine，作者在 7 天試用期內使用）；設定文字作者自述與 ChatGPT 討論後定稿

## 輸入與預期輸出

- 輸入：四個 Bot 的角色說明（隊長、探索者、實作者、審查者）、群組裡的一則啟動指令、每天一個全新的沙盒工作目錄。
- 輸出：當天的探索紀錄（候選題目與選擇理由）、可執行的原型與本機 git 提交、審查者的分級問題清單、隊長的晨報（Complete／Partial／Failed、怎麼執行、哪些真的跑過、是否值得保留、下次怎麼改提示與交接）。

- 作者做法（翻譯改寫，非逐字）：
  1. **時間窗**：建議 03:00–09:00，依序為探索與選題、實作與除錯測試、獨立驗證、依審查修一輪、最終驗收與晨報；提早完成可直接進下一段，不為填滿時間做無意義工作。
  2. **交接順序寫死**：探索者 → 實作者 → 審查者 → 實作者（選擇性修正）→ 隊長；隊長不能因為自己比較快就跳過審查或假裝別人做完。
  3. **選題規則**：最多三個候選，評估今晚能否做完、技術風險、是否需要外部服務、能否完全在沙盒完成、怎麼展示；避免純 TODO App、純登陸頁、只換顏色的 CRUD。題目若需要付費 API、正式帳號或公司資料，直接改成不需要的版本，不半夜找人。
  4. **實作者**：必須真的 Build／Run，遇錯先自己除錯，範圍太大就縮小，假設不成立可轉向但要記錄；不能只交程式片段、README 或滿是 TODO 的成果。
  5. **審查者**：第一版完成前不介入；先不看實作者自評，照 README 從乾淨狀態安裝、建置、執行核心路徑，再從可執行性、技術品質、實驗價值與「誠實度」（是否誇大、把 Partial 寫成 Complete、把 Mock 說成真整合）評估，問題分 BLOCKER／HIGH／MEDIUM／LOW，只要求當晚修 BLOCKER 與少數 HIGH。
  6. **安全邊界**：只能寫入當天沙盒目錄；不讀其他 Bot 目錄、作者的正式專案或公司資料；不碰正式環境、不自行發文寄信、不付費、不推送正式 repo、不 force push、不擴大密鑰權限。
- 作者回報的結果：最後一次夜巡列出圓形連線、希爾伯特曲線、仿植物種子排列三個候選，隊長選了圓形連線，理由是圖案容易辨識、規則簡單、容易檢查連線結果。作者說留下了可操作網頁、圖片匯出程式、範例圖、自動測試、選題與檢查紀錄。
- 本庫核對到的範圍：公開 repo 只有 `README.md`、`app.js`、`index.html`；文中提到的 Python 指令版、自動測試、晨報與審查紀錄**沒有在公開 repo 中**，無法核對測試是否通過或審查找到什麼。作者沒有提供每晚用量、費用或失敗次數。

## 建議操作流程（本庫設計，未實跑）

1. 先只開兩個角色（實作者＋審查者），手動觸發一次，確認沙盒路徑與「不准做的事」都有被遵守，再加排程與其他角色。
2. 每天用全新目錄，不沿用前一天的程式碼；晨報固定寫明 Complete／Partial／Failed。
3. 審查者一定要照 README 從頭跑一次，並另外檢查「宣稱有測試」的地方是否真的有測試檔與執行結果。
4. 早上只看晨報與 Demo；值得保留的才由人手動移到正式 repo。
5. 連續幾天都失敗或成果重複時，先改選題規則或交接說明，不是加更多 Bot。

## 可複製提示詞（本庫原創，未測；結構參考作者設定，非逐字）

你是夜間實驗的審查者。只有在實作者通知第一版完成後才開始。先不要看實作者的自評，依 README 在乾淨的當日沙盒目錄中安裝、建置、執行核心流程，逐步記錄指令與結果。接著檢查：README 是否誇大、是否把部分完成寫成完成、宣稱的測試是否真的存在並通過。問題分 BLOCKER／HIGH／MEDIUM／LOW，只要求今晚修 BLOCKER。只能讀寫當日沙盒目錄；不要讀其他目錄、不要推送任何遠端、不要安裝需要付費或登入的服務、不要對外發文或寄信。最後交一份可以讓人早上五分鐘看完的審查摘要。

## 所需連接、權限與限制

- 需要 Bot 的雲端電腦、可安裝套件與本機 git；不需要也不應該給正式 repo 推送權、公司資料或付費 API。作者設定明確禁止這些。
- 多個 Bot 共用同一台電腦時，「不讀其他 Bot 目錄」只是指示，不是系統隔離；敏感檔案不要放在同一台電腦。
- 每天自動跑六小時會持續消耗用量；作者沒有提供數字，要先觀察一兩次再決定頻率。
- 任何要公開的成果（推上 GitHub、發文）由人另外決定。

## 驗收與可重現性

- 晨報的「真的跑過」項目，能在沙盒裡找到對應指令輸出或測試結果。
- 審查者至少一次標出 Partial 或 Failed 時，晨報沒有被改寫成成功。
- 沙盒外沒有新增或修改的檔案；沒有任何對外推送或發文紀錄。
- 本庫未執行；作者的公開成果只證明有一個可用的網頁版原型。
