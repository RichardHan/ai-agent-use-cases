# UC-336：自製圓形掌上裝置當Grok Bot語音入口：錄音上傳、轉文字、經MCP送達再回到螢幕

- 情境：開發
- 標籤：實體裝置、語音、MCP、延遲
- 網站標題：不打開手機，按一下手上的小圓屏就能跟AI團隊說話
- 一句話用途：作者把一個ESP系列圓形螢幕裝置接到Grok Bot：裝置錄音上傳，自己的Mac轉文字後經本機MCP服務送給Grok Bot，回覆再沿原路回到裝置螢幕。作者稱優化後一來一回在兩分鐘內，仍嫌慢。另一版本（2026-11-13補）：英文作者 @LifeofJohnnyOD 用 Grok Bot 自己寫出 iPhone＋Apple Watch App「Bob」，錶面一鍵發起即時語音通話，聲音走 Meta Ray-Ban 眼鏡，底層用 xAI 的 Grok Voice 即時 API，通話中 Bob 能查行事曆、提醒、郵件與訊息。

## 為什麼這個用法值得看

多數實體裝置案例是「代理控制裝置」或「裝置事件喚醒代理」。這裡把裝置當成對話終端：輸入是人的語音，輸出是代理的回覆。作者也誠實列出瓶頸：每一跳都加延遲，而代理本身只花十幾秒，真正的時間花在中繼與轉換上。

## 建議操作流程（本庫設計，未實測）

1. 先畫出完整鏈路，每一跳記下延遲：錄音上傳、轉文字、送進代理、代理處理、回傳、顯示。
2. 先用只讀的問題測試（例如「今天行事曆有什麼」），確認回覆能正確回到裝置；再考慮讓語音觸發任何會對外的動作。
3. 外部可達的通道（tunnel）要加驗證，只收自己裝置的請求；轉文字結果在送出前可先在裝置上顯示確認。
4. 為「沒有回覆」設逾時與錯誤顯示，避免使用者以為代理收到了。

## 可貼指令（本庫原創、未測）

我透過一個語音終端和你對話，訊息會先被轉成文字，可能有錯字或斷句錯誤。請遵守：每次回覆不超過80字，先用一句話重述你理解的要求；如果要求涉及寄信、發文、付款、刪除或改設定，只回覆「需要在手機或電腦確認」並停止，不要執行。聽不懂就請我重說，不要猜。

## 所需連接、權限與限制

- 需要自建韌體、本機轉文字與MCP服務，以及對外可達的通道；通道若未加驗證，任何人都可能送訊息進你的代理。錄音可能含旁人聲音，留存與轉文字要注意隱私。
- 作者的Mac必須開機在線才能中繼；延遲約兩分鐘是作者自述，未見逐段計時。
- Grok Bot可用的入口（MCP、連接器、對外呼叫）依方案與版本變動；作者的「不開放外部呼叫」是當下觀察，需自行查官方文件。
- 語音轉文字錯誤可能導致代理誤解；不應用語音直接觸發有實際影響的動作。
