# UC-340：搜尋代理的實際工具回應與模型輸出分開驗收

- 網站標題：代理說讀到了網頁，怎麼確認真的有抓到來源？
- 一句話用途：作者把模型自行輸出的文字和實際HTTP回應分開，避免只憑代理說「找到」就接收搜尋結果；保留這套試驗的可核範圍。
- 情境：開發
- 標籤：搜尋、證據來源、工具紀錄、驗收
- 分類：代理工具取證與結果接收的隔離
- 工具：Grok Bot／Hermes／Ollama／SearXNG／curl_capture／JEV判讀器
- 作者／日期／語言：Марк Грабарёв（iseedeadpixels），2026-10-11，俄文。
- 首次收錄／最近查證：2026-10-18（台灣時間）
- 證據狀態：B，原作者實驗與結果自述；Grok Bot協調試驗並協助檢查日誌，不代表所有搜尋或取證程式均由它完成。未取得公開原碼、回應封存包或獨立重現。下方提示詞與驗收設計為本庫原創、未測。

## 問題、實作與實際結果

作者以Grok Bot協調公開資料搜尋實驗，並協助檢查日誌。終端模式另設curl_capture，把真實HTTP回應存到作者稱被測模型不能存取的伺服器資料夾；模型印出的文字不當作取證。較早的網頁試驗發現一個真實存在、卻未出現在該次搜尋或工具紀錄的網址；這不是終端封存遭攻破的證明。

作者已把分開保存的回應納入結果接收流程，也保留無法解析JSON等失敗。這支持實作與驗收邊界，不證明來源內容正確、封存不可竄改，或某模型普遍較好。

## 可重用驗收步驟（本庫設計，未執行）

1. 先用虛構網頁與合成工具紀錄，分開建立「模型輸出」「工具呼叫」「來源回應」三份資料；每條事實要能對上同一次執行的來源。
2. 模型自行寫出的網址、引文或執行成功文字，只當待查聲明。即使網址存在，也不能推定本次工具曾取得內容。
3. 將缺少回應、回應與主張不符、版本不明、超時及格式失敗保留為不同結果；不只統計通過項。
4. 若要實作封存，先設計最小權限及可檢查的寫入邊界；另測模型能否偽造或覆寫紀錄。檔案雜湊只說明內容識別，不能單獨證明取得來源與時間。
5. 用獨立人工核對的合成真值驗收判讀器；把工具是否真的取得、來源是否支持主張及主張是否正確分開計分。

## 可貼指令（本庫原創、未測）

請只使用我提供的虛構網頁、模型回答與合成工具紀錄，建立逐項證據驗收表。每項主張列執行編號、工具呼叫、對應回應、支持片段、版本與缺項；分開「模型自行聲稱」「網址存在」「本次工具確實取得」「內容支持主張」。找不到對應回應就標缺證，不能補寫日誌。保留格式失敗、超時及來源矛盾，另提出封存可被覆寫的測試設計，但不要執行。不要連網抓取、登入、下載或安裝軟體、建立伺服器、設定憑證、改權限、寄送訊息或使用任何真實人員名單。

## 權限、費用與限制

- 真實採集及封存需分別取得來源讀取、伺服器寫入及保存權限；公開可瀏覽不等於可任意批量採集、轉載或長期保存。
- 原始HTTP回應可能夾帶個資或憑證，應先限定可存欄位、讀者及保存期限；公開報告用合成資料或去識別摘要。
- 封存位置不可由被測模型改寫是需實測的權限設計，不是加一句提示詞就成立，也不是本庫已驗證的安全保證。
- 代理、模型、搜尋與伺服器可能分別收費。原文的分段費用不是整個專案總成本；當前方案、額度與工具可用性未核，不能宣稱免費。
