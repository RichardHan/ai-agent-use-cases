# UC-351：Grok Bot 額度不夠用？讓它只負責調度，重活交給雲端電腦上的免費／低價模型代理

- 情境：開發
- 標籤：多代理、派工、用量
- 網站標題：Grok Bot 額度燒太快？讓它只負責拆工作和檢查，實際執行交給雲端電腦上的免費模型，搞不定再換便宜的付費模型
- 一句話用途：中文作者分享的省額度做法：在 Grok Bot 的雲端電腦裝 OpenCode 接免費模型、另備 Pi Agent＋DeepSeek 當付費保底；工作先丟免費模型，做不好再降級到 DeepSeek，Grok Bot 自己只做調度、拆解、檢查和總結。作者自述兩套都跑通、Grok Bot 本身用量大幅下降；本庫未重現。
- 核心目標：把「想用 Bot 做很多事」和「每週額度有限」的矛盾，改成分層派工：便宜的執行層做重活，Grok Bot 只花額度在判斷與驗收。
- 工具：Grok Bot（雲端電腦、調度）／OpenCode（作者測 DeepSeek V4.1 Flash Free 等免費模型）／Pi Agent＋DeepSeek（deepseek-v4-flash、複雜任務 deepseek-v4-pro）；來源B另加 webhook 觸發的 routine 與開源腳本 grokbot-local-agent（MIT）
- 分類／標籤：多代理派工／用量分層／外部代理保底
- 目標使用者：已經常碰到 Grok Bot 每週額度上限、又不想升級方案，且能自己管理外部模型帳號與金鑰的進階使用者
- 首次收錄／最近查證：2026-10-19（台灣時間）
- 證據狀態：`author-demo`（作者自述實測）：來源A四則連續貼文＋一張架構示意圖（非實際畫面）；來源B作者貼文＋公開腳本 README（已讀、未安裝）；兩者都沒有用量前後截圖或數字。
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：要交給 Bot 的工作（作者沒有列出具體任務類型）；裝在 Bot 雲端電腦上的 OpenCode 與 Pi Agent；免費模型與 DeepSeek 的使用權限。
- 輸出：Grok Bot 把工作拆好交給外部代理執行 → 檢查結果並總結回報；免費模型做不好時自動改用 Pi Agent＋DeepSeek。作者期望的結果是 Grok Bot 自己的額度消耗明顯下降。

- 取得內容（翻譯改寫）：作者同樣是為了 Grok Bot 額度掉太快，在 Bot 的雲端電腦裝一個代理（他說 Pi、Codex、Claude Code、OpenCode 都可），Bot 只管調度和輕活，寫程式、批次改檔、長文初稿、上網調研交給它。他點出實際會踩的坑：Bot 派完工作就休眠，代理做完也不會通知它，結果好壞 Bot 和使用者都不知道。他的解法是一組小腳本：每件工作有編號、狀態與過程紀錄，可以續聊、可以取消；工作一結束就用 webhook 叫醒 Bot，由 Bot 核查結果再向使用者回報；就算通知丟了，Bot 下次醒來也會補報沒回報過的工作。
- 倉庫：[robbin/grokbot-local-agent](https://github.com/robbin/grokbot-local-agent)，MIT，建立於 2026-10-18 08:23 UTC（台灣時間 16:23），最近推送 2026-10-19 09:03 UTC（台灣時間 17:03）；README 已讀，未安裝。README 寫明：這裡的「本地」指 Bot 自己的 Linux 雲端電腦，不是使用者的 Mac；`pi-task` 把每次呼叫包成有編號的工作，檔案放在 `~/.pi/tasks/<ID>/`，完成時只送出 `{source, id, owner, state, exit_code}` 給 webhook；routine 叫醒 Bot 後讀檔、核對 `result.md`／git diff／測試，再回報並 `ack`；每件工作記下派工 Bot 的 ID，避免多個 Bot 回報彼此的工作；「通知只為了快，磁碟上的狀態才是準」，漏通知不要重跑。模型登入要使用者自己在互動終端完成，README 明說不要叫代理讀或複製 `~/.pi/agent/auth.json`；webhook 網址與金鑰用宿主的安全輸入機制存放。
- 作者報告結果：自述 webhook 已開好幾個、使用順利；另提醒回應 webhook 本身也可能消耗用量。沒有用量前後數字。
- 失敗點／缺口：README 自承這只是 Bot 電腦上的「第二雙手」，不是隔離的工作服務；不要假設雲端電腦有專屬沙盒、無限的程序存活時間或強權限隔離；長期專案可能更適合專用的雲端開發環境。與來源A相同，沒有用量比較。

## 建議操作流程

本庫依來源整理，未實跑：

1. 先量一週：用 [UC-066](066-agent-token-usage-self-audit.md) 的方式看用量花在哪些 Bot／工作，確認真的是「長工作的執行步驟」在吃額度，而不是排程空跑；後者先關掉空跑比換代理有效。
2. 挑一類可自動驗收的工作試（例如有測試可跑的程式小改、格式固定的資料整理），不要一開始就把涉及個資、帳戶或對外發送的工作交給外部模型。
3. 在雲端電腦安裝外部代理後，先用一個安全的小任務確認可以從 Bot 呼叫、能回傳結果；金鑰用環境變數或密鑰機制存放，不貼進聊天。
4. 固定交辦格式：輸入、允許改動的範圍、完成條件、失敗時回報什麼；Grok Bot 依完成條件檢查，不合格才升級到付費模型，並記錄每次升級原因。
5. 跑一到兩週後，用同樣方式再看一次用量與返工次數，決定要不要保留。

## 可複製提示詞

本庫原創設計，非作者原文：

> 這週先試「分層派工」：你只負責拆解、指派、檢查和總結，實際執行交給你電腦上的外部代理。先用免費模型做；只有在結果沒通過完成條件時，才改用我已設定好的付費備援模型，並在回報裡寫明升級原因。只處理我標成「可外包」的工作，不要把含個資、帳戶資訊或客戶資料的內容送給外部模型；不要安裝新工具、不要建立新的付費帳號或儲值。每天結束時給我一張表：工作名稱、執行者（免費／付費備援／你自己）、是否通過檢查、返工次數。

## 所需連接、權限與限制

- 外部代理與模型服務會收到任務內容：送出前要確認哪些資料可以離開你的帳號環境，並看清各服務的資料使用條款；免費模型的條款可能不同於付費版。
- 安裝指令會在雲端電腦執行第三方程式，先確認來源是官方；Bot 電腦上的所有 Bot 共用檔案與登入狀態，外部代理也可能讀到。
- 付費保底會產生另一筆帳單；先設好用量上限。
- 外部代理的成果仍要由 Grok Bot 或你驗收；「額度下降」不等於工作品質不變。
- 是否能把 Grok Bot 用量真正轉嫁出去，取決於調度與檢查本身消耗多少；作者沒有給出比例，本庫不推定節省幅度。

## 驗收與可重現性

- 有試行前後各一週的用量比較，且同期工作量相近。
- 每件外包工作都有「通過／未通過完成條件」紀錄，升級到付費模型的次數與原因可查。
- 沒有任何含個資或帳戶資料的內容被送到外部模型。
- 若採來源B的通知機制：故意讓一次 webhook 失敗，確認 Bot 下次醒來會補報、且不會重跑同一件工作。
- 本庫未重現；只有作者文字自述、示意圖與公開腳本說明。
