# UC-361：多帳戶任務路由先用合成資料驗證歧義停點

- 情境：開發
- 標籤：帳戶隔離、測試、失敗、授權邊界
- 網站標題：有兩個代理帳戶時，先確認工具不會猜錯帳戶再派工作
- 一句話用途：公開問題報告以合成描述檔測出第三方 Grok Bot CLI 的多項歧義拒絕行為，提醒精確帳戶路由不能以預設登入替代。
- 核心目標：將選擇帳戶的意圖和實際使用的連線保持一致，遇到歧義停止。
- 工具：Grok Bot／第三方 ScriptedAlchemy/grok-bot-cli
- 分類／標籤：多帳戶路由／合成驗收
- 首次收錄／最近查證：2026-10-20（台灣時間）
- 證據狀態：author-demo（合成測試自述）＋固定版公開原碼讀核；非真實帳戶事故。設計指令未實跑。
- 是否獨立重現：否

## 來源與作者結果

spencer-shadley 的英文 [Issue #102](https://github.com/ScriptedAlchemy/grok-bot-cli/issues/102)（2026-09-23建立，本輪仍 Open）報告：以合成描述檔測試固定版本，單一項可載入，兩／三項在解密前回 AMBIGUOUS_ENTRIES，空項及未知版本也各自拒絕。作者未用真憑證或呼叫帳戶；桌面兩個登入是否實際產生該檔案格式仍未核。報告要求明確選擇帳戶並保留拒絕歧義，並非移除保護。

本輪讀到[固定版 app-session.js](https://github.com/ScriptedAlchemy/grok-bot-cli/blob/b1c747132799707b0733bbdb9f0179c721c0f0c8/src/core/app-session.js)的多項拒絕分支；只讀原碼，不執行載入器、不讀任何本機憑證。這只能支持所指版本的條件分支，不證明目前版本、真帳戶路由或修復有效。

## 建議驗收設計（本庫設計）

1. 為每件工作記錄不含秘密的目標帳戶標記與接收服務。
2. 先用合成測試表比較單項、多項、空項、未知版本、選擇不存在及中途切換；不要拿真實憑證測試。
3. 預期帳戶不能唯一對上就停止，不改用目前畫面帳戶或其他環境的登入。
4. 對每次請求分別保留預期與實際的非敏感綁定證據；一件失敗不能偷偷切換另一件的帳戶。
5. 功能提案、程式分支存在、合成測試通過、實際任務完成四種狀態分開記錄。

## 可貼指令（本庫原創，未執行）

只審閱下面的合成任務路由規格，不連服務、不執行載入器、不讀電腦登入或環境變數。使用虛構帳戶甲乙，列出單一選項、多選項、沒有選項、指定帳戶不存在、來源衝突與請求期間切換的預期結果。每列註明應繼續或拒絕、需要的非敏感證據及可能的錯誤歸因。所有歧義採停止，不設計繞過安全檢查或取用憑證的方法。

## 權限、費用與限制

第三方 CLI 非官方支援保證，安裝、真實帳戶接入及持續權限須另核。來源沒有本次成本或目前產品方案資料。不得將原始描述檔、token或私人帳戶標記寫進公開研究。合成測試不代表任何真實帳戶遭誤用，也不能聲稱已修復。

## 去重與計數

不同 UC-045 跨代理交接、UC-208 技能搬移與核准以及 UC-276 多人入口分派；本案驗收的是精確帳戶綁定遇到歧義時的拒絕行為。多個測試列只計一個 B 級作者測試流程。
