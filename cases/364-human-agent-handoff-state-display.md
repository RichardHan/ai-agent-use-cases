# UC-364：人工決策接力與外部任務狀態顯示驗收

- 網站標題：現在輪到誰？讓外部看板對得上人工決策與成品
- 一句話用途：以同一任務的可追溯事件核對工作中、等人判斷與可開啟成品，不把動畫當實際進度。
- 情境：開發
- 分類／標籤：人機交接／狀態顯示驗收
- 標籤：人工決策、任務狀態、成果驗收、看板
- 工具：ChatGPT dots／作者自建Mac Dot Face
- 證據狀態：B，原作者真實任務展示及修復自述；非官方功能，未獨立重現
- 查證日期：2026-10-20（Asia/Taipei）

## 問題、作者實作與結果

AI試作室Ryo以文章發布包任務展示自建Dot Face：工作中轉成待人判斷，作者回ChatGPT選標題方案B，同一任務恢復，完成後從看板開啟成果。看板不代替聊天核准，也不顯示模型內部思考。

作者記錄舊啟動狀態阻止下一次顯示，修復後再QA；長時負載、極長輸入及reduced-motion仍未驗。這是作者自述驗收，非本庫測試。[公開原文](https://note.com/ai_shisakushitsu/n/n72380f9ef07a)

## 參考步驟（本庫自行設計，未測）

1. 用合成任務建立固定task_id與事件序號，不連真實助手或讀私人紀錄。
2. 將狀態轉換明定為工作中、待人判斷、成果可驗收；另外保留未知／資料過期，避免硬猜。
3. 待判斷事件必須附具體問題；人工回答在原授權對話完成，看板只顯示事件。
4. 回答後驗證仍是同一task_id；完成要同時有產物登錄及可開啟測試，不能靠動畫停止判定。
5. 重開及第二次啟動時檢查舊狀態殘留；斷線時顯示資料過期。
6. 同一合成事件序列測試各外觀，避免外觀切換改變任務。

## 可貼指令（自行設計，未測）

只以我提供的合成任務事件設計驗收表，不讀系統內部紀錄、不操作我的電腦、不啟用常駐服務。逐項檢查task_id一致、事件順序、人工問題是否顯示、回答後是否回到同一任務、成果連結是否有可開啟證據。缺事件顯示未知，斷線顯示資料過期；動畫與預估進度不可當完成證據。加入舊啟動狀態殘留、重複回答及缺產物三種反例。交付離線測試資料和驗收清單，不自動發布。
