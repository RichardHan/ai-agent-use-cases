# UC-366：把開源專案的顯示卡燈效協定移植成另一家控制軟體的外掛，先唯讀探測再寫入

- 情境：開發
- 標籤：硬體、外掛、移植、唯讀測試
- 網站標題：顯示卡燈光只能用原廠軟體控制？請 Bot 把開源協定移植成主機板軟體的外掛
- 一句話用途：作者自述讓 Grok Bot 參考 OpenRGB 對自己那張顯示卡的燈效實作，做成 ASUS Armoury Crate 能載入的外掛，在一個軟體裡統一控制燈光；Bot 先附唯讀測試工具與安全閘門，再交給本人上機。
- 核心目標：在不改原廠韌體、不先寫入硬體的前提下，把「已知的開源協定」轉成「另一套軟體認得的外掛介面」，並把模擬測試、唯讀探測、單次寫入、正式載入分成不同驗收關卡。
- 工具：Grok Bot／OpenRGB（協定來源）／ASUS Armoury Crate（Aura LightingService 外掛介面）／NVIDIA NVAPI I2C／mingw-w64 交叉編譯
- 分類／標籤：開發／硬體整合／外掛移植／唯讀探測
- 目標使用者：想把不同廠牌周邊整合到同一套控制軟體、又能自己判斷風險的進階玩家
- 首次收錄／最近查證：2026-10-20／2026-10-20（台灣時間）
- 證據狀態：`author-demo`（作者自述實測：X 貼文＋Bot 回報截圖＋公開 GitHub 原碼與 README 已讀）；本庫提示詞為 `designed`
- 是否獨立重現：否。本庫沒有下載、編譯或安裝外掛，也沒有接觸任何硬體。

## 輸入與預期輸出

- 輸入：作者自己的顯示卡型號（PNY RTX 5070 Ti ARGB Epic-X）、OpenRGB 對該卡的燈效協定實作（GPL 開源）、Armoury Crate／Aura 外掛範例與規格。
- 預期輸出：64 位元與 32 位元兩版外掛 DLL、只讀燈控晶片的獨立測試工具、模擬呼叫外掛的測試程式、安裝／移除／診斷腳本、自簽章備案腳本、README 逐步操作順序與日誌位置。

## 建議操作流程

以下為本庫設計，未實測；不是作者原文步驟。

1. 先確認開源協定的授權（本例 GPL），決定成品能否公開、要不要附原碼與聲明。
2. 要求 Bot 先寫「規格對照表」：開源實作的暫存器／指令 ↔ 目標軟體的效果代號，標出無法對應的效果。
3. 交付物必須含：硬體 ID 比對閘門（不符就零動作）、唯讀探測工具、dry-run、單次寫入確認、移除腳本、日誌位置。
4. 在開發環境用假的硬體介面跑過呼叫流程，Bot 回報要分清「模擬通過」與「實機未測」。
5. 本人上機只依序做：唯讀探測 → 單次寫入 → 載入外掛；任一步異常就停，回傳日誌而不是換參數硬試。
6. 自簽章、關閉安全設定、改登錄等步驟另外由本人判斷，不交給 Bot 決定。

## 所需連接、權限與限制

- 實機操作全由本人在自己的電腦執行；寫入硬體、未簽章 DLL 載入、自簽章憑證都有風險，可能影響保固或系統穩定。
- 授權：協定細節來自 GPL 專案，散布需遵守 GPL；本庫不轉載二進位。
- 非官方：與顯示卡、主機板或 GPU 廠商無關；廠商軟體更新可能讓外掛失效。
