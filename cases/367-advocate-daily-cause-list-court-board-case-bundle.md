# UC-367：律師每天的庭期準備：晨報、晚間查庭期表、白天盯法庭叫號板、自動整理案卷

- 情境：工作
- 標籤：每日、法律、庭期、案卷
- 網站標題：執業律師把每天的庭期追蹤與開庭資料夾交給 Bot，判斷與簽名仍自己來
- 一句話用途：印度清奈高等法院一位執業三十多年的律師自述，Grok Bot 每天早上送當日行程與最高法院新判決摘要、晚上查隔天庭期表、白天盯法庭叫號看板快輪到時提醒，並替每件案子整理含裁定、索引與判決要旨的開庭資料夾。
- 核心目標：把「每天查庭期、盯叫號、為每件案子備齊文件」這類文書負擔交給 Bot，本人只做法律判斷、簽名與下單。
- 工具：Grok Bot（routine 排程、雲端電腦瀏覽公開法院網站）／印度 eCourts 服務入口／法院庭期表與叫號看板（公開頁面）
- 分類／標籤：工作／法律實務／庭期追蹤／文件準備
- 目標使用者：每天要跑多個法庭、管理大量案件期日的律師或法務助理
- 首次收錄／最近查證：2026-10-20／2026-10-20（台灣時間）
- 證據狀態：`author-demo`（作者自述實測，X 單則四段文字，無截圖）＋eCourts 官方入口已讀（`official`，只證明入口存在）；本庫提示詞為 `designed`
- 是否獨立重現：否。

## 輸入與預期輸出

- 輸入：律師自己的案件清單（案號與法院）、公開的庭期表（cause list）、法院叫號看板、eCourts 上的歷次裁定、本人的郵件與帳單提醒。
- 預期輸出：
  - 每天早上：當日行程摘要＋最高法院最新判決摘要。
  - 每天晚上：核對庭期表，列出隔天有排的案子。
  - 白天：看板上自己的案子快輪到時提醒。
  - 每件案子：追蹤列案紀錄與下次期日，產出「開庭資料夾」——從 eCourts 下載的裁定、有索引的打字版卷宗、附判決要旨的引用判例、一頁工作筆記。

## 建議操作流程

以下為本庫設計，未實測；不是作者原文步驟。

1. 先建一張案件主表：案號、法院、承辦人、下次期日、資料夾位置。Bot 只讀這張表與公開法院頁面。
2. 晚間 routine：讀隔天庭期表，與主表比對，輸出「有排／沒排／表上出現但主表沒有」三欄；第三欄一律請本人確認。
3. 白天看板提醒：設定「前面剩幾號時提醒」，並寫明看板讀不到時要直接說「無法讀取」，不要用舊資料推估。
4. 開庭資料夾：裁定、索引、判例要旨、工作筆記分檔；每份文件標出處與下載時間，判例要旨標「Bot 摘要，未核」。
5. 遇到驗證碼、登入或付費資料庫時停下，由本人處理；不要求 Bot 繞過。
6. 每週抽一件案子人工比對資料夾與原始紀錄，記錄漏件或錯件。

```text
每天晚上 8 點：讀 [法院] 公開的隔天庭期表，與我的案件主表（附件）比對。

規則：只讀公開頁面，不登入、不填驗證碼；頁面讀不到就寫「無法讀取」，不要用前一天的資料代替。

```

## 所需連接、權限與限制

- 讀取範圍：公開庭期表、叫號看板、公開裁定；本人的郵件與帳單屬私人資料，是否接入由本人決定。
- 當事人資料與案卷屬保密資訊：放進雲端代理前要確認執業倫理規範、委任人同意與資料保存位置；公開案例庫不放任何案件細節。
- 驗證碼、登入與付費判例資料庫：不得繞過；由本人操作或使用合法授權。
- 法律判斷、引用判例是否適用、書狀簽名與遞狀全由律師負責；Bot 摘要可能出錯。
- 作者提到的股票交易紀律屬另一流程，本案不收錄、不建議交由 Bot 下單。

- 只有作者自述：使用兩個月、每天執行；沒有提醒時間紀錄、漏報或案卷錯誤率。
