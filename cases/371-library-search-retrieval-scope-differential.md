# UC-371：Library 搜尋可見與檔案內容授權的分層排障

- 網站標題：搜得到檔名，卻讀不到檔案？用兩個測試檔和頁面對照定位
- 一句話用途：將檔案搜尋、內容取回與對話選取範圍分開驗收，保留拒絕證據，不把中繼資料可見當成讀檔成功。
- 情境：工作
- 分類／標籤：知識檔案排障／授權範圍驗收
- 標籤：Library、權限、對照測試、失敗紀錄
- 工具：ChatGPT dots／ChatGPT Library／Space 頁面
- 證據狀態：B，作者雙測試檔與跨入口對照失敗自述；未獨立重現、未確認修復
- 查證日期：2026-10-20（Asia/Taipei）

## 作者實作與具體結果

OpenAI Community 作者 lingzhic046 在個人 Pro 帳戶測試兩個由 ChatGPT 產生的小檔案。Library 搜尋能列出檔名等中繼資料，取回內容卻在動作執行前收到 HTTP 403／scope_violation。另以 Space 測試頁對照，正文可以讀取。這證明的是作者當次「搜尋成功、檔案內容取回失敗」，不是所有儲存內容都無法讀取。

作者再比較 macOS 與桌面網頁入口，未找到客服所說的 Add from Library 選項；下載後重新上傳的建議尚未驗證。錯誤文字提到本輪選取的 Library 資料夾範圍，不能只憑文字判定根因或宣稱改設定就會修復。[原始回報](https://community.openai.com/t/dot-library-search-finds-files-but-retrieval-returns-scope-violation-no-add-from-library-option/1407635)

## 操作步驟（從回報抽象化，非已驗證修復）

1. 使用兩個無敏感內容、已授權的小測試檔，逐一記錄搜尋是否命中。
2. 另記內容取回是否真的成功。只見檔名、大小或識別碼，不算正文可讀。
3. 用一個已授權且可讀的測試頁作對照；頁面可讀不能推定附件也可讀。
4. 記錄入口、錯誤時間與原樣錯誤文字；公開回報前移除私人檔案識別碼及內容。
5. 遇到範圍拒絕就停止該取回，不試探其他資料夾、不擴權。缺少介面選項與修復未驗證分開回報。

## 可貼指令（本庫自行設計，未測）

只讀我明確選取的兩個無敏感測試檔與一個測試頁。分別列出搜尋是否命中、正文是否取得、失敗發生在哪一步、錯誤原文與查閱時間。只看到中繼資料不可標成功；頁面可讀不可推定檔案可讀。若出現範圍或權限拒絕，立即停止，不更改權限、不建立新授權、不改用猜測的檔案網址。提供去識別化的差異清單與仍缺證據，不宣稱修好。
