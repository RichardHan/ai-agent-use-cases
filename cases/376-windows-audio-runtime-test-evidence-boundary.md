# UC-376：Linux測試通過，不代表Windows音訊程式沒有爆音

- 情境：開發
- 標籤：音訊、跨平台、測試、失敗紀錄
- 網站標題：把模擬測試與Windows真實音訊驗收分開
- 一句話用途：避免代理把雲端測試成功誤報成目標平台問題已修復。
- 核心目標：讓每項測試結果綁定實際執行環境與程式版本。
- 目標使用者：開發Windows音訊工具、但讓dots委派雲端程式任務的人。
- 首次收錄／最近查證：2026-10-20（Asia/Taipei）
- 證據狀態：author-demo（具體失敗實作，B級）；不是成功修復教學。
- 是否獨立重現：否。

## 輸入與預期輸出

輸入為有權使用的程式版本、合成測試紀錄與目標平台測試回報。輸出是「已測／未測」矩陣及最小重現交接，不是宣稱全部測試通過。

## 來源版本

Aframe93於OpenAI Community英文回報，頁面日期2026-10-11 18:09，未標時區，不擅轉台灣發文時間。[原文](https://community.openai.com/t/give-dots-a-windows-testing-environment-with-virtual-audio/1405390)。實讀公開全文：作者以dot委派Codex開發Windows音訊程式；Linux能檢查程式並跑合成測試，但Windows小緩衝有機械音、大緩衝仍爆音。作者稱Wine因IPC限制未能啟動，仍須反覆手動安裝測試。未提供音檔、版本、量測或修復證據。這是具體受阻結果，不把文中要求的虛擬音訊環境當已實現功能。

官方[電腦與應用程式說明](https://learn.chatgpt.com/docs/dots/computers-and-apps)只支持區分雲端、已連接電腦及其各自環境；不保證Windows音訊堆疊、Wine或虛擬loopback支援，也沒有證實此作者根因。

## 建議操作流程

以下是本庫設計的驗收方法，未實測，非作者已完成步驟。

1. 固定build／commit，先列可用執行環境；不要因檔名是.exe就假設雲端能跑。
2. 把靜態檢查、合成測試、目標平台執行、實體裝置四欄分開。每欄附實際指令、環境、結果與產物；未執行寫未測。
3. 在已授權且具備相容環境時，才用固定測試訊號對照緩衝大小、採樣率與裝置設定。沒有此環境就準備交給人工執行的測試包，不擴權繞過IPC限制。
4. 同一版本比較修復前後輸出；合成測試綠燈不能關閉只有Windows能重現的缺陷。
5. 只有取得目標環境證據後才更新該欄；虛擬音訊結果也不代替所有硬體／驅動驗證。

## 所需連接、權限與限制

只讀程式及既有測試資料即可開始。平台測試需要另有相容且獲准的環境；此案例不授權操作任何人的電腦。帳戶可用性、額度與相容性依實際服務而定，本文未取得專用Windows雲端方案或費用，不假設免費。測試音檔應為合成或已授權素材，不公開私人語音。

## 驗收與可重現性

可驗收成果是每個結論能追到版本、環境、測試輸入與紀錄；不能以「已修改程式」或「Linux測試通過」代替Windows音訊結果。本庫沒有執行任何程式、安裝Wine或測試音訊。
