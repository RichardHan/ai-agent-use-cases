# UC-377：用行曆客戶代碼整理FreshBooks工時（待驗證）

- 情境：工作
- 標籤：工時、行事曆、對帳、待驗證
- 網站標題：開票前把行曆工時依客戶代碼整理好
- 一句話用途：把事後記錄的工作時數轉成可覆核的計費工時候選。
- 核心目標：以客戶代碼配對，不靠客戶名稱猜測歸屬。
- 目標使用者：按工時計費的個人工作者。
- 首次收錄／最近查證：2026-10-20（Asia/Taipei）
- 證據狀態：unverified（作者單則詳細自述，未見產物）；不納入1000。
- 是否獨立重現：否。

## 輸入與預期輸出

輸入是含客戶代碼、實際花費時間的行曆紀錄及指定承包商發票；輸出是待覆核工時清單，而非自動寄出帳單或收付款。

## 來源版本

Reddit英文作者DarkPaul在[原串](https://www.reddit.com/r/GrokBot/comments/1wvhcmh/has_anyone_actually_made_money_from_a_grok_bot/)的留言表示：把客戶代碼放在事件開頭並記實際時間，開票前一天由Grok Bot整理進FreshBooks工時，另從收件匣加入承包商發票。公開閱讀版只顯示相對日期，留言絕對日期未核；沒有帳務畫面、程式或核對結果，因此保留候選而不計合格。未讀私人帳簿。

[FreshBooks官方Time Entries](https://www.freshbooks.com/api/time_entries)確認工時欄位包含client_id、duration（秒）、started_at及billed，且讀寫要相應授權；這不證實Grok Bot有原生FreshBooks連接器，也不證實作者用API而非瀏覽器。

## 建議操作流程

本庫自設、未測：先唯讀匯出指定帳期事件，以事件穩定ID去重；用已確認對照表將代碼轉客戶ID。實際工時缺漏、時區不明或代碼不唯一就列例外。與已入帳工時比對後，只交新增候選讓本人確認；不建立正式帳單，不寄送、不付款。

## 可複製提示詞

原創設計、未測：「請唯讀整理〈帳期〉行曆的計費工時候選，依〈已確認客戶代碼表〉配對。輸出來源事件ID、客戶ID、實際時長及時區；缺值不猜，與現有工時對帳避免重複。不得寫入帳務、寄帳單或處理付款，先交差異清單給我。」

## 所需連接、權限與限制

需已授權的日曆與帳務只讀資料；若未連接，以本人匯出且去敏的檔案準備也可。寫入需要另外批准及實際支援的連接方式；不為此自行建立OAuth或交出憑證。FreshBooks與代理費用未核，不提供固定成本。只記錄本人有權處理的資料，禁止公開帳單或客戶資料。

## 驗收與可重現性

需取得匿名樣本的來源ID→客戶ID→工時ID對照、總時數一致及重跑無重複，才有進一步驗證基礎。作者未提供此證據；「記工時」也不等於開票、寄出或收到款。

## 去重與版本紀錄

與一般收據彙整不同，焦點是計費工時來源及客戶代碼映射。只保留一個待定流程，不把承包商發票另拆。2026-10-20首次收錄，合格數不增加。
