# UC-385：一人經營謎題書副業：Bot 寫題目產生器、用另一個解題器證明每題只有一個答案，再交出手機就能照做的上架清單

- 情境：創作
- 標籤：出版、謎題書、驗收、核准
- 網站標題：想用 AI 量產謎題書又怕有題目解不開？讓 Bot 用獨立解題器逐題驗證，上架與定價仍由你按
- 一句話用途：英文作者 Blake La Pierre 自述，一個專責「書」的 Grok Bot 從 9 月 30 日起和他做出 15 本 Amazon KDP 謎題書、6 本已上架：Bot 寫題目產生器、用獨立的 SAT 解題器證明每題唯一解與難度、程式畫插圖、排內頁與封面、寫商品頁與版稅試算，最後交一份手機可照做的上架清單；登入 KDP、看樣書、按發布由本人做。作者公開整個書籍倉庫與驗證報告，並直說 6 本上架、0 筆訂單。本庫未重現。
- 核心目標：AI 產出的謎題要「證明能解、而且只有一解」才算成品；把人工必做的上架步驟壓成手機上複製貼上就能完成的清單。
- 工具：Grok Bot（作者稱每個 Bot 有自己的記憶與指示，共用同一台 Linux 雲端電腦）／Git 倉庫／Python（ReportLab、python-sat、numpy、Pillow、python-docx）／Amazon KDP（本人操作）
- 分類／標籤：創作／出版副業／謎題書驗證與上架交接
- 目標使用者：想用代理做低內容／中內容出版品（謎題書、練習本），但擔心品質與上架流程的人
- 首次收錄／最近查證：2026-10-20 17:40（台灣時間）批次
- 證據狀態：`author-demo`（作者自述實測）：Substack 兩篇第一人稱長文＋公開 GitHub 倉庫（各書資料夾、驗證報告、上架清單、版稅算式，本輪以 GitHub 公開 API 讀取）。銷售數字為作者自報。本庫流程與提示詞為 `designed`。
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：系列設定（作者的「Frostwood」冬季小屋系列：溫馨、不暴力、冬天但不是聖誕節、每本換一種題型）、題型、版型規格（6×9 吋、鏡像邊界）、作者的固定偏好（不寫謀殺、預設售價 9.99 美元）、點子紀錄檔。
- 作者描述的輸出：每本書一個可獨立重建的資料夾，內含題目產生器、驗證程式、插圖程式、內頁 PDF、依頁數算書背寬度的全包封面、`listing.md`（書名、副標、描述、關鍵字、分類、版稅算式）與給手機看的 KDP 上架清單；每本附一份由程式產生的驗證報告。

## 建議操作流程

本庫設計，未實跑（參考作者「Steal this」的方向）：

1. 先定系列規則：語氣、禁忌、季節、每本換題型、預設售價；寫進 Bot 的指示與點子紀錄檔。
2. 每本書一個資料夾，所有路徑相對化，任何一本都能單獨重建。
3. 題目「一種方法產生、另一種方法驗證」：用獨立解題器檢查唯一解與存檔答案；難度以所需技巧層級定義並逐題驗證。
4. 驗證報告由程式產生並隨書保存；任何一題不通過就不進排版。
5. 商品頁檔案內附版稅算式，先算清每本實收再決定頁數與售價。
6. 上架、帳號、付費廣告由本人操作；Bot 只交手機可照做的清單與已核對的檔案。
7. 送審被退時，把退件原因寫回版型規則，再重建所有受影響的書。

## 所需連接、權限與限制

- 只需要雲端電腦上的程式環境與 Git 倉庫；出版平台帳號、稅務與付款資料由本人保管與操作，不交給 Bot。
- 程序化插圖與開源字型可避開生圖授權問題，但字型授權仍需逐一確認；若改用生圖模型，另查平台對 AI 內容的揭露規定。
- 作者顯示 Amazon 作者欄會出現 Bot 名稱的情況；是否要掛名、如何移除，依平台規則由本人決定。
- 做得出來不等於賣得出去：作者自報 0 訂單，本案不證明任何收入。

## 驗收與可重現性

- 隨機抽 10 題，用另一個解題器（或人工）解一次，答案與答案頁一致且無第二解。
- 驗證報告的題數、日期與內頁題數一致；任一題不通過時建置會停下。
- 封面書背寬度依實際頁數重算；平台預覽工具無邊界警告。
- 上架清單的每個欄位能直接複製；價格頁的印刷成本與版稅與 `listing.md` 算式一致。
- 本庫未重現、未查核銷售；作者的書數為兩個不同日期的自報快照。
