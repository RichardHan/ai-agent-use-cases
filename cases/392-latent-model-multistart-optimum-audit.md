# UC-392：統計模型顯示收斂，仍要用同模型對照與多起點找較差解

- 網站標題：統計程式顯示正常，為什麼換個起點會得到更好的解？
- 一句話用途：作者讓Grok Bot交叉比較兩套統計實作，再固定資料多次擬合，找出健康指標正常卻停在較差解的情況；不是統計結論認證。
- 情境：學習
- 標籤：統計、數值驗收、多起點、失敗
- 工具：Grok Bot／gllvmTMB／GLLVModels.jl；後續修復另標Claude Code
- 證據狀態：B級作者實作自述＋公開結果表、生成碼與後續修訂紀錄；未獨立重算或重現。
- 首次收錄／最近查證：2026-10-20／2026-10-20（台灣時間）
- 是否獨立重現：否

## 問題、輸入與交付

研究者拿到「正常收斂」的擬合物件，不代表已找到同一目標函數的最佳解。本案的交付是可回查版本與模型條件的異常清單，而不是由代理直接宣告研究結論正確。

輸入為固定版本、同一資料、等價模型規格與多個起始點。預期輸出需把目標函數值、收斂碼、Hessian、梯度及重跑條件並列，另列不可比與尚未改善的項目。

## 作者實作與結果

itchyshin在2026-09-27的公開問題單明標Grok Bot執行測試。作者將同一批資料交給R與Julia的原生實作，先對齊模型及參數數量，再比較似然值。部分R擬合雖回報收斂、Hessian正常及小梯度，結果仍較差。挑出的8例改用10起點後，部分改善，另3例仍有差距，不能宣稱多起點全數解決。

同批另一問題單保留零膨脹模型的失敗；作者後續公開資料生成碼及seed規則，並以公開spider資料重跑，檢查較大模型的擬合不應差於其包含的簡單模型。這是同一數值可靠性驗收流程，不按分布、資料集或問題單拆數。

後續PR1478明標Claude Code修訂。作者回報新增確定性起點後，部分Poisson測試改善，但NB2仍有未解案例，預設多一次最佳化亦增加耗時。不能把後續代理的修復歸功原Grok測試，或把修訂環境當成原環境的獨立重現。

## 可參考步驟（本庫設計，未執行）

1. 先限定小型、已授權且無敏感資料的統計問題，記錄資料版本、套件版本、seed和運算預算。
2. 在比較數值前，檢查兩邊的模型、參數化、常數項及目標函數是否可比；不一致就停止排名。
3. 將正常退出、局部收斂、數值健康檢查、較優目標值分開記錄。任何單一綠燈都不能替代其他檢查。
4. 固定資料，只改事先指定的起始點策略；比較有改善、沒改善、轉為不健康及未執行的結果。
5. 若使用包含關係或已知界線作檢查，先由適任研究者確認前提，不憑代理一句話套用。
6. 保留原結果與修訂後結果，交付可重查差異、剩餘疑點及最小補測方案，不回寫歷史通過。
