# UC-393：把外部 pitch deck 補成 PDF，讓會前材料與會後筆記留在同一投資案

- 情境：工作
- 標籤：投資研究、提案收件、附件補全、會議脈絡、人工覆核
- 網站標題：補齊提案材料，保留同一案的會前會後脈絡
- 一句話用途：將外部簡報連結補成可查閱材料，再把會後筆記對回同一提案，避免附件、會議與決策背景分散。
- 工具：Meta Muse／Signed／Granola／作者開源工具 deckk
- 首次收錄／最近查證：2026-10-20／2026-10-20（台灣時間）
- 是否獨立重現：否
- 證據狀態：B級作者實作自述。作者具體實作自述與公開程式碼已讀，私人提案、回寫紀錄及完整輸出未公開，未獨立重現。下方建議驗收與提示詞為本庫自行設計。

## 問題與作者結果

Zach Holman 自述一則 LinkedIn 貼文讓他一週收到約 250 個新創提案。Signed 集中收件，Muse 把缺少 PDF 的外部 deck 連結補匯入；Zoom 後再將 Granola 筆記寫回同一 pitch，供日後搜索與理解討論背景。作者說數個案子仍在盡職調查，沒有聲稱已完成投資。

250 是收件規模，不代表 Muse 成功處理 250 份；沒有公開節省時間、附件成功率或投資報酬。作者是 Signed 創辦者，存在商業利益。原文另含依政治立場篩選創辦人的做法，本案不採用，也不提供敏感人身特質篩選指令。

## 作者流程與公開實作證據

1. Signed 收取提案及基本資料，由其自身分析流程整理欄位。不能把 Signed 的全部能力歸功於 Muse。
2. 作者指出 Muse 會用 deckk 嘗試將只有連結的簡報補成 PDF，交回提案資料。
3. 作者明確描述 Muse 會將會後 Granola 筆記回寫到同一 pitch。投資選擇仍由作者自己處理。

上述作者流程採精簡轉述；更細的技術能力另來自下列固定程式快照，而非推定每項都已在 250 件提案中成功執行。

- deckk 按 URL 選擇 adapter；現成 PDF 直接保存，公開 Slides 可輸出 PDF，部分簡報播放器採逐頁擷取。
- Google Drive adapter 檢查檔案是否以 `%PDF` 開始；非 PDF 再嘗試 Slides，仍失敗則回報格式或分享權限問題，不把網頁假裝成 PDF。
- README 載明部分路徑需要 Chrome／Chromium，預設總 timeout 為五分鐘；密碼、驗證碼或受限連結並非普遍支援。
- DocSend 空間連結判別有公開單元測試檔。本輪只讀檔案，沒有執行測試，不能宣稱測試通過。

## 權限、費用、限制與驗收

- 作者沒有公開本流程 Muse、Signed、Granola 的費用或 token 用量；deckk 原碼採 MIT 授權。免費開源不代表代理執行、其他服務與帳號資格免費。
- 真正實作可能需要獲准的 deck 存取、必要檔案讀寫、Signed 指定 pitch 讀寫及 Granola 指定會議筆記讀取。先以有限樣本與唯讀匯出確認，不要求整個郵箱或完整投資組合。
- 安裝第三方程式、新增持續 MCP 存取、上傳非公開 deck、外部寫入應分別確認。這次研究沒有安裝、登入、啟用付費服務或執行案例。
- 原碼有自動處理電子郵件門檻的能力，預設可能讀取 `git config user.email`；Drive 下載路徑亦含略過檔案掃描提示的參數。因此不能直接把工具原樣當安全執行範本，本庫指令明確停在這些邊界。
- 建議驗收：三案都有穩定案號與原始來源；人工抽查 PDF 頁數；缺檔明示而不補造；會後筆記不串案；引用及未知資訊分明；若日後獲准寫入，核對目標案號、附件數與完成狀態。
- 投資、轉帳、依敏感特質做高影響決策不在本案可自動化範圍。這是材料與脈絡整理，不是投資建議或績效保證。

## 去重與界線

本案只計「同一 pitch 的外部材料補全與會前會後上下文閉環」。不拆成 deck 下載、會議摘要、Vestaboard 顯示或事後引介等多個案例。已對照UC-004社群互動轉CRM、UC-017外聯開發，以及UC-349詢問信登錄與會議邀約。本案不是多一個CRM工具，而是將外部材料補全、會後筆記與同一提案身份連回，供後續查閱；不另外計會議摘要或檔案下載。沒有把公開程式存在當成所有私人提案成功處理的證據。
