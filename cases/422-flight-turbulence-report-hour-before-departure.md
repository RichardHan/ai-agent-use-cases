# UC-422：每班飛機起飛前一小時，Bot依航線整理亂流預報表與地圖；飛行中也能隨時再問一次

- 情境：生活
- 標籤：旅遊、航班、天氣、行事曆
- 網站標題：怕搭飛機遇到亂流？讓Bot在每班起飛前一小時，依你的航線整理哪一段可能顛簸，附表格與路線地圖
- 一句話用途：英文作者 Dan Burkland（@DBurkland）在飛冰島前用 Grok Bot 做了「航班亂流報告」Bot：讀行事曆上的航班，起飛前一小時抓航線、SIGMET／AIRMET（航空氣象警報）、PIREP（飛行員回報）與 Turbli 亂流預報，寄來分段表格加路線地圖；飛行中也能臨時要一份。作者自述＋當次飛行中報告截圖，本庫未重現；報告只是參考，不能取代航空公司與機組資訊。
- 核心目標：把分散在多個航空氣象來源的資訊，整理成「這班飛機哪一段、幾點、什麼高度可能顛簸、根據哪個來源」的一頁報告，並明列資料缺口。
- 分類／標籤：旅遊準備／天氣資料彙整／行事曆觸發
- 目標使用者：常搭飛機、怕亂流或想事先知道哪段要繫好安全帶的旅客；不適用於飛航決策
- 工具：Grok Bot（作者自建 Bot，另以 skill「flight-turbulence-report」產出報告）／行事曆（航班事件）／公開航空氣象資料（SIGMET、AIRMET、PIREP、METAR／TAF、WAFS SIGWX）／Turbli／航班追蹤（截圖標 FR24）
- 首次收錄／最近查證：2026-10-22 14:40（台灣時間）
- 證據狀態：`author-demo`（作者 X 貼文＋飛行中真實報告截圖＋公開 Bot 模板頁說明）；本頁流程與提示詞為 `designed`
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：行事曆上的航班事件（航班號、起訖機場、出發時間）；飛行中則用即時位置。
- 輸出：一份報告，含整體判斷、目前位置（座標、高度、速度、剩餘距離與預計落地時間）、分段表（段落、當地時間、高度、預期狀況、資料來源）、「缺口」說明（例如沒有申報航路點只能假設直線、航線附近沒有飛行員回報），以及標出警報區與分段顏色的路線地圖。

## 建議操作流程（本庫設計，未實跑）

1. 在行事曆航班事件裡固定寫航班號與起訖機場代碼，讓 Bot 讀得到。
2. 設定排程：每個航班事件開始前 60 分鐘產出報告；另允許飛行中用一句話臨時要求。
3. 報告固定欄位：整體判斷、分段表（時間、高度、預期、來源）、缺口、地圖；每個判斷都要能指到來源與資料時間。
4. 拿不到某個資料源時，寫「未取得」與原因，不要用舊資料或猜測補上。
5. 落地後可回頭記一句實際感受，累積幾次後看預報準不準。

## 可複製提示詞（本庫原創設計，未實跑）

> 每當我的行事曆有航班（事件標題含航班號與機場代碼），在起飛前60分鐘給我一份亂流參考報告：先一句整體判斷，再用表格分段列出時間（出發地與目的地時間）、高度、預期顛簸程度與根據（SIGMET、AIRMET、PIREP、目的地 METAR／TAF、公開亂流預報），每個資料都寫取得時間。最後列「缺口」：哪些資料拿不到、哪些是假設（例如航線用直線估）。附一張標出警報區與分段的路線圖。這只是乘客參考，不要給任何飛航操作建議；資料過期或拿不到就直說，不要補猜。我在飛行中問「現在呢」時，用最新位置再做一次。

## 所需連接、權限與限制

- 需讀取行事曆航班事件；不需要訂位帳號或護照資料，別把訂位代號、會員號放進提示。
- 航空氣象資料多為公開來源，但各來源的使用條款、更新頻率不同；Turbli 等第三方預報的條款請自行確認。
- 機上 Wi-Fi 不穩或未購買時，飛行中臨時報告可能收不到。
- 本案是乘客的資訊整理，**不是**飛航簽派或安全決策；遇到機組廣播或安全帶燈號一律以機上指示為準。

## 驗收與可重現性

- 頭幾趟對照：報告中的警報區與官方網站同時段資料是否一致；資料時間是否標示。
- 測一次「資料源讀不到」：報告應寫缺口，而不是給出看似完整的判斷。
- 落地後記錄實際顛簸段落，對照報告分段。
- 本庫未重現；只有作者一次飛行中截圖。
