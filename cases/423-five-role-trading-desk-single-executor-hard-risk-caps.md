# UC-423：五個角色的AI交易小組：研究、題材、訊號、風控各寫一個檔案，只有一個Bot能下單，每晚各自領回自己的教訓

- 情境：工作
- 標籤：多代理、交易、風控、排程
- 網站標題：讓好幾個Bot一起看盤，怎麼避免它們互相打架、亂下單？分角色各寫一個檔案，只准一個Bot碰錢，風控上限先寫死
- 一句話用途：英文作者 @Anniliese_ETH 自述用 Grok Bot 組了五個角色的交易小組：研究（鏈上大戶、未平倉量、資金費率）、題材（X 熱點）、訊號（提出進出場與風險檢討）、風控（硬性上限）、執行（唯一能下單、改單、撤單）；角色之間只透過共用資料夾裡的三個檔案交接，每天三輪，每晚自我檢討後只把各自的教訓發給各角色。作者自述＋影片（本庫未看），未重現；本頁不構成任何投資建議。
- 核心目標：把「一個聊天視窗什麼都做」改成分工、單一下單口、事前寫死的風控上限與書面紀錄，讓錯誤只犯一次。
- 分類／標籤：多Bot分工／交接靠檔案／高風險動作單一出口
- 目標使用者：已在用小額帳戶做程式化交易、想讓多個代理協作但必須控管下單權限的人；不建議新手或用生活必需資金嘗試
- 工具：Grok Bot（多個 Bot＋共用雲端電腦檔案系統、瀏覽器、routine）／Hyperliquid API 錢包（作者說只能下單撤單、不能提領）／X API
- 首次收錄／最近查證：2026-10-22 14:40（台灣時間）
- 證據狀態：`author-demo`（作者 X 長文全文＋工作中影片貼文；影片未播放；無成交紀錄或帳戶截圖）；本頁流程與提示詞為 `designed`
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：鏈上與市場數據（大戶錢包、未平倉量、資金費率、ETF 流量）、X 上的熱門話題、K 線與 ATR；風控規則。
- 輸出：三個共用檔案——`signals.md`（訊號角色的設定與風險檢討）、`whales.md`（研究角色的已查證大戶動向、未平倉量與費率變化，每條附來源）、`live_log.md`（執行角色的每筆委託、成交、停損與教訓，並標註該筆來自訊號角色還是執行角色自己的判斷）；每輪「交易或跳過」的決定；每晚分角色的檢討。

- 作者報告（翻譯改寫、只摘要結構）：
  1. **雇角色而不是寫提示**：每個代理一個工作、一個輸出檔、一個排程；「沒寫進檔案就等於沒發生」。
  2. **名冊**：研究只做鏈上資料、每行要有來源、不下看法；題材角色看時間線在吵什麼；訊號角色提出設定與風險檢討但碰不到帳戶；風控不是有意見的代理而是所有角色（含執行）都要遵守的硬上限；執行是 Grok Bot 本身，唯一能下、改、撤單。
  3. **只有一個代理能動錢**：避免兩個代理同時開同一部位或互相平倉；執行用的 API 錢包只能下單撤單、不能提領。
  4. **硬性風控**（作者列的上限，原文為作者個人設定）：每筆風險不超過帳戶1%、最高5倍隔離槓桿、進場同時掛停損、強平價至少在停損外3倍距離、最多2個持倉、每天最多4筆、不攤平、夜間（作者時區 23:30–08:00）不新開倉、單日虧5%停手、從高點回撤20%全部暫停並通知本人；刻意不設每週獲利目標。
  5. **交接時序**：每輪前約20分鐘研究更新 `whales.md`、題材角色標出市場在反應的新聞、訊號角色更新 `signals.md`，執行角色再讀全部、跑風控檢查、看即時價格，決定交易或跳過。
  6. **每個角色只拿需要的工具**；題材角色經 X API 與雲端電腦上保持登入的瀏覽器讀 X。
  7. **排程**：每天三輪交易（作者時區 9、15、21 點）、早中晚的 X 發文包、日間熱點掃描、每晚自我檢討——Grok Bot 看當天成敗，只把各角色自己的教訓分別發給它們。
  8. **已經付出的教訓**：第一筆模擬交易方向對、但停損只距進場0.38%，被一根影線掃掉後價格才往預期方向走；修正成規則：停損放在波段低點再減1倍15分鐘ATR、且須距進場0.8%–2%，部位縮小以維持1%風險，並寫進 `live_log.md` 與風控上限。
- 缺口：實盤績效、執行角色有沒有違反過上限、檔案衝突（兩個角色同時寫）、API 錢包權限設定畫面、用量與費用都沒有公開。影片未看。

## 建議操作流程（本庫設計，未實跑）

1. 先只用模擬盤或極小金額；把可承受的最大虧損寫在最前面。
2. 角色分工寫成文件：誰只能寫哪個檔、誰能讀哪些檔；只有一個角色有下單權限，且其金鑰在交易所端設定為不能提領。
3. 風控寫成執行前必跑的檢查清單（每筆風險、槓桿、停損、持倉數、每日筆數、停手條件），任何一項不過就跳過並記錄原因。
4. 每輪執行角色輸出「交易或跳過＋理由＋引用哪幾行檔案內容」，寫進紀錄檔。
5. 每晚檢討只產出「規則修改建議」，由本人決定是否改上限；不讓代理自己放寬風控。

## 可複製提示詞（本庫原創設計，未實跑；只用模擬盤）

> 你是唯一的執行角色，只在模擬帳戶操作。每輪開始時讀 {研究檔}、{題材檔}、{訊號檔} 的最新內容（超過{N}分鐘沒更新就當作無資料），再讀 {風控規則檔}。逐項檢查風控，任何一項不過就「跳過」。輸出：交易或跳過、理由、引用了哪幾行檔案內容、訊號來自訊號角色還是你自己的判斷。把結果追加到 {紀錄檔}，不要改其他角色的檔案。不得放寬風控規則、不得提領、不得在 {停手條件} 觸發後繼續交易；遇到任何不確定就跳過並通知我。

## 所需連接、權限與限制

- **高風險**：槓桿交易可能在短時間內虧損全部本金；代理會誤讀資料、延遲或重複下單。本頁只整理作者自述的結構，不推薦任何標的、平台或參數。
- 交易所 API 金鑰應在交易所端限制權限（不能提領、限 IP 等），不要貼進聊天或檔案；作者說使用不能提領的 API 錢包，本庫未核其設定。
- 不同國家對衍生品交易與平台使用有法規限制，請自行確認是否合法可用。
- 共用檔案交接要注意同時寫入與過期資料；本庫流程用「超過時限視為無資料」防呆。

## 驗收與可重現性

- 在模擬盤刻意給一個違反上限的訊號（例如停損過近），確認執行角色跳過並寫明哪條規則。
- 讓研究檔過期，確認執行角色不使用舊資料。
- 連續一週對照紀錄檔與交易所成交紀錄，筆數、方向、停損必須一致。
- 本庫未重現；作者未公開成交紀錄。
