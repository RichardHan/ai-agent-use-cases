# UC-427：把每天用不完的X讀取額度拿來建自己的貼文資料庫：替帳號分角色、算話題熱度，再做成一頁看板

- 情境：創作
- 標籤：每日、X、資料庫、看板
- 網站標題：Bot每天的X讀取額度沒用完很可惜？讓它每天抓貼文存進資料庫，一週累積3萬多則，再做成可切換「畫像／雷達／帳號池」的看板
- 一句話用途：簡體中文作者 @mspd4100（鸡骑猫）讓 Grok Bot 每天用掉內含的 X 讀取額度，把貼文與數據結構化存進資料庫：先抓自己的歷史貼文與回覆做自我畫像與索引，再擴大到關注的領域與帳號；作者說一週累積 3 萬多則貼文、4 萬多行數據，之後用 Grok Bot 的頁面（Page）功能做成「X 運營看板」，可看當日額度記帳、帳號角色分層與近 3 天中文話題熱度。
- 核心目標：把每天固定的讀取額度轉成可累積、可查詢的自有資料，而不是每次臨時讀時間線。
- 分類／標籤：社群經營／資料累積／額度記帳／看板
- 目標使用者：經營 X 帳號、想長期追蹤同領域帳號與話題的人
- 工具：Grok Bot（每日排程、X 讀取）；Grok Bot 頁面（Pages）功能；資料庫（作者未說明種類，截圖中有 `post_metrics` 資料表名稱）
- 首次收錄／最近查證：2026-10-22 17:45（台灣時間）
- 證據狀態：`author-demo`（作者 X 貼文自述＋3 張看板截圖）；頁面功能另有 `official` 說明；本頁提示詞為 `designed`

- 輸入：自己的 X 帳號歷史貼文與回覆；關注的領域與帳號清單；每天可用的讀取額度上限。
- 輸出：一個持續累積的貼文與數據庫；帳號角色標籤（作者截圖中如官方帳號、同規模對標、大號、新聞雷達、略過等）；每日額度記帳；話題熱度排行；一頁可切分頁的看板（作者截圖分頁：總覽、畫像、雷達、帳號池、動作）。

## 建議操作流程（本庫設計，未實跑；依作者描述的順序）

1. 先只抓自己的歷史貼文與回覆，存成固定欄位（貼文 ID、時間、文字、互動數、抓取時間），確認不重複寫入。
2. 每天固定時間執行，開跑前讀取「今日已用額度」，預留一部分給臨時查詢；超過上限就停，寫入記帳表。
3. 擴大到關注帳號時，先建帳號池並給每個帳號一個角色標籤（例如同規模對標、官方、新聞來源、略過），標籤寫明判定理由，讓你能改。
4. 熱度只做相對比較並註明資料範圍與日期，不當成全站趨勢。
5. 最後才做看板：總覽（資料量、額度）、畫像、雷達、帳號池；資料庫是主體，看板只讀。

## 可複製提示詞（本庫原創設計，未實跑）

```text
每天［時間］執行一次，只讀不寫：用 X 讀取工具抓［我的帳號］的新貼文與回覆，以及［帳號池清單］中每個帳號最近的貼文，存進［資料庫／表格］。
欄位：貼文ID、帳號、角色標籤、發文時間、文字、讚／轉發／回覆／瀏覽數、抓取時間。用貼文ID去重，已存在的只更新數據欄位。
開始前先記下今天已用的讀取次數；本次最多用［N］次，用完就停，並在記帳表寫一行：日期、本次用量、累計、是否中途停止。
不要按讚、轉發、回覆、追蹤或發文。
每週一另外產出：各角色帳號的貼文量與互動中位數、近 7 天出現最多的 10 個話題（只做相對排名，註明資料範圍）。
```

## 所需連接、權限與限制

- 只用唯讀權限；讀取自己的首頁時間線或書籤需要連接 X 帳號，公開貼文搜尋則不一定需要（見官方說明）。
- 大量蒐集他人貼文前，先確認 X 使用條款與 API 規範；資料只供自己分析，不要把他人內容重新公開散布。
- 帳號角色與話題熱度是 Bot 的分類結果，可能有誤；用於選題或互動決策前要抽查。
- 額度、計費與上限可能變動；以官方說明與帳戶畫面為準，不以作者截圖中的 1000 為通用數字。

## 驗收與可重現性

- 隨機抽 20 則庫內貼文，比對原貼文的時間與文字是否一致、是否重複。
- 記帳表的每日用量加總與帳戶顯示的用量一致。
- 熱度排行能回溯到具體貼文清單。
- 本庫只看到作者 3 張截圖；資料庫、抓取紀錄與排程設定未公開，未獨立重現。
