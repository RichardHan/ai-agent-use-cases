# UC-431：公開事件日報先按街區篩選，再用案件編號追蹤紀錄申請

- 網站標題：附近發生的事件，先核對地點與案號，再追蹤資料申請
- 一句話用途：作者把公開事件 PDF、街區篩選與申請回執串起，避免相同案件重複申請；申請已受理不等於報告已取得。
- 情境：生活
- 標籤：公開資料、地理篩選、去重、回執
- 工具：Grok Bot；未具名地方機關公開資料及紀錄入口
- 證據狀態：B 級作者實作與一次測試結果自述；未獨立重現，沒有原始 PDF、地圖或回執。
- 查證日期：2026-10-23（Asia/Taipei）
- 作者／語言：Reddit u/h8torade／英文；精確發布日期未核，原頁只有相對時間。

## 作者實際做了什麼

作者說每日讀所屬區域的公開事件 PDF，擷取類型、地點、時間與案件編號，繪圖後只挑落在指定街道的事件；沒有符合就不通知。有符合時，再由自己的紀錄入口提出電子副本申請，保存申請參考號及已申請案件清單。作者自述初次測試找到一件附近的破壞事件，數分鐘後送出申請。

這是一次具體的使用結果陳述，不是本庫看見機關收據。沒有證據證明已拿到報告、案件判定正確、長期不重複或資料完整。公開事件紀錄也不等於犯罪成立，不能據此指控住戶或個人。

## 可參考操作步驟（本庫設計，未實測）

1. 用虛構事件表與虛構街道清單演練；保留原文件日期、頁碼和原始地點文字。
2. 將地址正規化與街區比對分開；地址不完整、同名街道或地圖位置不確定時留待人核，不猜座標。
3. 以機關代號＋案件編號作候選去重鍵；沒有穩定編號時不自動併案。
4. 將「符合街區、通知候選、申請草稿、本人核准、已提交、受理回執、報告已取得」分開。
5. 只交申請草稿及待核欄位。任何正式提交、登入、驗證、費用或法律條款均另行確認；無回執不能因逾時重送。
6. 收到正式回執後才更新狀態；後續取得報告也另驗文件與案件是否相符，不公開住戶資訊。
