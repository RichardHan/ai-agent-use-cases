# UC-432：用 dots 協作建置公開網站證據分級工具，不把查不到當成安全

- 網站標題：網站交出個資前怎麼看？把公開證據、推測與看不到分開
- 一句話用途：作者與dots協作研究及製作NAIKEN，將公開網站的可觀察訊號分級並追溯來源；歷史快照只能表示抽樣，不能推算更新頻率。
- 情境：開發
- 標籤：公開證據、資安、原型、限制
- 工具：ChatGPT dots（協作建置）；作者應用另用Sites、Agents API、Decisions API、Cloudflare D1
- 查證日期：2026-10-23 06:45 Asia/Taipei
- 證據狀態：B作者建置實作自述＋公開專案說明；未獨立重現。不是dots直接連接該服務或自主安全稽核的證據。

[10月20日功能說明](https://zenn.dev/masahide/articles/9649ab5073f562)區分確定、推測、看不到，拒讀與逾時不納入危險分數。歷史比較每年只取一份保存樣本，作者承認未做到更新頻率判斷；關閉頁面後持續處理及dots連接仍未實作。

[公開repo README](https://github.com/team-voidvoid/cy-naiken)可讀架構、引用核對與結果保存說明。應用的額外研究由Agents API執行，角色圖像不是dots接入。已讀兩篇文章與README，未審全部原碼、未執行網站掃描、API或測試。

## 可借用步驟（本庫設計／未實測）

1. 先以合成HTML、標頭與舊版本樣本定義輸入，不拿真實網站當無限制測試場。
2. 每個發現列觀察值、取得時間、來源位置，分成直接證據、推測、無法觀察。
3. 讀取失敗和未檢查不算通過，也不算危險；未識別的版本不自動判老舊。
4. 生成說明後，由固定檢查驗證引用是否真的存在於輸入，無法對上的退回待核。
5. 歷史快照只比較樣本當時看見的版本；不要把保存時間寫成部署時間。
6. 人工驗收正常、缺證、逾時、引用不符及關頁中斷。交付原型與限制，不交安全保證。

## 可貼指令（原創／未實測）

只分析我提供的虛構公開頁面樣本與歷史快照，設計一個只讀證據分類原型。每項列直接證據、推測或無法觀察，附輸入位置及時間；讀不到不能變成低風險。要求引用字句可在原輸入找到，未知版本不評分。快照日期不等於更新日期；沒有漏洞實證就不寫已發現漏洞。先交資料結構、假資料測試及限制，不連真站、不掃描、不建立API金鑰、不啟用付費服務或發布。
