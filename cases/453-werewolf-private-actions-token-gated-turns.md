# UC-453：五個玩家 Bot 玩狼人殺，主持 Bot 用私人行動與回合憑證避免搶話、重複結算

- 情境：創作
- 標籤：桌遊、多代理、狀態機、驗收
- 網站標題：讓 Bot 們玩一局真的有結局的狼人殺，不把私密角色貼進群組
- 一句話用途：以可檢查的回合狀態管理多人推理遊戲，而不是讓多個角色隨意接話。
- 工具：Grok Bot、社群 Werewolf Gamemaster Skill
- 證據狀態：B級作者測試自述＋結局截圖；本庫未獨立重現。
- 查證日期：2026-10-25（Asia/Taipei）

## 問題與作者結果

Heyvhuang 的公開專案把主持與五個玩家分開。作者稱英文五玩家局已端到端測試；本輪目視附圖可見投票淘汰、狼人勝利、身份揭曉及賽後討論。這能支持一次已展示的結局，不證明每個中間回合都符合規則。六玩家人工主持及七玩家 AI 主持僅有規則，後者受群組人數限制，不當成測通。

## 操作步驟與核心機制

1. 先讀專案 Skill 與 references，人工建立主持＋五玩家群組；不要把下載檔案當成已安裝。
2. 主持先交規則，等本人確認後才分配身份。公開發言由玩家自己發；身份、夜間選擇與投票分別走一對一。
3. 以單一待辦玩家及新的 `turn_token` 驗收回覆。舊憑證、搶先回覆或主持代述不能推進；所有必要輸入到齊才結算一次。
4. 逾時依專案狀態機重送新憑證；再次失敗暫停交人，不把沉默補成棄權。

以上為專案流程摘要；不保證指令本身強制隔離記憶或阻止資料外洩。

## 權限、費用與限制

- 需可用的 Grok Bot 帳戶、群組及 Skill；建立 Bot／群組是帳戶修改，須由有權使用者決定。本輪沒有執行遊戲。
- 官方文件本輪可讀，群組支援二至六個 Bot；這僅支持容量與訊息交接，不是官方認證此遊戲。
- 多代理對話會用額度；作者未提供完整一局成本、耗時或成功率，數字留空。繁中提示詞未證中文局測通。
- 一對一規則是流程分工，不等於密碼學或帳戶層隔離；只用虛構角色。不上傳他人聊天或秘密。
