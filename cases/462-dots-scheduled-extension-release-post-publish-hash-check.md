## 建議操作流程（本庫依截圖整理＋自行設計，未實測）

1. 先把發布流程寫成固定清單（哪些檢查必過、發到哪些地方），讓代理只照清單做，不臨場改流程。
2. 發布權限用專用、可撤銷、範圍最小的權杖；第一次跑時在「開始發布」前停下等你確認。
3. CI 未通過、任一平台建置失敗就停止並回報，不自行改測試或跳過平台。
4. 發布後從公開位置下載實際檔案，比對版本號與雜湊；任一平台尚未反映就標「待確認」並稍後再查，**不重新發布同版本**。
5. 回報格式固定：檢查結果、合併與 CI、各平台建置、公開檔案數與比對結果、未完成項。

## 所需連接、權限與限制

- 需讓 dots 能操作 GitHub（PR、合併、Release）與套件市集的發布權杖；本庫未核 dots 的實際連接方式。不推定 Grok Bot 或 Muse 有相同流程。
- 發布到公開市集屬對外、難以撤回的動作；權杖外洩風險高，不要放在提示詞或對話中。
