# UC-477：Muse 的雲端 VM 沒有對外入口：從 VM 內往外拉反向通道、sshd 只聽本機，讓自家電腦能 SSH 進去傳檔、轉發看 VM 內的網頁

- 情境：開發
- 標籤：雲端電腦、遠端連線、資安、故障診斷
- 網站標題：想從自己電腦連進 Muse 的雲端 VM 傳檔、看它架的網頁？日文作者用反向通道＋只聽本機的 sshd 打通，並記下五個踩坑
- 一句話用途：日文作者 satouyoshiaki 的 Muse 雲端 VM（Ubuntu 24.04、2 vCPU）沒有公開 IP、也不能開埠；他想從自家 Windows 電腦用 SSH 進 VM 傳檔、透過埠轉發看 VM 內的本機 LLM 與自製工具畫面。做法：sshd 只監聽 127.0.0.1:2222、只收公鑰、不收密碼；由 VM 內往外建 Pinggy 免費反向通道接到該埠；自製監控腳本在 sshd 或通道掉線時重啟，並把每次變動的連線位址寫進檔案。作者以錯誤訊息記錄 apt 走代理失敗、sshd 拒絕啟動、Windows 私鑰權限太鬆被忽略、`AllowTcpForwarding no` 讓埠轉發失敗等坑與解法。作者自述，本庫未重現。
- 核心目標：在不開放入站連線的前提下，讓本人（且只有持鑰者）能進入代理的雲端工作環境。
- 分類／標籤：雲端代理環境／遠端存取／安全設定
- 目標使用者：已讓 Muse 在 VM 上架服務或產出大量檔案、想用自己的終端機直接存取的進階使用者
- 工具：Meta Muse（雲端 VM）／OpenSSH 9.6p1（.deb 解包使用）／Pinggy 免費通道／Windows OpenSSH 用戶端
- 首次收錄／最近查證：2026-10-31 08:55（台灣時間）
- 證據狀態：`author-demo`（作者 Qiita 自述＋錯誤訊息原文；連線位址與金鑰刻意不公開）
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：Muse 的 VM（無入站路徑）、作者自己的電腦與 SSH 金鑰對、反向通道服務。
- 輸出：可用的 ssh／scp／sftp 連線、`-L` 埠轉發看 VM 內網頁；一份「目前有效位址」檔案；斷線自動重建的監控腳本。

## 來源版本

### 來源A：satouyoshiaki（Qiita，日文）

- 原文：[インバウンド経路のない Muse の VM に、リバーストンネルで SSH 接続できるようにした話](https://qiita.com/satouyoshiaki/items/43191118e04ca80ae525)，2026-10-30 16:29 JST（台灣時間 15:29）；本輪讀全文。同作者同日另有 VM 規格調查、VM 上架 Minecraft 伺服器等文（未收）。
- 取得內容（翻譯摘要）：
  1. 架構：sshd 只監聽 127.0.0.1:2222、只允許公鑰；Pinggy 反向通道把外部連線導到該埠；自製 supervisor 腳本監看 sshd 與通道，掉了就重啟。
  2. 坑一：apt 經代理回 400／不支援的代理協定，但 curl 可連 → 改用 curl 下載 .deb、`dpkg-deb -x` 解到工作資料夾，不安裝到系統。
  3. 坑二：sshd 啟動即退出，訊息為 `/run/sshd must be owned by root...` → 改 root:root、755。
  4. 免費通道 60 分鐘到期、每次重建位址都變 → 監控腳本自動重建，把現行位址寫入 CURRENT-ADDRESS.txt，連線時再查，不固定設定。
  5. 坑三：Windows 下載資料夾的私鑰權限太鬆，OpenSSH 顯示 `UNPROTECTED PRIVATE KEY FILE` 並忽略 → 搬到 `~\.ssh\` 並用 icacls 限本人唯讀；另有路徑寫錯的 `not accessible`。
  6. 坑四：能登入但轉發的網頁 `ERR_CONNECTION_RESET`，sshd 記錄 `refused local port forward` → 原本為了加固寫了 `AllowTcpForwarding no`，與「轉發看 VM 內服務」的目的矛盾，改 `local` 後通過。
  7. 最後確認 SSH 登入、轉發看本機 LLM 畫面與自製工具示範頁、LLM 回應都正常。
- 作者提醒：VM 被重新配置或重開時常駐程序全停（檔案保留），要重建 sshd 權限分離使用者與 `/run/sshd`；公開位址本身也當祕密，不貼到文章或社群。
- 缺口：supervisor 腳本與 sshd_config 全文未公開；Muse 服務條款是否允許此用法、此 VM 網路政策是否會變，本庫未查證。

## 建議操作流程（依來源整理；本庫未實測）

1. 先確認用途（只傳檔？要轉發看網頁？），再決定 sshd 的轉發設定，避免「加固」與目的矛盾。
2. sshd 只聽本機、只收公鑰、關密碼登入；私鑰只留在自己電腦，權限限本人。
3. 通道與 sshd 交給監控腳本重啟；位址會變就寫檔查詢，不貼到任何公開處。
4. 不用時關掉通道；VM 重開後依清單重建。

## 可複製提示詞（本庫原創設計，未實跑）

> 我想從自己的電腦 SSH 進你的 VM，用途是傳檔和用 -L 轉發看你 VM 裡 127.0.0.1 的網頁。請先說明你的 VM 有沒有入站路徑、能否用 apt；再提出方案：sshd 只監聽 127.0.0.1、只收我提供的公鑰（我只給公鑰）、關閉密碼登入、AllowTcpForwarding 只開 local；由你往外建反向通道。執行前先列出會安裝什麼、開什麼程序、會對外連到哪個服務，等我同意。完成後把目前位址寫進檔案、只在對話裡告訴我，不要貼到任何公開地方；每次通道重建要通知我。

## 所需連接、權限與限制

- 等於替代理的工作環境開一扇門：只用公鑰、只聽本機、通道位址保密；別把任何私鑰交給代理或放進 VM。
- 第三方通道服務會看到連線中繼；免費方案 60 分鐘到期（作者引用的畫面訊息）。
- 這是 Muse VM 的作者實作，不代表 Grok Bot 或 dots 的環境有相同網路限制或做法。
