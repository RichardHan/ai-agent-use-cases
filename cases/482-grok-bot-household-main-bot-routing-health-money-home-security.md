# UC-482：生活版 Bot 團隊：只跟主 Bot 說話，由它分派給健康、家計、家電、帳號安全 Bot；冷氣依不快指數每30分鐘微調、每週一排週末外出

- 情境：生活
- 標籤：家庭、多代理、智慧家電、每日
- 網站標題：私生活的雜事都丟給一個窗口 Bot：它找健康、錢、家電、帳號安全各自的 Bot 商量，幫你點餐、調冷氣、排週末行程、清理沒在用的訂閱
- 一句話用途：日文作者 ysk-ig 在 Qiita 自述，私人用 Grok Bot 建了 Main（窗口分派）、Health、Money、Home、Security 五個 Bot：說「肚子餓」由 Main 問 Health（營養）與 Money（預算）後在 Uber Eats 找店、確認後下單；Home 經 Nature Remo API 每30分鐘依不快指數微調冷氣並確認沒停；每週一 Money 送本週外出預算、Main 綜合天氣與步行量排週末行程並寫入 Google 日曆；Security 讀 Gmail 盤點帳號、兩步驟驗證與漏網訂閱，列成清理清單一起解約。iPhone 健康資料與位置用 Bot 專屬信箱的「+標籤」地址寄入。作者稱數位雜事壓力體感降到約六分之一。
- 核心目標：把散在多個 App 的生活管理，收斂成「只對一個窗口 Bot 說一句話」，並讓各職責 Bot 的記憶與權限分開。
- 分類／標籤：個人生活管家／多 Bot 分工
- 目標使用者：願意把私人帳號與家電交給代理、想減少 App 來回切換的人
- 工具：Grok Bot（多 Bot、routine、Bot 專屬信箱、Webhook、Bot 瀏覽器）／Gmail、Google 日曆、Google 雲端硬碟連接器／Nature Remo API／Uber Eats、網購、家計簿 App（Bot 瀏覽器登入）／iPhone 捷徑與健康資料同步 App／1Password（Bot 專用保管庫）
- 首次收錄／最近查證：2026-11-01 08:51（台灣時間）
- 證據狀態：author-demo（作者長文自述＋表格；無截圖、無執行紀錄）
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：對 Main Bot 的一句話（文字、iPhone／Apple Watch 捷徑語音）；Gmail 通知信；Bot 信箱收到的健康與位置資料；Nature Remo 感測值。
- 輸出：點餐候選與確認後下單；冷氣設定調整；每週外出計畫與日曆事件；帳號／訂閱清理清單與代寄的刪除申請信；確定申告文件檢查意見。

- 取得內容（翻譯摘要）：
  1. 分工：Main 為窗口，自行判斷轉給負責 Bot；選項與確認卡出現在 Main 的對話中。有「只有該 Bot 記得」與「全員都記得」兩層記憶（例如「外部資訊一律附具名連結」）。建 Bot 也交給 Bot。
  2. 點餐：Main 參考 Health 與 Money 的意見，在 Uber Eats（Bot 自己的瀏覽器登入）找店與菜單，本人確認才下單；外食會避開最近吃過的，決定後寫入日曆。
  3. 家電：Home 用 Nature Remo API 操作冷氣、燈、電視、窗簾；在家時以不快指數為目標，每30分鐘微調並檢查是否停擺；「冷」「有點熱」立即調整並記住偏好；語音經 iPhone 捷徑以 Webhook 送達。
  4. 週末：每週一早上 Money 做家計檢查（唯讀）並把本週外出預算送給 Main，Main 綜合天氣、往返步行量排行程，寫進 Google 日曆。
  5. 日用品：「這個和那個幫我買」→ Home 在網購比較2–3個候選，選好才下單，會考慮補充包與合併到貨日。
  6. 帳號安全：Security 讀 Gmail 盤點帳號、兩步驟驗證／通行金鑰與外洩狀況，列出忘記停的訂閱與沒用的帳號，再一起解約刪除；只收信件刪除申請的服務由 Bot 寄信並盯回覆。
  7. 例行：Health 每早檢查是否忘了量體重；Main 每天追蹤卡住的手續、每幾小時查 Grok Bot 新功能。
  8. 資料進出：連接器（Gmail 多帳號、日曆、雲端硬碟）、API（Nature Remo）、Bot 瀏覽器（網購、Uber Eats、家計簿）、Bot 專屬信箱「+health」「+location」標籤地址接收健康同步 App 與捷徑資料；1Password 開 Bot 專用保管庫，只放少數服務的登入。

## 建議操作流程（本庫依來源整理，未實測）

1. 從一個窗口 Bot 加一個職責 Bot 開始，每接一個 App 才新增 Bot，不一次全建。
2. 家計 Bot 先只讀；任何下單、解約、刪帳號都要求在窗口對話出現確認卡，本人按下才執行。
3. 家電控制先手動跑通一次，再設定30分鐘 routine，並讓 routine 回報「上次執行時間」以偵測停擺。
4. 健康、位置等敏感資料用專屬收件地址與標籤分流，註明哪個 Bot 可讀。
5. 帳號清理先產出清單，由本人逐項勾選後才代寄刪除申請。

## 可複製提示詞（本庫原創，未實跑）

> 你是我的生活窗口 Bot。我只跟你說話；需要時請轉問健康 Bot（營養、作息）與家計 Bot（本週預算，唯讀）。任何會花錢、下單、解約、刪除帳號或寄信的動作，先在這個對話列出內容、金額與對象，等我回「好」才做。每週一早上［時間］：向家計 Bot 取本週外出預算，綜合天氣與往返步行量，提出兩個週末方案，我選定後才寫入日曆。所有外部資訊附具名連結。

## 所需連接、權限與限制

- 涉及 Gmail 全部信件、健康與位置資料、購物與外送帳號，屬高度敏感；建議與工作帳號完全分離，登入只放 Bot 專用保管庫並最小化。
- Nature Remo 為作者使用的家電遙控器 API；其他家電需各自 API。本案流程為 Grok Bot；不推定 Muse 或 dots 具有相同的 Bot 專屬信箱與 Webhook 功能。
- 家電自動調整需注意長輩、寵物與安全上限。

## 驗收與可重現性

- 可驗收：每筆下單／解約都有確認紀錄；冷氣 routine 每次執行有時間戳；週末計畫與日曆事件一致；清理清單每項附證據信件。
- 本庫未重現。
