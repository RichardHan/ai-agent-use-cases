# UC-485：讓 Bot 用雲端電腦點美團外送：讀近幾天訂單出 2–3 個選項、勾最大紅包並補齊漏菜，讀回確認、說「提交」才送出，停在收銀台由本人在手機付款

- 情境：省錢
- 標籤：外送、優惠券、技能、核准
- 網站標題：叫外送懶得一項項挑、又常忘了勾紅包？一份開源 Agent 技能：Bot 依最近訂單給選擇題，自動勾最大券，你說提交它才下單，付款仍在你手機上
- 一句話用途：簡體中文作者 YeJe-cpu 在 GitHub 公開 MIT 授權的「grok-eats」技能：Grok Bot 在雲端電腦開美團外賣 H5 網頁，用簡訊驗證碼登入（身分核實走加密表單），讀近 3–7 天訂單避開今天吃過的，給 2–3 個「再來一單」候選；選定後組購物車、勾選額度最大的紅包與商家券、比對原單補齊漏掉的菜，把店名、品項、費用、用券、合計、地址讀回，使用者明確說「提交」才送出，並停在收銀台由本人在手機付款。作者 2026-10-31 實測兩單（¥14 美式咖啡、券後 ¥24.6 晚餐），附 16 張打碼截圖。
- 核心目標：在沒有個人外送下單 API 的平台上，讓 Bot 代做挑選、比券、組單等繁瑣步驟，同時把付款、提交與地址守在本人手上。
- 分類／標籤：外送點餐／優惠券套用／瀏覽器操作技能
- 目標使用者：常叫外送、在意優惠券與飲食控制，願意讓 Bot 在雲端瀏覽器登入自己外送帳號的人
- 工具：Grok Bot（雲端電腦瀏覽器、技能、可選 routine）／美團外賣 H5 網頁版／美團官方領券 skill（meituan-coupon）；作者說同一份技能也可給 Muse 等能開瀏覽器的代理使用，但僅在 Grok Bot 實測（餓了麼 H5 標「待實測」）
- 首次收錄／最近查證：2026-11-02 08:58（台灣時間）
- 證據狀態：`author-demo`（作者公開倉庫，README 自述 2026-10-31 實測兩單，附 16 張打碼步驟截圖；一個帳號、一天）
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：本人的美團帳號（簡訊驗證碼由本人在聊天中提供）、地址簿既有地址、可選的個人檔案（預算、忌口、偏好，`profile.md`）、近期訂單紀錄。
- 輸出：2–3 個候選（選擇題）；勾券後的報價讀回（店名、品項與數量、打包費、配送費、用了哪些券各多少、合計、預計送達、地址）；提交後的訂單號與金額，請本人到 App「待支付」付款；可選：近 3 天外送熱量簡報（只給區間與依據檔位，不給假精確數字）。

## 來源版本

### 來源A：YeJe-cpu／grok-eats（GitHub，簡體中文＋英文 README）

- 倉庫：[github.com/YeJe-cpu/grok-eats](https://github.com/YeJe-cpu/grok-eats)，建立 2026-10-31 09:19 UTC（台灣時間 17:19），MIT 授權；含 `SKILL.md`、`references/`（login、address、recommend、checkout、nutrition、coupons、routines）與 `assets/` 截圖。
- 取得內容（翻譯摘要）：
  1. 動機：美團對個人開放的 AI 能力只有領券和跑腿；跑腿「幫買」要另付費且用不到外送滿減與紅包，所以改讓 Bot 操作 H5 網頁。
  2. 實測踩到的坑：紅包不會自動勾（未勾 ¥41.6、勾「滿 38 減 15」與商家券後 ¥24.6）；「再來一單」會漏菜（原單 5 樣進購物車只剩 2 樣，須打開原單逐項對照補齊並確認達起送價）；Bot 會自己編地址（想在地圖新建「XX 健身房」）；登入可能跳出要填證件生日的身分核實。
  3. 四條硬規則：不碰支付（提交就停，彈出支付密碼框直接關掉）；不擅自提交（讀回確認頁，本人說「提交」才點）；不編地址（只用地址簿）；敏感資訊不在聊天明文索取（走加密表單，沒有就由本人自填）。
  4. 可選每日例行（預設關閉，先手動用幾次確認穩定）：09:00 以官方 skill 領券；11:00／17:30 先檢查登入狀態再發候選；routine 只能推薦不能自行提交，沒回覆就不動作、不追訊息，「今天不點／這週暫停」要記住並照做；登入過期要通知而非悄悄失敗或反覆重試。
- 作者報告結果：兩單皆由 Grok Bot 提交、本人手機付款；官方領券 skill 一次領到 10 張券（截圖）。
- 失敗點／缺口（作者自列）：證據只有一個帳號、一天、兩單；登入能維持多久、多頻繁會觸發風控尚無資料；H5 自動化非美團官方支援用法，改版或風控可能失效、帳號可能被要求額外驗證；熱量估算非營養建議。

## 建議操作流程（依來源整理）

1. 先讀倉庫的邊界與風險說明；只用於自己的帳號、低頻使用，不批量下單、不刷券。
2. 把 `SKILL.md` 與 `references/` 交給 Bot 存成技能；可選填 `profile.md`（預算、忌口、偏好）。
3. 第一次登入由本人提供簡訊驗證碼；身分核實若無加密表單就本人自己填。
4. 手動點幾次，逐單核對：報價是否已勾最大可用券、購物車品項是否與原單一致、地址是否來自地址簿。
5. 確認穩定後才考慮開啟 routine，而且 routine 只發候選、不提交。

## 所需連接、權限與限制

- 需讓 Bot 在雲端瀏覽器登入本人外送帳號；共享瀏覽器登入對同一帳戶下所有 Bot 都可用，請評估風險。
- 付款完全保留在本人手機；提交仍須逐次明確同意。
- 不推定其他代理產品或其他外送平台（如餓了麼、Uber Eats）已驗證可用；作者僅美團實測。
- 平台條款與風控可能限制自動化操作，使用風險自負。
