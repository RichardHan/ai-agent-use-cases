# UC-486：讓 Muse 操作自己電腦上的 Blender：用官方 Gadget SDK 的 Linux 版接上 Ubuntu，專用低權限使用者執行，建好機器人模型後再開檔把一隻手舉起來

- 情境：開發
- 標籤：實體裝置、3D建模、權限隔離、驗收
- 網站標題：Muse 也能動你電腦上的軟體：用官方 SDK 把 Ubuntu 註冊成 Muse 的裝置，叫它在本機 Blender 建模、改模型，並用檔案和截圖確認真的做了
- 一句話用途：日文作者 wahhooi 在 Qiita 記錄：用 Meta 官方開源的 Muse Gadget SDK（Linux 版）把手邊沒有藍牙的 Ubuntu 24.04 註冊成 Muse 的「裝置」，指令以另外建立、沒有 sudo 的專用帳號執行；配對時向另一台 Linux 電腦借藍牙網卡（USB/IP 走 SSH 通道，只開在 loopback），配對後立即歸還。之後請 Muse 用 `system.run`／`file.write` 寫 Blender 指令稿，在本機建出機器人並另存舉起右手的版本，兩次結束碼皆為 0，作者用預覽圖、GLB 讀取與 SHA-256 核對。作者自述實測（2026-11-03），本庫未重現。
- 核心目標：讓雲端代理操作本機才有的專業軟體，同時把它能執行的範圍限制在一個專用帳號與工作資料夾，並用實際檔案而不是代理的回覆來驗收。
- 分類／標籤：本機軟體遠端操作／3D 建模指令稿／權限隔離與驗收
- 目標使用者：已有 Muse 帳號、熟悉 Linux 命令列，想讓 Muse 動本機 Blender 或其他命令列工具的開發者與 3D 玩家
- 工具：Meta Muse（iPhone App 開發者模式配對＋SDK token）／Muse Gadget SDK 0.1.0（Linux 版，固定到特定 commit）／Ubuntu 24.04／Blender 5.2.2 LTS（Cycles CPU 算圖）／USB/IP＋SSH（只在配對時用）；作者說環境建置與確認用 Codex，Blender 指令稿由 Muse 撰寫
- 首次收錄／最近查證：2026-11-03 09:00（台灣時間）
- 證據狀態：`official`（Muse Gadget SDK 為 Meta 在 GitHub facebookincubator 公開的專案，作者附固定 commit 的 README 連結）＋ `author-demo`（作者自述實測：配對記錄檔、兩張算圖、檔案大小表、結束碼與雜湊核對）；本頁提示詞為 `designed`
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：一台 Ubuntu（可沒有藍牙）；可借用的 BLE 藍牙網卡（可在同區網另一台 Linux）；Muse App 開發者模式；在官方頁面發行的 SDK token（以不回顯方式輸入，存成 root 擁有、權限 600 的檔案）；Blender 執行檔絕對路徑與專用帳號可寫入的工作資料夾。
- 輸出：Blender 原始檔、GLB、預覽 PNG、產生用的 Python 指令稿；編輯版另存新檔（保留原檔）；SDK 服務記錄檔中的執行紀錄與結束碼。

## 來源版本

### 來源A：wahhooi／Qiita（日文）

- 原始網址：[BluetoothのないUbuntuで、MuseにBlenderのモデル作成・編集を任せてみた](https://qiita.com/wahhooi/items/e60536d045627164ef72)
- 作者：wahhooi；發布：2026-11-03 07:42 JST（台灣時間 06:42）；原文語言：日文；作者標示確認日 2026-11-03。
- 取得內容（翻譯摘要）：
  1. 建立系統帳號 `muse3d`（無登入 shell、無 sudo），安裝 SDK 時以 `--run-as muse3d --no-pair` 指定執行身分並延後配對；作者提醒分開帳號不等於完整沙箱，該帳號可讀的檔案與網路仍可達，也沒有限定只能跑 Blender。
  2. SDK token 以 `getpass` 輸入、寫成 root 擁有、權限 600 的檔案，不放在命令列參數；token 有獨立使用條款。
  3. 工作機沒有藍牙：在另一台 PC 用暫時腳本把藍牙網卡以 USB/IP 匯出，防火牆只允許 loopback，再從工作機開 SSH 本機轉送後 attach；腳本中斷時自動解除綁定、移除暫時防火牆規則並把網卡還給原驅動。最初設定 5 分鐘自動結束，因需要時間操作手機改成 10 分鐘。
  4. 第一次配對卡在手機「連線中」，記錄檔只到裝置資訊回應、未進入驗證；重開 App 重試後通過（`pairing confirmed`、`auth_ok`、`Paired.`）。作者說第一次失敗原因不明，不能說重開必定有效。
  5. 配對後 detach 歸還網卡，服務記錄出現 `registered with the Muse`；`musegadget doctor` 只檢查服務與 token 格式，不能當作「Muse 已能執行指令」的證明。
  6. 委託內容（作者摘要）：用已註冊 Linux 裝置的 `system.run` 與 `file.write`，在本機 Blender 做藍綠＋橘色機器人（圓頭、眼睛、身體、雙臂雙腳、天線、底座），存 .blend、GLB、預覽圖與產生指令稿；並附減負設定（背景執行、CPU 2 執行緒、同時 1 個程序、Cycles CPU 512×512、16 samples、不開降噪、不用外部素材或額外套件）。接著要求「打開剛存的模型，把一隻手舉起來」，Muse 以 `ShoulderR` 為支點旋轉 `ArmR` 與 `HandR`，另存新檔、原檔保留。
- 作者報告結果：建立與編輯兩次執行的結束碼都是 0；預覽圖可見手臂舉起；GLB 可依 glTF 2.0 讀取；上傳後下載的檔案 SHA-256 一致。檔案大小表：.blend 177,972→177,693 bytes、GLB 645,536→645,644、PNG 356,093→358,539。
- 失敗點／缺口（作者自列）：只驗證簡單機器人的建立與物件移動／旋轉，複雜建模與骨架綁定未測；首次配對卡住原因未明；本次 Muse 額外 token 用量未計測。文末有作者招待碼（作者自己也會得到獎勵），本庫不轉載。

工具支援狀態：Gadget SDK 的 Linux 版與 `system.run`／`file.write` 為作者依官方 README 的使用描述；本庫未另讀官方文件核對方案條件與地區。

## 建議操作流程（依來源整理）

1. 先建專用、無 sudo 的執行帳號與工作資料夾；安裝 SDK 時指定此帳號並延後配對。
2. token 以不回顯方式輸入並限縮檔案權限；不貼在聊天或命令列。
3. 沒有藍牙就短暫借用，只開 loopback＋SSH 通道，設定自動結束與復原，配對後立即歸還。
4. 用服務記錄檔確認「已向 Muse 註冊」，不要只看服務狀態或 doctor。
5. 委託時明講執行檔路徑、輸出位置、資源上限與「不用外部素材」；編輯一律另存新檔。
6. 驗收看實際檔案：結束碼、預覽圖、檔案能被讀取、雜湊一致。

## 所需連接、權限與限制

- Muse 可透過 SDK 在你的電腦執行 shell 指令；請只給專用帳號，並理解它仍能讀該帳號可讀的檔案與網路。
- SDK token 有獨立條款，與程式碼授權不同；不要公開。
- 借用藍牙涉及在另一台機器暫時改驅動與防火牆；作者腳本針對特定網卡 ID，照抄前須改成自己的值。
- 不推定其他代理產品有同等的「本機裝置」通道。
