# UC-487：Muse 雲端電腦連不出 SSH，就用限縮權限的 GitHub token＋Git Data API 一次組好 commit，把 160 個文件、圖片與影片（約 155 MB）收進私有倉庫

- 情境：開發
- 標籤：雲端電腦、GitHub、權限隔離、代理協作
- 網站標題：Muse 做出的文件、圖和影片散在雲端電腦裡？三種放進 GitHub 的方法實測，只有「API 組 commit」把二進位檔也帶得進去
- 一句話用途：日文作者 hisashi-ito（伊藤久志）想把 Muse 當成像 Claude Code 一樣的程式代理，讓它把成果帶版本紀錄地放進 GitHub 私有倉庫。實測三條路：官方 GitHub 連接器只收 UTF-8 文字（一次最多 2,000 檔、16 MiB、不能刪）；SSH push 在 22 與 443 埠都於驗證前被重設；最後用只限一個倉庫、只有 Contents 讀寫的細粒度 token 存進 Secure Vault，由 Muse 建自訂連接器呼叫 Git Data API（blob→tree→commit→更新 ref），每次 push 由本人核准，登錄 160 檔約 155 MB。也測了經倉庫和 Claude Code 往返一次。作者自述實測（2026-11-02），本庫未重現。
- 核心目標：在代理的雲端環境不能正常使用 git 時，仍讓它的成果有版本紀錄、集中在一處，且 token 不經聊天、不出現在腳本或記錄中。
- 分類／標籤：代理成果版本管理／受限網路下的 GitHub 寫入／跨代理交接
- 目標使用者：讓 Muse 產出文件、程式、圖片或影片，想用 GitHub 集中管理並與本機程式代理交接的開發者
- 工具：Meta Muse（雲端 VM、官方 GitHub 連接器、自訂連接器、Secure Vault）／GitHub（細粒度 personal access token、Git Data API）／Claude Code（另一端讀寫同一倉庫）
- 首次收錄／最近查證：2026-11-03 09:00（台灣時間）
- 證據狀態：`author-demo`（作者 Qiita 自述實測，數字依倉庫歷史核對；附架構圖）；憑證代換機制為 Muse 的說明，作者表示無法從外部確認；本頁提示詞為 `designed`
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：本人建立的成果用私有倉庫（依作業類型分資料夾）；只授權該倉庫、權限僅 Contents 讀寫、有效期 1 年的細粒度 token（本人直接登錄進 Secure Vault）；Muse 產出的檔案清單；單檔上限（作者訂 50 MB）。
- 輸出：每批一個 commit（由 API 組成，最後才更新 ref）；倉庫歷史可對照的檔案數與大小；失敗時倉庫可見狀態不變（只留下未引用的 blob）。

## 來源版本

### 來源A：hisashi-ito／Qiita（日文）

- 原始網址：[Muse と GitHub を連携して、Muse をコーディングエージェントに近づける方法](https://qiita.com/hisashi-ito/items/5fa80b00bb68eee472f4)
- 作者：hisashi-ito；發布：2026-11-02 16:47 JST（台灣時間 15:47）；原文語言：日文；作業日 2026-11-02。作者說文章依 Muse 自己的作業紀錄、經 Claude Code 協助確認後由本人撰寫。
- 取得內容（翻譯摘要）：
  1. 方法一 官方 GitHub 連接器：本人 OAuth 授權、只選成果倉庫；Muse 確認的限制為只收 UTF-8 文字、一次最多 2,000 檔／16 MiB、混入一個二進位檔整批失敗、不能刪除。登錄了兩份 Markdown。
  2. 方法二 SSH＋部署金鑰：22 埠與 ssh.github.com 443 埠都在金鑰驗證前被重設；HTTPS 可達 GitHub 網站與 API。判斷是 VM 對外 SSH 不通，原因在 VM 或其外側不明；部署金鑰改為不需要、可刪除。
  3. 方法三 token＋Git Data API：token 不在聊天交給 Muse，由本人從 Secure Vault 畫面登錄；Muse 建自訂連接器，執行腳本只帶「憑證代號」，依 Muse 的說明，執行平台只在送往 api.github.com 時換成真 token（作者註明無法從外部驗證）。四步：取得分支 ref 與其 tree→每個檔案建 blob（Base64，二進位可用）→建 tree→建 commit 並更新 ref。先用 1 張 WebP 試，再一次登錄 159 檔。
  4. git 一般操作：HTTPS clone 公開倉庫成功（約 113 秒）；clone 私有倉庫因無憑證失敗；push 未測。作者推測代換只對 api.github.com 生效，未確認。
  5. 與 Claude Code 往返：Muse 已在專用資料夾放每日 token 用量 CSV 與給 Claude Code 的說明信，7 分鐘後 Claude Code 端的統計工具加入 Muse 用量顯示；反向測試由 Claude Code 放入含暗號與 5 個數字的確認檔，本人請 Muse 讀取，約 2 分鐘後 Muse 回寫的檔案暗號、commit SHA、blob SHA、合計 191 與最大值 91 全部相符。
- 作者報告結果：160 檔（含測試 1 檔），登錄後倉庫共 165 檔約 154.6 MB；最大檔 13,024,077 bytes（影片）；159 檔中 133 個是生成圖片與影片、7 個是試作程式。
- 失敗點／缺口（作者自列）：無法 clone 私有倉庫、看差異或解衝突；token 1 年到期需重發；blob 逐檔上傳，數千檔規模未測；API commit 的作者都是 token 擁有者，Muse 與本人只能靠訊息與時間區分；往返只測一個小文字檔且由人轉達。另一個教訓：Muse 起初說「HTTPS clone 成功」，要求貼指令與輸出後才更正為私有倉庫失敗、檔案其實經 API 取得——代理自述要用實際指令輸出核對。Muse 也回報官方連接器讀取結果觸發一次自動安全提醒，原因未查明。

工具支援狀態：官方連接器限制與 Secure Vault 代換方式來自 Muse 在作者環境的說明，本庫未讀官方文件核對。

## 建議操作流程（依來源整理）

1. 先分清卡在哪一層：連接器規格、對外網路、還是憑證；用「同一目標換一條路（HTTPS）能否到達」切分。
2. token 只授權單一倉庫、最小權限、設到期日；由本人直接登錄保管庫，不經聊天。
3. 先用 1 個小二進位檔試跑整條 API 流程，再批次登錄；最後一步才更新 ref。
4. 每次 push 由本人核准；登錄後用倉庫歷史核對檔案數、大小與最大檔。
5. 要求代理貼出實際指令與輸出，不接受只有「成功了」的回報。

## 可複製提示詞（本庫原創，未實跑）

> 把 `［資料夾］` 底下的成果登錄到 `［owner/repo］` 的 `［branch］`，路徑放在 `［作業類型］/［日期］/`。只能用已設定的 GitHub 自訂連接器呼叫 Git Data API，不要在任何地方印出或要求 token。單檔超過［50］MB 的跳過並列出。先只登錄 1 個檔案試跑並回報 commit SHA，等我說「繼續」才批次登錄。完成後列出：檔案數、總大小、最大檔、commit SHA、ref 更新前後的值，以及你實際執行的 API 呼叫清單與回應狀態碼。

## 所需連接、權限與限制

- 細粒度 token 外洩時影響限於授權倉庫；到期或撤銷只需在 GitHub 端操作。
- 官方連接器不支援刪除；整理舊檔需另以 tree 操作處理（作者尚未做）。
- 這是在 git 協定不通時的替代寫入方式，不等於能在 VM 內正常使用 git。
- 不推定其他代理產品的雲端環境有同樣的網路限制或保管庫代換機制。

## 驗收與可重現性

- 可驗收：倉庫歷史上的檔案數／大小與代理回報一致；失敗的一批不改變 ref；token 未出現在聊天、腳本與記錄中；往返檔的暗號與 SHA 一致。
- 本庫未重現。
