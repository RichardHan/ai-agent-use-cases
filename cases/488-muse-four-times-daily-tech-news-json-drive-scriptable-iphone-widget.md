# UC-488：Muse 一天四次收集技術新聞，先查一手來源、去掉已發過的，寫成 JSON 存 Google Drive，iPhone 主畫面小工具直接顯示

- 情境：學習
- 標籤：每日、新聞彙整、事實查核、手機小工具
- 網站標題：不用一直滑 X：讓 Muse 每天四次整理技術新聞，查證過才放、沒有大事就說沒有，結果直接出現在手機主畫面
- 一句話用途：日文作者 eri1600 在 Qiita 分享：在 Muse 開一個專用側聊，交代每天四次從 X、其他社群、新聞網站、arXiv、GitHub、Hugging Face 收集指定六類技術新聞（本機 LLM、雲端 LLM、本機圖像生成、Apple、資安漏洞、其他），每次先比對是否已發過（只有後續進展例外）、到官方發表或原帖查證，查不到就不放或標「傳聞／未確認」，沒有大事就老實回「沒有」；結果以固定格式 JSON 覆寫同一個 Google Drive 檔案，再用 Muse 寫的 Scriptable 指令稿顯示成 iPhone 主畫面小工具，點進去可開一手來源。作者自述在用，附兩張截圖，本庫未重現。
- 核心目標：把「刷動態追新聞」換成固定時段、有查證與去重規則的摘要，並把結果放在打開手機就看得到的地方。
- 分類／標籤：個人資訊收集／每日新聞摘要／手機主畫面顯示
- 目標使用者：想追 AI 與硬體新聞、又不想整天刷社群的 iPhone 使用者
- 工具：Meta Muse（排程、網頁搜尋、Google Drive 寫入）／Google Drive（JSON 公開讀取連結）／Scriptable（iOS 小工具）；作者描述候選收集階段「經 Muse 問 Grok 近幾小時 X 上的話題」，本庫未核實 Muse 以何種方式取得 Grok 回覆

## 輸入與預期輸出

- 輸入：關注類別與優先順序；每天的執行時段（作者小工具中寫的是約 8:20、12:20、17:20、21:20）；Google Drive 上的 JSON 檔與讀取連結。
- 輸出：每回一份 JSON（`version`、`title`、`date`、`edition`、`updatedAt`、`items[]`：類別、標題、1–2 行摘要、來源網址、配信回）；Muse 側聊中的標題＋重點＋來源；小工具依尺寸顯示 2／4／8 則，區分「有新聞」「沒有大事」「讀取失敗」三種狀態，點擊開一覽頁、每張卡片可開原始來源。

- 取得內容（翻譯摘要）：
  1. 流程五段：候選收集（作者說經 Muse 問 Grok 近幾小時 X 上的技術話題，並以其他社群與新聞搜尋補充）→查證（Muse 對照官方發表、原帖、技術媒體）→去重（排除已配信過的，續報例外）→配信（Muse 側聊貼出，同時寫 JSON 到 Google Drive）→顯示（Scriptable 讀 JSON 更新小工具）。
  2. 委託重點：每次覆寫同一檔名；不設件數上限以免漏掉重要消息；反過來沒有醒目新聞就照實說沒有——作者說「與其灌水，不如什麼都不給比較可信」。
  3. 小工具程式由 Muse 撰寫：逾時 20 秒、狀態分 ok／empty／error、依類別上色、每 30 分鐘重整。
  4. 作者整理的重點：明確要求不誇大、未確認就寫未確認；速度交給 Grok、正確性交給 Muse 找一手來源；先決定類別與優先順序，件數增加也不會亂。
- 作者報告結果：主畫面小工具與點開後一覽頁的截圖（2026-11-01 20:49、21:30）。
- 失敗點／缺口：未說明運作了幾天、查證錯誤或漏報次數、每回用量；Google Drive 檔案需有可讀連結，公開範圍未說明；Grok 參與的方式只有作者一句描述。

## 建議操作流程（依來源整理）

1. 專開一個側聊給這項工作，先寫好類別、優先順序、時段與 JSON 格式。
2. 把「去重」「查證一手來源」「查不到要標未確認」「沒有就說沒有」寫成每回必做規則。
3. 固定覆寫同一個 JSON 檔，讓顯示端只認一個網址。
4. 小工具要分出「沒有新聞」與「讀取失敗」，避免把壞掉誤認為沒消息。
5. 前幾天逐則點開來源抽查，確認標「已確認」的真的有一手出處。

## 可複製提示詞（本庫原創，未實跑；改寫自來源規則）

> 每天［08:20、12:20、17:20、21:20］收集以下類別的最新消息：［類別1…N，依優先順序］。每一回：①與先前已配信的項目比對，重複的不放，只有實質後續進展可再放並註明「續報」；②每則都要找到官方發表、原帖或可信媒體的一手出處並附網址，找不到就標「未確認」或不放；③沒有值得報的就回「本回沒有重大消息」，不要湊數。結果覆寫到 Google Drive 的［檔名］.json，格式固定為［貼上 JSON 結構］，同時在這個對話列出標題、1–2 行重點與來源。

## 所需連接、權限與限制

- 需授權 Muse 寫入 Google Drive；小工具讀取的連結若設為「知道連結者可看」，內容即半公開，不要放私人資料。
- 每天四次會持續消耗用量；作者未提供數字。
- 不推定 Muse 內建可直接呼叫 Grok；作者只描述為「經 Muse 問 Grok」。

## 驗收與可重現性

- 可驗收：連續數日每回都有新 JSON 或明確的「沒有」；抽查標「已確認」的項目都有可開啟的一手來源；同一新聞不重複出現；小工具在檔案壞掉時顯示「讀取失敗」而不是「沒有新聞」。
- 本庫未重現。
