# UC-491：兒子出生後要記餵奶、睡眠和照片：在 Grok Bot 協助下自建手機網頁 App，資料放自己的 Cloudflare 與 Google 免費方案，Bot 在旁邊用同一個 API 整理、提醒與回答

- 情境：生活
- 標籤：家庭、育兒、個人App、排程
- 網站標題：新手爸爸自建育兒紀錄 App：手機點一下就存、背景同步，資料留在自己的帳號，Bot 負責把隨手筆記整理成紀錄、定時摘要與回答問題
- 一句話用途：英文作者 @ozfreeman 分享：兒子出生後想有一個地方記餵奶、睡眠與照片，於是在 Grok Bot 協助下做了自己的 App，並整理成可套用到其他個人 App 的四段架構——手機主畫面網頁 App（先存本機、背景同步）＋Cloudflare 免費方案（Pages 放 App、Functions 當唯一 API、D1 存結構化紀錄、KV 存小狀態）＋Google 免費方案（Drive 放照片檔案、Calendar 放時間性事項、Apps Script 串接）＋Grok Bot 代理（不在 App 裡面，用自己的 token 呼叫同一個 API：把粗略筆記轉成乾淨紀錄、定時摘要／提醒／檢查、依自己資料回答的領域助理）。作者自述 Bot 也協助寫規格、協調程式代理、在 staging 測試與部署；本庫未重現。
- 核心目標：讓家人能一起用的紀錄工具同時具備「快」（本機先存）、「資料在自己手上」與「AI 可以讀寫」，又不必從零當全職開發者。
- 分類／標籤：家庭紀錄／個人 App 架構／代理經 API 讀寫
- 目標使用者：想記錄育兒、健身、寵物、居家維護、植物或家計，但覺得只靠跟 Bot 傳訊息不夠方便的人
- 工具：Grok Bot（routine、程式代理協調、部署協助）／Cloudflare Pages、Functions、D1、KV／Google Drive、Calendar、Apps Script

- 證據狀態：`author-demo`（作者自述架構＋一張架構圖；App 本身、程式碼與 Bot 設定未公開）

## 輸入與預期輸出

- 輸入：家人在手機上每次點選的紀錄（餵奶、睡眠、照片）與隨手打的粗略筆記。
- 輸出：存在自己 D1 的結構化紀錄、Drive 裡的照片、Calendar 上的時間事項；Bot 定時送出摘要與提醒、做資料檢查，並可回答「依我們家資料」的問題；App 可分享給太太與家人使用（作者在回覆中提到）。

## 來源版本

### 來源A：@ozfreeman／X（英文）

- 原始網址：[A design pattern for personal AI-powered apps](https://x.com/ozfreeman/status/2117576881239474358)；2026-11-03 11:17 UTC（台灣時間 19:17）；原文語言：英文；附架構圖一張。
- 補充回覆：[回覆 @jaemclaugh](https://x.com/ozfreeman/status/2117770845838029286)，2026-11-04 00:08 UTC（台灣時間 08:08）。
- 取得內容（翻譯摘要）：
  1. 起點：一開始也只是傳訊息給 Bot，很快覺得不夠方便，於是先做儀表板、再做顯示資料的前端頁，逐步擴充成可用的 App；另一個好處是能分享給太太和孩子的其他照顧者（回覆內容）。
  2. App：可加到主畫面的小型網頁 App，每次點擊先存在手機、背景同步，網路差也感覺即時。
  3. Cloudflare：Pages 託管；Functions 是所有東西（登入、紀錄、檔案、webhook）唯一經過的 API；D1 放結構化紀錄、KV 放小狀態。
  4. Google：Drive 存照片與檔案、Calendar 放有時間性的事、Apps Script 把兩者接到 App。
  5. Grok Bot：「AI 在 App 旁邊，不在 App 裡面」，代理用自己的 token 走同一個 API；三種角色：把粗略筆記轉成乾淨紀錄的 routine、定時摘要／提醒／檢查的排程、依自己資料回答的領域助理。
  6. 原則：資料在自己的 Google 與 Cloudflare 帳號；都在免費方案；每個儲存都包一層小 adapter，可替換；Bot 協助寫規格、協調程式代理、在 staging 站測試與部署。同一架構可換成健身、寵物、居家維護、植物日誌或家計，只改紀錄類型、畫面與助理知識。
- 作者報告結果：自述已在使用並與家人共用；未公開畫面截圖以外的實際紀錄量、運作期間或費用。
- 失敗點／缺口：未說明代理 token 的權限範圍、登入方式、備份與嬰兒照片的分享範圍；「免費方案」的額度上限未提。

## 建議操作流程（依來源整理）

1. 先只用聊天記錄一兩週，找出真正要記的欄位（例如時間、量、睡眠起訖）。
2. 讓 Bot 先寫規格：紀錄類型、畫面、API 端點、哪些資料放 D1／Drive／Calendar。
3. 由程式代理實作，先部署到 staging，本人用手機實測離線點擊與同步。
4. 給 Bot 一組只限該 API 的 token，再加 routine：整理筆記、每日摘要、異常檢查。
5. 家人共用前確認登入與照片分享範圍。

## 所需連接、權限與限制

- 嬰幼兒照片與作息屬家庭隱私：登入、分享連結與備份要先想清楚，不要用公開可讀的 Drive 連結。
- 代理 token 應只限這個 API，不能拿來讀寫其他 Cloudflare／Google 資源；部署與刪除資料前應由人確認。
- 免費方案有用量與功能限制，作者未提供數字；本庫不推定 Meta Muse 或 ChatGPT dots 能以同樣方式協調部署。

## 驗收與可重現性

- 可驗收：手機離線時點擊仍會存、恢復連線後同步到 D1；Bot 的筆記整理結果可回到原始筆記核對；每日摘要的數字與 D1 查詢一致；換掉一個儲存（adapter）不影響 App。
- 本庫未重現。
