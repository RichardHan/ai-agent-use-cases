# UC-492：不會畫圖也想讓 App 裡的角色眨眼：Muse 畫原畫與閉眼差分，Claude Code 用開源工具做骨架與輸出，遮罩外逐像素比對後才收進 iOS App

- 情境：創作
- 標籤：生成圖像、角色動畫、代理協作、驗收
- 網站標題：一張圖做出會眨眼、張嘴、歪頭的 App 角色：Muse 負責畫，Claude Code 負責骨架與輸出，人只看動得好不好
- 一句話用途：日文作者 stak22 在 Zenn 分享：想在自己的 Swift iOS App 放一個會眨眼、微微晃動的角色，但不想導入 Live2D／Spine，自己也不會畫。分工是 Meta Muse 畫原畫（PNG、透明背景、全身、臉不被遮）與閉眼差分、並看姿勢一覽圖指出變形；Claude Code 經 Claude in Chrome 操作 Muse 畫面往來，依開源 Mesh Avatar Studio 的代理手冊做骨架（rig.json）、姿勢檢查、匯入差分與輸出 `.mavatar`；人只在實機判斷好壞。閉眼圖收進前先檢查「遮罩外 0 像素改變」。作者附 Muse 最初原畫與過程截圖，App 用的正式原畫未公開；本庫未重現。
- 核心目標：把「畫圖」「骨架與輸出」「審美判斷」拆給不同的手，並在 AI 生成圖進入產品前用可量化的檢查擋住多改的地方。
- 分類／標籤：角色動畫素材製作／生成圖＋程式代理分工／生成結果驗收
- 目標使用者：想在 App 放輕量角色動畫、但不是插畫或動畫專業的開發者
- 工具：Meta Muse（圖像生成與檢查）／Claude Code（經 Claude in Chrome 操作 Muse）／Mesh Avatar Studio（開源，作者確認於 commit ac76b84f）／SwiftUI＋WKWebView
- 首次收錄／最近查證：2026-11-04 08:55（台灣時間）
- 證據狀態：`author-demo`（作者自述實作＋指令、檢查程式與過程截圖；正式原畫與動態成品未公開）
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：對原畫的條件（透明背景、全身、臉不被手或頭髮遮住、線條與上色清楚、縮小也能辨識）；Mesh Avatar Studio 的代理手冊 `docs/agent-guide.md`。
- 輸出：能眨眼、開合嘴、歪頭、呼吸、頭髮擺動的 `.mavatar`（含閉眼差分約 650KB）；App 用靜態圖（載入中、失敗或開啟「減少動態效果」時顯示）；SwiftUI App 內只讀同捆檔案的播放元件。

## 來源版本

### 來源A：stak22／Zenn（日文）

- 原始網址：[Muse × Claude Code で、絵を描かずに動くアバターを iOS アプリに載せた](https://zenn.dev/stak22/articles/4eae6e28ba5f29)；2026-11-03 15:46 JST（台灣時間 14:46）；原文語言：日文。
- 工具倉庫：[shinshin86/mesh-avatar-studio](https://github.com/shinshin86/mesh-avatar-studio)（作者引用，本庫未執行）。
- 取得內容（翻譯摘要）：
  1. 分工表：Muse＝畫原畫、畫閉眼等差分、看姿勢一覽圖指出崩壞；Claude Code＝與 Muse 往來、在 Studio 做骨架、姿勢檢查、匯入差分、輸出、製作靜態圖；人＝在實機判斷外觀。
  2. 骨架：Claude Code 依手冊先用 `vision-check` 量自己讀座標的準度，再用放大格線與疊圖確認眼睛範圍沒偏。注意點：眼睛張開範圍不要包到睫毛或皮膚；下眼瞼範圍要離開腮紅（原本每次眨眼腮紅跟著動，下緣上移 10px 修好）；細網格只鋪頭到胸。
  3. 姿勢一覽圖由 Claude Code 先自己看、再送 Muse 挑錯；作者強調要在手順中明寫「不准沒看圖就回報沒崩」。
  4. 閉眼：只用網格壓扁會讓睫毛弧線變波浪，改請 Muse 畫。送遮罩與條件：回傳與原圖同尺寸的完整 RGBA、遮罩外連透明度都不准改一像素、修改限遮罩邊緣內 4px、每眼畫一條向下弧線（不要笑眼）、眉毛不動（骨架會依表情移眉，畫了會變雙眉）。收件後以程式比對遮罩外差異為 0 才收。
  5. 自承失誤：比對程式一開始用亮度判斷遮罩，因遮罩 RGB 全白而永遠回報「差異 0」；改用透明度判斷後仍是 0、Studio 自帶檢查也一致，沒有實害，但作者說檢查程式應先用故意弄壞的圖確認會失敗。
  6. 輸出與 App：`--no-source` 避免把原圖原始資料打包進去；同名檔會 EEXIST，每版換名。App 以自訂 scheme 只回傳同捆檔案、封鎖所有 http(s)、不保存資料；播放時機由原生端控制、看不到時停；網頁端只回報「第一格畫好」與「失敗」兩種訊息，不傳使用者資料；不接受點擊。
- 作者報告結果：完成帶眨眼、嘴、歪頭、呼吸、髮絲的角色並放入 App；未做繪製負荷與記憶體量測。
- 失敗點／缺口：大動作（跑、吃）與換裝不在範圍；正式原畫未公開，無法看到動態成品。

## 建議操作流程（依來源整理）

1. 先寫好原畫條件交給圖像生成端，挑一張線條清楚、臉不被遮的全身圖。
2. 程式代理照工具手冊做骨架前，先量它讀座標的準度，並用格線／疊圖逐部位確認。
3. 輸出姿勢一覽圖，要求代理「看過圖才准回報」，再交另一個 AI 挑錯。
4. 需要差分（閉眼等）就給遮罩請生成端畫，收件前比對遮罩外 0 像素差異；比對程式先用故意弄壞的圖測一次。
5. 輸出時去掉原始資料、每版換檔名；App 端只讀同捆檔、封鎖外部網路。

## 可複製提示詞（本庫原創，未實跑；改寫自來源條件）

> 附件是原圖與遮罩（遮罩透明的地方才可以改）。請畫出閉眼版本：①回傳與原圖同尺寸的完整 RGBA 圖，不要裁切；②遮罩以外的像素（含透明度）一個都不能改；③只在遮罩邊緣內側至少 4px 的範圍作畫；④每隻眼睛畫一條向下的弧線，不要畫成笑眼；⑤眉毛不要動。做不到其中任何一項就直接告訴我，不要交一張接近的圖。

## 所需連接、權限與限制

- 由 Claude Code 透過瀏覽器操作 Muse 畫面屬作者的組合；本庫不推定 Muse 提供給其他代理的官方 API。
- 生成圖可能悄悄改到沒要求的地方，必須有可量化檢查；正式素材的著作權與使用條款請自行確認。
- 開源工具版本會變，作者確認於 Studio commit ac76b84f、播放元件 0.4.1。
