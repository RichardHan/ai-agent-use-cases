## 來源版本

### 來源A：mirevo_ai／Qiita（日文）

- 原始網址：[4 vCPU / 7.9GB の無料VMを実測したら、実効1.6コア・空きメモリ0.5GBだった](https://qiita.com/mirevo_ai/items/178d0af82a4fb65a9688)，2026-11-05 01:14 JST（台灣時間 00:14）；原文語言：日文。本輪以 Qiita 公開 API 讀全文。
- 取得內容（翻譯摘要）：
  1. **CPU**：π 以 3 區塊並行算 1000 萬位 11.6 秒、3000 萬位 43.6 秒，前 20 萬位與 mpmath 獨立計算比對一致。SHA-256 滿載：4 個 worker 與 2 個 worker 的 busy 都卡在約 40%，2 worker 跑 30 分鐘吞吐量波動在 ±3% 內、沒有被強制終止 → 上限是「粗細」不是「時間」。
  2. **記憶體**：MemAvailable 只有約 0.5GB、swap 為 0，超過就直接 OOM；依 RSS 外推，1 億位需改成分塊計算、中間結果落地磁碟。
  3. **磁碟**：148GB 空間屬實；寫 189MB/s、讀 1.1GB/s，作者推測是網路儲存＋快取。
  4. **網路**：出口在美國（Cloudflare 顯示芝加哥），下載最高 245Mbps 但同一對象 18–211Mbps 波動，上傳約 11Mbps。
  5. **規則**：並行最多 2 執行緒、持續重負載壓在約 1.5 核；省記憶體優先，大型中間資料存磁碟；沒有時間上限，可「細水長流」，不要「短時間猛衝」。
  6. **觀察到的限制**：VM 會整台被替換（只保留家目錄），作者觀察約 2 小時發生一次；下一輪要用心跳紀錄量壽命與時段變化。
- 作者報告結果：數字皆為 2026-11-04～05 該 VM 個體的實測，每個條件只跑 1 次；不保證其他使用者或時段相同。

## 建議操作流程（依來源整理）

1. 請代理先列出要量的項目、方法與上限（時間、資料量），經你同意再跑。
2. 每項量測寫入 CSV，並附獨立檢算（例如另一套程式驗證結果）。
3. 結論只寫觀測事實；推測（例如「網路儲存」）要標明是推測。
4. 把結論轉成之後工作的設計規則，放進代理會讀的規則檔。
5. 列出下一輪要驗證的假說與方法，定期重測。
