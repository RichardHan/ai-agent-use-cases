# UC-513：讓 Grok Bot 讀取平台上 273 位創作者的 X 數據、寫 API 規格交 Claude Code 接進資料庫，並分角色研究爆款與學本人語氣寫稿

- 情境：工作
- 標籤：社群、數據、多代理、寫作
- 網站標題：其他工具拿不到 X 數據？讓 Grok Bot 直接讀每位創作者的追蹤與互動數字，接進自家頁面，再分角色研究爆款格式、照本人語氣起草
- 一句話用途：英文作者 Logan Gott（@LoganTGott，2026-11-07）自述用 Grok Bot 經營創作者平台與內容產線：Grok Bot 原生讀 X，替平台上 273 位創作者取追蹤數、曝光、按讚與回覆，不需 X API 金鑰或開發者設定；Grok Bot 寫 API 規格，Claude Code 把路由做進自家應用，數字直接進資料庫並顯示在每位創作者頁面。另外一 Bot 一職責：一個拆解 X 上爆紅的 B2B 科技與 AI 貼文，一個翻 LinkedIn 上有數百反應的貼文；寫稿前先讀作者本人的 X 歷史，只用他說過的事；寫發表串前先研究同領域最佳串文，只吸收站得住的內容並標出無法佐證的說法；Bot 與作者在群組聊天中來回改稿；API 金鑰放安全保管欄位。日文作者 grokBotter（@chiken_ai）2026-11-09 於 note 編譯並補規約提醒。作者自述，本庫未重現。
- 核心目標：把 X 上其他工具不易取得的公開數據接進自家產品，並用分工的 Bot 支撐有依據、像本人的內容產出。
- 分類／標籤：社群數據收集／規格交接給編碼代理／語氣與佐證檢查
- 目標使用者：經營創作者或 KOL 平台、需要追多個帳號 X 表現的團隊；個人創作者可只取寫稿部分
- 工具：Grok Bot（X 讀取、多 Bot 群組、Vault）／Claude Code／自家應用與資料庫；研究另涉 LinkedIn

## 輸入與預期輸出

- 輸入：創作者 X 帳號清單；自家應用的資料庫與頁面；作者本人的 X 歷史貼文；想參考的貼文或同領域串文。
- 輸出：每位創作者的追蹤、曝光、按讚、回覆數字（進資料庫、顯示在頁面）；Grok Bot 寫的 API 規格；爆款格式拆解；以本人語氣寫、只用說過的事、無法佐證處已標記的草稿。

## 建議操作流程（依來源整理）

1. 先確認平台規約與創作者同意，決定要取的 X 公開指標與頻率。
2. 讓一個 Bot 只負責讀 X 數字，並寫出交接用 API 規格；由編碼代理（作者用 Claude Code）實作路由寫入資料庫。
3. 另設研究 Bot：只拆解爆款格式，輸出格式要點，不搬原文。
4. 寫稿 Bot：先讀本人過去貼文，只用本人說過的事；參考同領域串文時，對無法佐證的主張只加標記。
5. 在群組聊天中改稿，最後由人決定是否發布。
6. 金鑰一律放 Vault／秘密欄位，不貼進聊天或檔案。

## 所需連接、權限與限制

- Grok Bot 可讀到哪些 X 指標（尤其他人帳號的曝光）未見官方清單；作者自述可取，本庫未核。
- 自動收集 LinkedIn 資料可能違反其使用者協議（來源 B）；本庫不建議自動抓取 LinkedIn。
- 創作者數據屬他人資料，需告知與同意，並依所在地個資法規保存。
- 多 Bot 群組與 Bot 間往來都耗用量。不推定 Muse 或 ChatGPT dots 能以同樣方式原生讀 X 數據。
