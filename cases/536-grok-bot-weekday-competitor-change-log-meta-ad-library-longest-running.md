# UC-536：每個工作日早上看競爭對手的 X 與官網、只回報「和昨天比有什麼變」並記進試算表；每週一再到 Meta 廣告檔案庫抓投放最久的廣告

- 情境：工作
- 標籤：競品、監看、試算表、廣告、每日
- 網站標題：不想每天手動逛對手的帳號與網站？讓 Bot 每天早上只報變化、附連結，安靜的日子不吵你；每週再整理對手投放最久的廣告
- 一句話用途：Grok Bot 教學站 TheGrokBotGuide 整理 YouTuber Pat Simmons 的示範（影片標明由 Grok Bot 贊助）：行銷 Bot 每個工作日早上檢查指定對手的 X 帳號與網站，對照自己的紀錄只回報新貼文、優惠、價格、上市與新頁面，每筆附連結，寫進 Google 試算表並貼到 Slack；沒變化就不發訊息。每週一用 Bot 自己的瀏覽器搜尋 Meta 廣告檔案庫，把投放最久的廣告（廣告主、開始日、格式、開場鉤子、優惠）加進同一張表，之後讓做廣告的 Bot 以這張表為參考。
- 核心目標：用「只報變化＋每筆附來源」取代每天手動巡對手，並用「廣告投放天數」當作公開資料裡唯一可得的成效線索。
- 分類／標籤：競品監看／變化紀錄／廣告研究
- 目標使用者：要追蹤競爭對手動態的行銷人員、電商老闆、手動巡競品的小團隊
- 實作門檻：工具串接
- 工具：Grok Bot（routine、雲端電腦瀏覽器、X 搜尋）／Google Sheets／Slack（選用）／Meta 廣告檔案庫；原示範另用付費廣告研究工具 Foreplay 的 MCP
- 首次收錄／最近查證：2026-11-17 08:30（台灣時間）
- 證據狀態：`author-demo`（Pat Simmons 影片示範，影片由 Grok Bot 贊助，經 TheGrokBotGuide 文字整理轉述，本庫未觀看影片）＋`designed`（可複製提示詞為 TheGrokBotGuide 依示範改寫，非原作者逐字提示詞）
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：對手的 X 帳號與網站清單（可先請 Bot 從 X 找一份初稿再自己修）；試算表名稱；回報地點（Slack 頻道或對話）；每週廣告檢查的日子與品類。
- 輸出：每天一份「只有變化」的清單（每筆附連結）；Google 試算表的累積紀錄（日期、對手、變了什麼、連結）；每週新增的長期投放廣告列（廣告主、開始日、格式、開場、優惠）。

## 建議操作流程（依來源整理；本庫未實測）

1. 先請 Bot 從 X 提一份對手帳號與網站初稿，自己刪改到 5–10 個。
2. 建 routine 與紀錄表；指示寫明「只報變化、每筆附連結、沒變化不發訊息」。
3. 建好後立刻手動跑一次，逐列點開連結，確認不是編出來的。
4. 每週一次的廣告檢查另開一段，限定「只讀、不互動」；投放天數只當排序依據，不當成效證明。
5. 把表交給做文案或廣告的 Bot 當參考時，要求「取角度、不照抄」。

## 所需連接、權限與限制

- 需要 Google Sheets 連線；Slack 選用。Meta 廣告檔案庫由 Bot 的雲端瀏覽器讀公開頁面。
- 每天跑會持續消耗用量；對手數量與檢查頁數要有上限。
- 只做公開資訊研究；不要讓 Bot 用你的帳號跟對手互動。
