## 建議操作流程（依來源整理；本庫未實測）

1. 先讓 Bot 只讀程式庫，產出架構說明與文件，自己審過再提交。
2. 設一個 Routine 定期比對程式碼與文件，只在有差異時開分支改文件。
3. 把常用檢查寫成 /qa 類指令，要求它引用文件中的規則，不憑印象。
4. 新功能先寫提案（OpenSpec 的 explore／propose），本人同意後才 apply。
5. 每次改動後跑驗證技能，回報結果；學到的規則只寫在這個 Bot 自己的紀錄裡。

## 可複製提示詞（本庫原創，依來源改寫，未實跑）

> 你是［程式庫名］專屬的工程 Bot。第一步只讀不改：讀完程式庫，在 docs/ 寫出架構概覽、模組說明與執行方式，開分支給我審。之後每週［星期幾］檢查程式碼與文件是否不一致，有差異才開分支更新，沒有就回覆「無變更」。所有新功能先寫提案等我同意；每次改動後執行驗證並附結果。學到的規則只記在你自己的筆記，不套用到其他程式庫。不要直接推到 main。

## 所需連接、權限與限制

- 需要程式庫存取權；建議只給分支與 PR 權限，合併留給本人。
- 定期更新文件會消耗用量；沒變化就停止的規則可以省用量。
- dr eggbot、OpenSpec 與驗證技能都是第三方內容，安裝前自行閱讀原始碼與權限。

## 驗收與可重現性
