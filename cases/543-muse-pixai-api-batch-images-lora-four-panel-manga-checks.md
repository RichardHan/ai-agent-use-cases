# UC-543：讓 Muse 經 PixAI API 量產同一角色的插圖：先報張數與點數等你核准、四種構圖一次生成、角色 LoRA 套用比較，再做四格漫畫並分開「生成」與「排版」驗收

- 情境：創作
- 標籤：圖像、角色一致性、API、費用、核准、驗收
- 網站標題：想用 AI 代理幫你畫同一個原創角色的多張圖和四格漫畫？一位日本作者實測 Muse 接 PixAI 的完整流程與踩坑
- 一句話用途：日文作者 Sato-310（Zenn 同文帳號 satofun）自述：用 Meta Muse 經已連線的 API 輔助程式操作 PixAI API v2，以原創角色做三組檢驗。①Muse 把角色特徵寫成共用提示詞、只換構圖，一次生成正面／45 度／側臉／回頭 4 張；生成前先列出張數、模型與預估點數，作者核准後才送出；以 `POST /v2/image/create` 建立、`GET /v2/task/{id}` 查到完成並取回檔案才算成功，實測 16,000 點、約 3 分 20 秒，並分開評估「API 成功」與「圖是否符合指定」（裙長與回頭構圖有落差）。②Muse 整理 10 張學習圖並打包、擬標註，LoRA 在 PixAI 網頁版訓練（作者說公開 API 未見訓練端點），再由 Muse 搜尋並以 `loras` 陣列套用；起初搜不到，改成公開後才找到（作者不斷定唯一原因）。③四格漫畫：Muse 設計分鏡與生成條件，生成後用製作工具放框、對白泡泡與直書台詞，修台詞時只改排版 JSON 重新合成、不重生圖。作者自述實測，本庫未重現。
- 核心目標：把「生圖」交給代理自動跑，但把花錢的決定、成果是否採用、排版是否正確分開把關。
- 分類／標籤：代理操作圖像 API／角色一致性／成本核准
- 目標使用者：有 PixAI 帳號與點數、想用代理批次產出原創角色素材或短篇漫畫的創作者
- 實作門檻：工具串接
- 工具：Meta Muse（安全連接器存 API 金鑰、API 輔助程式）／PixAI API v2（Tsubaki.3 模型、LoRA）／PixAI 網頁版（LoRA 訓練）

- 證據狀態：`author-demo`（作者 Qiita 與 Zenn 文章自述實測，附生成圖、設定表與部分成功請求 JSON；本庫未重現）

## 輸入與預期輸出

- 輸入：角色基準圖與特徵描述；PixAI API 金鑰（放在安全連接器）；點數上限；LoRA 學習圖。
- 輸出：指定構圖的角色圖檔與每張消耗點數；套用 LoRA 的比較圖；排好框與台詞的四格漫畫頁。

## 建議操作流程（依來源整理；本庫未實測）

1. 把 API 金鑰放進代理的安全連接器，不貼在對話裡。
2. 每次生成前要代理先回報：張數、模型、預估點數；你核准才送出，並設單次點數上限。
3. 成功標準寫清楚：任務完成且檔案取回、副檔名與實際格式一致。
4. 角色一致性：共用一段角色描述、只改構圖；需要更穩定時另訓練 LoRA（訓練在網頁版），再請代理搜尋套用。
5. 生成與排版分開驗收：先看圖是否符合，再看框、泡泡、讀序；修台詞只改排版資料重合成。

## 可複製提示詞（本庫原創，依來源改寫，未實跑）

> 用 PixAI API 幫我畫［角色名］的 4 張圖：正面、斜 45 度、側臉、回頭，角色特徵用同一段描述（附在下面），只換構圖。送出前先列出張數、模型、每張與總預估點數，等我回「可以」才生成；總點數超過［上限］就停。完成後確認每個任務都已完成並取回檔案，檢查實際檔案格式與副檔名是否一致，最後逐張說明哪些地方和指定不同，不要自行重生。

## 所需連接、權限與限制

- PixAI 為付費點數制，生成前核准是本案的關鍵控制；API 規格以 [PixAI 官方文件](https://platform.pixai.art/docs) 為準。
- 角色與學習圖需是你有權使用的素材；LoRA 改為公開會讓他人也能看到與使用。
- 本案只涉及 Meta Muse；不推定 Grok Bot 或 ChatGPT dots 已有相同的 PixAI 連線。

## 驗收與可重現性

- 可驗收：每張圖的消耗點數與核准數字一致；檔案能被下一步工具開啟；改台詞後只有排版變、圖不變。
- 本庫未重現。
