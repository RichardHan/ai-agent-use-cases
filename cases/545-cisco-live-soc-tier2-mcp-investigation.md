# UC-545：Cisco Live 用代理串聯封包與日誌，協助二線資安分析

- 情境：開發
- 標籤：資安、事件調查、MCP、人工覆核
- 網站標題：資安警報不只看摘要：串聯封包與日誌，交給分析師覆核
- 一句話用途：Cisco Live SOC 團隊自述以事件 ID 驅動代理查詢 XDR、封包及日誌，產生二線調查報告，分析師再驗證與決定處置。
- 核心目標：縮短跨工具蒐證，同時保留人工核對和升級判斷。
- 分類／標籤：資安／SOC／事件調查
- 目標使用者：管理 XDR、封包與日誌的資安分析團隊
- 實作門檻：進階開發
- 工具：Claude Code／Cisco XDR／Endace MCP／Splunk MCP
- 首次收錄／最近查證：2026-11-20
- 證據狀態：`official`（Cisco 員工對活動 SOC 的第一手報告；非獨立測試）
- 是否獨立重現：否

## 來源版本

[Cisco：Building an Agentic Tier-2 SOC Analyst](https://blogs.cisco.com/security/clamer-soc-2026-agentic-tier-2)，2026-07-07，英文。作者報告：活動現場以事件 ID 查 XDR API、Endace 封包和 Splunk 日誌，代理按結果調整查詢並產出 HTML 報告。一次 polyfill.io 事件約五分鐘取得判斷所需脈絡，另一名二線以外的分析師獨立提出相同封鎖請求；另一次 Angler 警報由封包及日誌判為播客流量誤報，作者再人工查核得到相同結論。這是團隊對個案的報告，不是盲測準確率或普遍時效。

## 建議操作流程（依來源整理；本庫未實測）

1. 指定事件 ID、授權的日誌索引與網路位置，取得警報與觀察指標。
2. 代理依事件查封包和日誌，必要時修正時間範圍，產生含證據的報告。
3. 分析師核對原始資料、處置與升級；不要只依生成結論封鎖。

## 所需連接、權限與限制

需要 XDR API 與封包、日誌存取及 MCP 伺服器；依組織政策限制敏感事件資料和模型供應商。團隊本地 Ollama 實驗未能及時穩定跑完代理迴圈，活動中改用雲端模型；不得宣稱本地方案已成功。來源指出仍需加強規模及可靠性，未公開整體錯誤率或成本。
