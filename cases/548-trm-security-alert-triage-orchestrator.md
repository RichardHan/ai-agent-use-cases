# UC-548：TRM 安全代理依警報風險分流自動結案與人工升級

- 情境：開發
- 標籤：資安、警報分流、人工覆核、權限
- 網站標題：安全警報先補脈絡：低風險自動處理，其餘交給人
- 一句話用途：TRM 團隊報告在 Slack 啟動受工具白名單限制的安全警報代理，對少數已知低風險模式結案，其他事件附脈絡升級。
- 核心目標：減少值班警報的重複蒐證，同時限制自動處置範圍。
- 分類／標籤：資安／SOC／警報分流
- 目標使用者：管理雲端安全警報的資安團隊
- 實作門檻：進階開發
- 工具：Slack／Claude／Cloud Run／Google Cloud／Cloudflare
- 首次收錄／最近查證：2026-11-20
- 證據狀態：`official`（TRM 工程團隊第一手自述；非獨立測試）
- 是否獨立重現：否

## 來源版本

[TRM Labs：How One Agent Triages, Remediates, and Approves Across TRM](https://www.trmlabs.com/trm-tech-blog/scaling-security-in-the-age-of-ai-part-2-how-one-agent-triages-remediates-and-approves-across-trm)，Carlo Jessurun、Jayson Franklin，2026-06-10，英文。安全警報進 Slack 後由特定工作流程身分及工具白名單約束，讀取雲端與其他安全工具，對已知低風險警報在來源系統結案，其餘交人。作者報告過去 30 天約 238 個警報（17%）未通知值班人員而結案；其他工作流程的 45% 不可混作此指標，警報總數及獨立稽核未公開。

## 建議操作流程（依來源整理；本庫未實測）

1. 以限定身分接收警報，隔離不可信內容，僅提供此工作流程需要的工具。
2. 收集資產與過往處置證據，對事先界定的低風險模式決定是否結案；其他情況升級並附脈絡。
3. 重大不可逆操作等待人的明確確認；修補 PR 仍由人合併。

## 可複製提示詞（本庫設計，未實測）

> 請根據［去識別警報］、［經核准的低風險規則］和［可核對證據］提出分流建議，逐項列出符合與不符合條件；有缺漏或衝突時建議人工升級。這次只做離線判讀，不要關閉警報、改設定或連接外部系統。

## 所需連接、權限與限制

需安全工具、雲端與 Slack 存取；自動結案可能隱藏真實威脅，必須先以已知案例驗證、設定嚴格授權與回溯監控。來源另談 PR 審核與弱點修補，但此處不把它們拆成額外案例。來源將高影響操作交由人確認，不代表所有自動結案皆經人工逐案核准。

## 驗收與可重現性

以已標記的去敏警報核對結案、升級與證據鏈，重點查漏報；本庫未重現或核驗成效。

## 去重與版本紀錄

此篇記 TRM 第二代多工作流平台的警報分流；原始 CVE patch 代理是其前身，不另計一筆。與 [UC-547](547-figma-security-alert-memory-draft-pr.md) 為不同組織、工具及授權設計。
