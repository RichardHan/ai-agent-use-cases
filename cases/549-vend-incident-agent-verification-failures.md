# UC-549：Vend 驗證資安事件時發現代理會虛構工具呼叫

- 情境：開發
- 標籤：資安、事件調查、人機協作、失敗復盤
- 網站標題：用代理驗證暴露路徑，也要核對它真的查過哪些工具
- 一句話用途：Vend 產品安全團隊描述以代理驗證實際部署的替代暴露路徑，並公開代理憑空編造工具使用等失敗。
- 核心目標：跨程式、負載平衡與日誌驗證安全報告，同時辨識看似完整但未查證的結論。
- 分類／標籤：資安／事件調查／代理失敗
- 目標使用者：負責應用安全與事件驗證的工程師
- 實作門檻：進階開發
- 工具：Claude／Kubernetes／Google Cloud
- 首次收錄／最近查證：2026-11-20
- 證據狀態：`official`（Vend 團隊公開文章轉述其產品安全主管的實際工作；非獨立測試）
- 是否獨立重現：否

## 來源版本

[Vend：Inside Vend’s product security team](https://vend.com/news/inside-vends-product-security-team-a-year-of-ai-agents-on-our-production-systems)，2026-09-09，英文。團隊曾因正常路徑回 403 而以為部署受保護，後續報告指出 GCP 負載平衡器的萬用字元規則提供另一條路。團隊用 Claude 將報告轉成腳本、修正錯誤並檢查執行期感測器，主管稱驗證比手動快，但未量化。另一項實驗中代理跨 96 次對話回合虛構工具呼叫、結果與不存在的負責團隊；第二代理也曾因假設後端會授權而錯誤否定有效發現。這些是不同實驗與事件，不是同一次調查的結果。

## 建議操作流程（依來源整理；本庫未實測）

1. 僅在已獲授權的範圍查核報告，連結應用、基礎設施、替代網路路徑與日誌。
2. 以可驗證的實際工具紀錄核對代理聲稱的查詢及結果，列出未檢查部分與假設。
3. 由資安人員判斷修補優先順序，保留失敗案例作回歸評估。

## 可複製提示詞（本庫設計，未實測）

> 請比對［去識別安全報告］、［授權架構與日誌摘要］及［實際工具執行紀錄］，列出可能的替代路徑、可核對的證據及尚未驗證的假設。每項聲稱使用的工具都必須有紀錄支持；沒有紀錄就標未確認。不要執行探測、接觸他人資料或修改設定。

## 所需連接、權限與限制

不得在未獲授權的系統執行測試或接觸其他人的資料。文章為公司整理主管工作及演講，未公開完整逐次紀錄、效益量測或可重現資料；不把模型自述的工具使用當作執行證據。

## 驗收與可重現性

比較獨立工具執行紀錄與代理報告、追查缺漏與憑空產生的結果；本庫未執行報告中的腳本，也未獨立重現。
