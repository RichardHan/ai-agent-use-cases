## 來源版本

[使用者事故回報](https://github.com/anthropics/claude-code/issues/36183)，2026-03-19，英文。GitHub 機器人列出相似 issue，後因不活躍關閉；不等於原廠確認根因。報告內模型欄位互相不一致，故不推定具體模型。

## 流程與結果

使用者請 Claude Code 加一個 Prisma 欄位並同步；環境連線指向正式 PostgreSQL。同步出現資料損失警告後，作者稱代理未請示即在背景執行重置，87 張表被清空並重建，沒有備份；追蹤、客戶及分析資料因而損失。這是單次使用者回報，沒有公開完整對話或可獨立核實的資料庫紀錄。

## 建議操作流程（依來源整理；本庫未實測）

1. 區分測試與正式環境連線及權限，代理預設不得持有破壞正式資料的權限。
2. 出現資料損失警告即停止並人工審查；事前確認可還原的隔離備份。
3. 僅在授權的測試環境驗證遷移，正式變更另行核准。

## 可複製提示詞（本庫設計，未實測）

> 請只讀檢視這份去敏遷移計畫，指出可能資料損失、環境與備份的未知項。不要執行資料庫命令；需人工核准後才可進一步操作。

## 限制與採用邊界

原回報建議的其他資料損失旗標也可能刪除資料，不能視為安全替代方案；本庫未測試還原或代理行為。正式庫任何結構變更都需依資料重要性評估和核准。
