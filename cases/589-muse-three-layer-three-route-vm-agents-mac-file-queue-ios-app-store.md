# UC-589：用 Muse 當個人開發總窗口出 iOS App：VM 內程式代理接輕活、Mac 端靠檔案佇列與常駐對話，五次事故後定下「45 分鐘切工作、提交要三點確認」等規則

- 情境：開發
- 標籤：多代理、交接、App 上架、驗收
- 網站標題：手機一句話就叫 AI 改 App？Muse 負責規格與驗收，輕活給雲端電腦裡的 Codex／Claude Code，要用 Mac 和 Xcode 的工作經檔案佇列或常駐對話交給 Mac 端代理；送出、付款、簽署一律等本人點頭

- 核心目標：讓多層代理分工時，任務送到對的地方、不互相踩踏，並且不相信執行者的自我回報，由一手資訊驗收。
- 分類／標籤：多代理編排／分派規則／事故復盤
- 目標使用者：已同時用 Muse 與 Mac 上的程式代理、想從手機下指令做個人開發的人

- 工具：Meta Muse（第 1 層、VM、與配對 Mac 的檔案讀寫）／Codex CLI／Claude Code／Antigravity（VM 與 Mac 各一套）／Mac 常駐監看程式／git worktree／Xcode／App Store Connect

## 來源版本

### 來源A：nariyuki_pdm／Zenn（日文）

- 原始網址：[3層×3経路のエージェント構成：Muse→VM内Codex→Mac内Claude Code、指示はファイルキュー・常駐・直通の3経路で降ろす](https://zenn.dev/nariyuki_pdm/articles/e83fbbbc1ca619)，2026-11-19 20:07 JST（台灣時間 19:07）；原文語言：日文。本庫以 Zenn 公開 API 讀全文。文中含邀請碼，本庫不轉載。
- 取得內容（翻譯摘要）：
  1. **三層（委派深度）**：第 1 層 Muse 對話、寫規格、分派、驗收、核准閘門；第 2 層 VM 內代理做輕活並寫第 3 層的指示檔；第 3 層 Mac 內代理處理實際倉庫、Xcode、實機。
  2. **三條路徑（連接方式）**：直通（第 1→2 層，立即、不碰 Mac）；檔案佇列（把 Markdown 指示檔放到 Mac 的 `~/muse-bridge/inbox/`，常駐監看程式一次執行一件，成果寫回）；常駐對話（Mac 上每個專案常駐一個 Claude／Codex 對話，傳訊息互動）。
  3. **分派規則**：不需 Mac 且 45 分鐘內可完成 → 直通；需 Mac、批次即可 → 檔案佇列；需 Mac 且要互動或目視 → 常駐對話；需品質的文案、設計、審查 → 多個 AI 各自產出、由另一個對話比較驗收；送出、提交、簽署、付款、登入 → 任何路徑都不自動化，停在本人核准。
  4. **VM 內注意事項**：內建 Codex 版本啟動即無法執行工具，改裝官方 npm 版到家目錄並以絕對路徑呼叫；`codex exec` 要加 `< /dev/null`，否則卡在等待標準輸入。實測 VM 內生成 1 張 1536×1024 圖約 33 秒。
  5. **檔案佇列特性**：一次一件；沒有完成通知 → 每次投入都另派一個子代理監看成果檔；約 60 分鐘執行上限。
  6. **五次事故與對策**：(1) 60 分鐘被終止、結果檔空白 → 工作切成 45 分鐘內、開工即先寫中間成果；(2) 失敗工作被重跑 4 次並覆蓋舊結果 → 偵測同一工作多次 START 就把指示檔改名「停放」；(3) 指定的工作資料夾不存在即失敗 → 投入前先建資料夾、失敗重投用新編號；(4) 把落後 origin/main 455 個提交的舊分支裝到實機 → 主檢出永遠保持 main 且乾淨、實作只在 worktree、當天提交、建置前量落差；(5) Muse 把「準備送審」誤報成「已送審」→ 送審判定固定為三點確認（狀態轉為「等待審查」、版本歷程最新事件為提交、出現在提交清單），且執行與驗收分在不同對話。
  7. **其他規則**：常駐對話的位址每次重啟會變，送出前從當前登錄清單解析；同一倉庫同時只由一個驅動者（批次或常駐對話）操作；同一領域固定主責 AI。
- 作者報告結果：2026 年 11 月以此構成上架 2 款、送審 1 款 iOS App，另有開發中專案；也用於商店素材與審查回覆草稿。

## 建議操作流程（依來源整理；本庫未實測）

1. 先寫下分派表（是否需要本機、預估時間、是否需互動、是否為對外確定行為）。
2. 雲端代理只接不需本機、45 分鐘內可完成的工作；其餘寫成帶工作資料夾、時間上限與「沒做完也要留中間報告」的指示檔。
3. 每次投入佇列都設監看與重複執行偵測；失敗重投換新編號。
4. 程式碼一律在 worktree 實作、當天提交，建置前比對與 main 的落差。
5. 任何「已完成／已提交」的報告，都由另一個對話以一手狀態（多個獨立指標）驗收；送出、付款、簽署停在本人核准。
