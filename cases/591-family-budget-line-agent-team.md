# UC-591：家庭傳明細與收據，由代理團隊整理月度家計

- 情境：生活
- 標籤：家庭、記帳、人工審查、多代理
- 網站標題：家人傳收據與明細，代理分類並把疑問留給家人
- 一句話用途：以分工的代理整理家庭收支、彙整月報，分類不確定時交家人確認。
- 核心目標：減少家庭逐張輸入記帳資料的負擔，保留人工決策與分類疑問。
- 分類／標籤：家庭家計／代理分工
- 目標使用者：希望共同整理家計且能管理敏感資料的家庭
- 實作門檻：進階開發
- 工具：Claude Code／LINE
- 首次收錄／最近查證：2026-11-20
- 證據狀態：author-demo（作者自述家庭使用；公開樣本使用虛構資料）
- 是否獨立重現：否

## 來源版本

## 流程與結果

作者稱家人透過 LINE 傳收據及卡片明細，由電腦接收並分類；Claude Code 的代理分工整理台帳、統計、撰寫報告及檢視規則。家庭使用時，超過門檻的模糊支出最多每月問五件，由家人決定；家人決定規則而不是讓代理自行定案。作者描述曾遇到日文檔名 Unicode 正規化差異使檔案找不到；另在資產團隊發現代理自創規則導致數週沒有提案，後改為只採家人寫下的規則。

文章展示的月報與公開範本使用**虛構家庭資料**，不是實際家計成果；作者自述家庭使用，但未公開實際明細、分類正確率或長期節省時間。LINE 接收與手機頁面的實作細節尚未在該文公開。文章介紹的範本以對話觸發；[公開範本 README](https://github.com/dice-k-lab8787/kakei-agent-team) 另列 0.2.0 的 Windows 排程腳本，本庫未執行，不能由範本功能推斷家庭實際排程情況。

## 建議操作流程（本庫設計，未實測）

1. 用合成收據與交易資料建立分類、退款及重複記錄的例子，保留原始資料不修改。
2. 將不確定分類列為待確認；先約定提問上限及超過上限如何標示，避免把推測當作已確認。
3. 家人審閱彙總與規則提案，正式資料與權限另行決定，不自動執行任何支付。

## 可複製提示詞（本庫設計，未實測）

> 只讀我提供的虛構收據與交易清單，按類別整理月報，列出可能重複、退款和需要人工確認的項目。保留不確定性，不登入、不上傳、不修改正式帳目或付款。

## 限制與採用邊界

財務資料敏感；不要輸入卡號、帳號、密碼或真實個資到公開範本。作者說原則上資料保留在家庭電腦，但傳輸服務及手機頁面有家人約定的例外；不能推斷整條處理鏈完全離線或保證隱私。軟體費用與服務條件需自行確認，本庫未測。
