# UC-610：灌溉代理系統的時間格式誤解與過量澆水

## 流程與結果

作者在自家十區花園以土壤感測和 FAO-56 水平衡計算需求，夜間由 AI 代理選擇灌溉策略，再交控制器執行。一次原計約 17 分鐘的區域澆水約一小時，淹到樺樹花床，作者從攝影機發現。原因是控制器手動指令要求 `HH:MM`，系統卻以 `MM:SS` 傳送；文中例子 `16:48` 會被解為 16 小時 48 分鐘。這是代理系統周邊的協定錯誤，來源未證明是模型產生錯誤格式，也未說明一小時後如何停止。

作者之後改用控制器原生排程，輪詢實際狀態而非只信 HTTP 200，並設監看程式；自述控制器注入到執行有 19–24 分鐘延遲，設 25 分鐘餘裕。另一次高溫期間模型錯誤偏重避開潮濕夜晚而跳過灌溉，作者更換模型並以確定性規則處理熱壓力；文章未提供修正前後的對照試驗。

## 建議操作流程（依來源整理；本庫未實測）

1. 先對照設備文件與低風險測試，明確檢查每個介面的時間單位與上下限。
2. 將模型建議和設備執行分開，獨立驗證實際狀態並設實體停止及人工接管。
3. 記錄計畫、指令與設備回報；錯誤或缺測不可靜默當成成功。
