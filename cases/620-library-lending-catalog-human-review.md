# UC-620：圖書館設備與軟體目錄的代理初稿、人工作決定

- 情境：工作
- 標籤：圖書館、目錄、人工確認
- 網站標題：設備借用目錄的代理初稿與逐筆審核
- 一句話用途：批次查找設備和軟體資料，將新舊說明並排交給館員審核。
- 核心目標：讓借用者看懂設備或軟體的具體用途，同時保留人工修訂。
- 分類／標籤：圖書館／館藏服務
- 目標使用者：圖書館館員與網站維護團隊
- 實作門檻：進階開發
- 首次收錄／最近查證：2026-11-21
- 證據狀態：official（圖書館專案團隊自報）
- 是否獨立重現：否

## 來源版本

[NC State University Libraries 專案報告](https://www.lib.ncsu.edu/projects/refreshing-software-and-technology-lending-descriptions-agent-based-ai)，英文；圖書館報告自身專案，本庫未獨立重現。

## 流程與結果

團隊用 VS Code 中 GitHub Copilot agent 與 Claude Opus 4.6，從圖書館 API 取回設備頁、查找資料並分批產生說明，將原文和建議稿存為結構化 JSON；自製介面把兩版並列，供館員批准、保留原文或標記人工改寫。軟體頁採相同流程，代理查閱官方文件。

館方表示館員審閱全部 294 筆設備及 155 筆軟體建議稿；設備 27 筆標記需進一步審核或改寫，其中六筆偏好原文；軟體四筆先標記再修訂，最終 155 筆均批准更新。館方稱兩類更新已上線。這是同一專案，設備及軟體不拆成多案；作者未提供對照組、實際節省工時或逐筆正確率。

## 建議操作流程（依來源整理；本庫未實測）

1. 以公開目錄資料試跑小批，保留原文與建議稿，並記錄來源。
2. 由熟悉設備或軟體的館員逐項判斷、修訂並確認借用流程資訊。
3. 上線前複核與回滾，另行衡量花費時間和錯誤；不要把核准率當事實正確率。

## 可複製提示詞（本庫設計，未實測）

> 依提供的官方資料草擬設備說明與具體使用範例；標出沒有來源支持的規格，不要自行發布。

## 限制與採用邊界

本庫未測試該介面或逐頁核實上線；館方描述的是自報，不是獨立評估。模型、API、網站權限和人力有成本；避免把借閱者個資傳入模型，發布前由授權人員確認。

## 去重與關聯

本案為設備與軟體目錄改寫及人工審核，與 UC-621 的館員推薦實驗及 UC-622 的館藏查詢服務不同；共同標籤可一起探索。
