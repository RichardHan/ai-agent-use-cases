# UC-630：大學 SOC 用本機代理跨工具調查警報

- 情境：工作
- 標籤：資安、SOC、人工覆核、本機模型
- 網站標題：本機代理跨日誌查警報，分析師核對證據再決定
- 一句話用途：研究者在大學 SOC 實際警報工單上測試本機代理，結合多個工具產生調查報告。
- 核心目標：減少跨工具蒐證負擔，同時讓人檢查結論。
- 分類／標籤：資安／SOC／警報調查
- 目標使用者：資安分析師與 SOC 工程師
- 實作門檻：進階開發
- 工具：LangChain／gpt-oss／Splunk／Microsoft Sentinel／VirusTotal
- 首次收錄／最近查證：2026-11-21
- 證據狀態：author-demo（研究團隊對自身實驗的報告）
- 是否獨立重現：否

## 來源版本

[WOSOC 論文：Experiences of Using Agentic AI to Fill Tooling Gaps in a Security Operations Center](https://www.ndss-symposium.org/wp-content/uploads/wosoc26-02.pdf)，Banstola、Al Faisal、Ou，2026，英文。研究者在大學 SOC 擔任初階分析師，使用八個真實工單做人工與代理輔助的對照實驗，並交替先後次序；不是對正式上線服務的隨機試驗。

## 流程與結果

本機部署 gpt-oss 的 ReAct 代理查 SIEM、威脅情報和內部資產資料，寫出待人覆核報告。八張工單中七張輔助時間較短；一張輔助 14 分 47 秒、人工 10 分 21 秒，作者認為先做輔助帶來學習效應。另一警報中，代理僅依簽名和 IP 信譽誤判 SQL 注入；分析師要求查看實際流量後，發現可疑字樣只在 PNG 檔名，代理修正為可能誤報。

## 建議操作流程（依來源整理；本庫未實測）

1. 在授權環境接入必要的日誌與資產查詢，保留工具呼叫紀錄。
2. 讓代理列出證據、判斷及缺口；分析師核對原始流量後決定是否升級。
3. 隔離或封鎖等處置需另經人員授權。

## 限制與採用邊界

僅八張工單，實驗者也是工具建造者，不能外推節省時間或準確率；論文未以獨立 SOC 分析師做此實驗。本機模型不代表所有外部查詢都不傳資料：應先審查 OSINT 查詢內容與權限。本庫未重現。

## 去重與關聯

同一研究的多個工單不拆案；可對照 UC-631 的企業生產流程及 UC-632 的活動 SOC。
