# UC-677：讓 Muse 經 SSH 主導一整套雲端服務驗證，卡在互動登入時改由它寫好「人只要跑一次」的腳本

- 情境：開發
- 標籤：多代理、人工審批、認證、驗收
- 網站標題：Muse 經 SSH 在自家電腦查文件、裝工具、派 Codex 做事並驗收；需要互動登入或付款時，改成它備好腳本、人只貼一行指令
- 一句話用途：日文作者 uniale 在 Zenn 自述，個人驗證 Microsoft 365 的 Work IQ 時，入口從頭到尾是 Meta Muse：Muse 經 SSH 進自家 PC 調查、寫手順、建 WSL、配置官方腳本、把 MCP 註冊給 Codex、讀 Codex 的 session log 驗收；Codex 在無畫面工作階段兩次無法完成互動登入後，改為 Muse 寫一支「人在自己的終端機執行一次就完成連線到投入資料」的腳本，執行結果寫進 log，再由 Muse 經 SSH 讀 log 驗證。
- 核心目標：把人的操作壓到「必須有互動工作階段或必須負責」的最少步驟，其餘調查、腳本、執行與驗收交給代理。
- 分類／標籤：個人代理主導技術驗證／跨代理驗收／人機分工
- 目標使用者：讓個人代理經 SSH 操作自家電腦、並會派工給程式代理的開發者
- 實作門檻：進階開發
- 工具：Meta Muse（SSH 到自家 PC）／Codex（CLI 與桌面版）／WSL／PowerShell／Microsoft 365 Work IQ（MCP）

## 輸入與預期輸出

- 輸入：驗證目標（Work IQ 個人驗證）、官方文件與價格頁、自家 PC 的 SSH 存取、Codex。
- 輸出：構成與安裝手順書；WSL、CLI、官方腳本配置與 Codex 的 MCP 設定（含 TOML 語法檢查）；一支人只執行一次的資料投入腳本與其結果 log；Muse 對 Codex 工作是否真的完成的驗收報告。

## 來源版本

### 來源A：uniale／Zenn（日文）

- 原始網址：[Work IQ 検証を、ほぼ AI エージェント（Muse）に任せた記録](https://zenn.dev/uniale/articles/d86133cd25a22e)，2026-11-21 16:53 JST（台灣時間 15:53）；原文語言：日文。本庫經 Zenn 公開 API 讀全文。同作者的導入篇與結果篇（文中連結）本輪未讀。
- 取得內容（中文摘要）：
  1. 分工：人負責下指示、確認契約與付款、互動式認證、最終判斷；Muse 負責 SSH 進自家 PC 調查、手順化、寫腳本、執行指令、驗證與記錄，實作偏重的工作派給 Codex，再由 Muse 驗收回報。作者實際動手的只有：M365 租戶簽約與購買授權、管理員同意與裝置碼登入核准數次、在自己終端機貼兩行並執行一次腳本。
  2. 跨代理驗收：Muse 讀 Codex 的 session log 判斷「是否真的完成」，因此發現官方腳本顯示「完成」但實際未完成。錯誤排查例：AADSTS650052 → 缺 service principal；認證 bug → 比對已知 Issue。
  3. 失敗一：Codex 投入種子資料連續兩次 0 筆——第一次是 PowerShell 執行原則拒載認證模組；第二次是 WAM 回 window_handle_required，因為 Codex 跑在無畫面的工作階段，用不到人在互動終端機完成的登入；裝置碼也一樣，人核准了、無畫面那端仍存不下。作者結論：限制不是權限，而是代理沒有互動工作階段。
  4. 解法：由 Muse 寫一支包含執行原則處理、連線、投入（郵件、行程、檔案、聊天）與 log 輸出的腳本，人在互動終端機執行一次；Muse 之後經 SSH 讀 log 驗證成敗。
  5. 失敗二：Muse 寫的 .ps1 被人執行時錯兩次——UTF-8（無 BOM）被 PowerShell 5.1 當 Shift-JIS 讀成亂碼；字串中的 `$i:` 被解讀成磁碟機變數。第三次起改為先在 PC 端做語法檢查再交給人。
  6. 失敗三：想用 Codex CLI 非互動模式（exec）自動跑 6 個示範情境，三種方式（SSH 無畫面、先暖機 WSL、工作排程器以互動工作階段執行）都在 Work IQ MCP 初次連線卡滿 120 秒上限逾時；原因是 exec 每次都重建連線。唯一成功的是已開著、連線已建立的桌面版 Codex 對話串：人貼一行「把準備好的問題檔全部用 Work IQ 跑完、結果寫進檔案」，6 題約 3 分鐘完成。
  7. 預先定下「購買、送出、刪除需核准」的規則，代理就會在那些點停下。
- 作者報告結果：終端機操作時間人遠少於代理；卡住的地方都是結構上代理做不到的（互動工作階段、已暖好的連線、責任歸屬）。作者總結：重點不是決定交給代理多少，而是先決定它停在哪裡。
- 缺口：腳本、log 與 Muse 的實際指示文字未公開；無總耗時與費用數字。

## 建議操作流程（依來源整理；本庫未實測）

1. 先列出人保留的動作：互動登入、核准、付款、對外申請；寫成「購買、送出、刪除需核准」規則交給代理。
2. 調查、手順、安裝、設定與語法檢查交給代理經 SSH 執行；實作派給程式代理時，要求讀它的 session log 驗收，不信「完成」字樣。
3. 遇到需要互動登入的步驟，不讓代理反覆嘗試；改請它寫一支「人在互動終端機執行一次即完成」的腳本，並把結果寫進 log。
4. 腳本交給人之前，代理先在目標機做語法與編碼檢查（例如 PowerShell 5.1 的 BOM 問題）。
5. 人執行後，代理讀 log 驗證並記錄。

## 可複製提示詞（本庫原創，未實跑）

> 這次驗證由你經 SSH 在我的電腦上主導：查官方文件、寫手順、安裝與設定，實作可以派給 Codex，但完成與否要讀它的 session log 判斷。購買、送出、刪除與任何互動式登入都停下來找我。遇到需要我登入的步驟，不要重試；請寫一支我在自己終端機執行一次就能完成的腳本，先在機器上做語法與編碼檢查，執行結果寫進 log 檔，我跑完後你讀 log 驗證並回報。

## 所需連接、權限與限制

- 代理持有自家 PC 的 SSH 權限，屬高權限；宜用專用帳號並限制可執行範圍。
- 互動式認證、付款與對外申請保留給人；作者以事先規則讓代理停下。
- 文中的逾時、WAM 錯誤為作者環境（Windows、WSL、PowerShell 5.1、Codex）下的觀察，不代表其他環境。
- 不推定 Grok Bot 或 ChatGPT dots 有相同的 SSH 或 Codex 派工方式。

## 驗收與可重現性

- 可驗收：人的操作清單可逐項列出；每個「完成」都有 log 佐證；腳本交付前有語法檢查紀錄。
- 本庫未重現。
