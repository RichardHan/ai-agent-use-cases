# UC-679：夫妻各用自己的 Muse 接同一個自架「家族腦」MCP：寫入只走 API、寫入工具平時關閉，週日由 Muse 提出過期與重複整理

- 情境：生活
- 標籤：家庭行程、共享記憶、MCP、每日
- 網站標題：一人照顧小孩期間，夫妻各自的 Muse 把買菜、行程、待辦寫進自家電腦上的家族資料庫；早上 7 點家庭簡報、手機一鍵完成、週日整理建議
- 一句話用途：日文作者 meccha__eeyan 在 Qiita 自述，在自家 PC 自架標準遠端 MCP 伺服器（經 Tailscale Funnel 以 HTTPS 公開），讓配偶專用的 Meta Muse 與自己的 Muse 都能透過同一個 MCP 登記家庭的行程、採買與待辦；資料以 Google Drive 上的純 Markdown／JSON 保存，但禁止 AI 直接改檔、一律經家族腦 API，寫入工具預設關閉；另有每天 07:00 的家庭簡報與只限夫妻兩人 tailnet 的手機 PWA。
- 核心目標：在家人分處兩地、各用不同 AI 時，讓家庭的行程與待辦集中在一份不依賴特定 AI 的資料，且不被 AI 改壞。
- 分類／標籤：家庭共享資料／自架 MCP／多 AI 共用記憶
- 目標使用者：會自架伺服器、想讓家人各自的 AI 共用同一份家庭資料的家長
- 實作門檻：進階開發
- 工具：Meta Muse（夫妻各一）／自製家族腦伺服器（Node.js 標準函式庫、遠端 MCP）／Tailscale（Funnel 與 tailnet）／Google Drive／Google 日曆（唯讀 ICS）／LINE／Web Push／さくらのAI Engine（晨間簡報生成）／Claude（也可接同一 MCP）
- 首次收錄／最近查證：2026-11-23 08:50（台灣時間）
- 證據狀態：`author-demo`（作者 Qiita 長文自述，附構成表與序列圖；伺服器原碼未公開）
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：家人隨時想到的採買、孩子行程變更、聯絡事項（從各自的 Muse 或手機 PWA 輸入）；最多 3 個 Google 日曆的唯讀 ICS。
- 輸出：家族腦裡的行程、採買、待辦與家庭備忘；新增時即時 Web Push 給另一人；每天 07:00 傳到家庭 LINE 群組的時序、帶物與期限提醒簡報；每週日晚上 Muse 提出的過期與重複項目整理建議。

### 來源A：meccha__eeyan／Qiita（日文）

- 原始網址：[妻の入院・ワンオペ育児を乗り切るために進化した「家族脳」と私のAI運用全体像（2026年11月版）](https://qiita.com/meccha__eeyan/items/abdfbe853979af815f15)，2026-11-22 13:29 JST（台灣時間 12:29）；原文語言：日文。本庫經 Qiita 公開 API 讀全文。
- 取得內容（中文摘要，只取與 Muse 及家族腦相關部分）：
  1. 背景：作者配偶住院、作者一人照顧小孩，10–11 月剛好是運動會與發表會等行事密集期，帶物、集合時間與聯絡事項不斷疊加。
  2. 接法演變：原本靠 ChatGPT 自訂 GPT 的 Actions 接家族資料；作者稱 2026 年 8 月 OpenAI 停止個人帳號新建自訂 GPT 後，改在自家 PC 自架標準遠端 MCP 伺服器，經 Tailscale Funnel 以 HTTPS 公開。因為是標準協定，11 月導入的配偶專用 Muse、作者自己的 Muse 與 Claude 自訂連接器，登記同一個 URL 就能接上。
  3. 兩條安全規則：一、所有寫入只經家族腦 MCP／API；夫妻雙方都禁止 AI 經 Drive 直接改 `Family/` 下的 Markdown（會格式走樣、同步衝突）。二、平常的寫入工具預設關閉，只有需要變更的工作才開啟。
  4. 一天的流程（作者序列圖）：07:00 伺服器把行程＋Google 日曆＋帶物＋到期待辦整理成簡報送到家庭 LINE；白天配偶經自己的 Muse 等透過 MCP 登記想到的事與採買；登記後即時 Web Push 到作者手機；作者傍晚邊買邊在 PWA 一鍵完成（不呼叫 AI）；完成不發通知、留到隔天早上彙整；每週日晚上 Muse 找出家庭備忘中過期與重複的項目並提出整理建議。
  5. 晨間簡報不能斷：先用さくらのAI Engine（JSON schema 指定、免費額度）生成，失敗改本機 CLI，再失敗改回固定格式版，並在末尾註明生成來源（三段備援）。
  6. PWA 只限夫妻兩人的 tailnet，不經 Funnel 公開，檢查登入名、Host、Origin；完成時只改寫與畫面完全一致的那一行，避免誤改名稱相近的項目。
  7. 作者自己的 Muse 另負責跨 Gmail／日曆／Drive 調查與擬稿、每天早上看折價券、每月盤點訂閱收據等。給經 Drive 連接器運作、檔名搜尋可能失準的 AI（如 Muse），作者在 `00_HOME.md` 放「依需求先開哪裡」的入口地圖與 Drive 檔案 ID 表。
- 作者報告結果：不必一再傳訊問住院中的配偶「那件事怎樣了」；換過多種 AI 工具與 App，因原始檔仍在 Google Drive，記憶一筆都沒掉（作者主觀描述）。
- 缺口：MCP 伺服器與 PWA 原碼未公開；Funnel 公開端點的認證方式文中未細述；週日整理建議是否直接寫入或只提案，文中寫「提案」。

## 建議操作流程（依來源整理；本庫未實測）

1. 把家庭資料放在一份 AI 無關的純文字或 JSON 儲存，並包一層自己的 API／MCP，作為唯一寫入路徑。
2. 寫入工具預設關閉；家人各自的 AI 只在需要登記時開啟。
3. 禁止 AI 經雲端硬碟連接器直接改資料檔，只能讀。
4. 新增即時推播給另一位家人；完成不推播，改進隔天早上彙整。
5. 每天固定時間送簡報，生成失敗時有備援並註明來源。
6. 每週請個人代理找出過期與重複項目，只提建議，由人確認後再刪。

## 可複製提示詞（本庫原創，未實跑；給接上家族 MCP 的 Muse）

> 每週日晚上 9 點，讀家族 MCP 裡的家庭備忘、待辦與採買清單，找出已過期、重複或已完成卻沒標記的項目，列成表給我看，每列附建議（刪除／合併／延期）與理由。不要直接修改或刪除任何項目，也不要經 Google Drive 直接改檔；等我逐項回覆後，才用家族 MCP 的寫入工具執行。

## 所需連接、權限與限制

- 自架 MCP 經 Funnel 對外公開，等於把家庭資料放上網路端點；需自行設計認證，本庫未見作者細節。
- 家庭行程與孩子資訊屬私人資料，經雲端 AI 處理前應確認各服務的資料使用條款；作者對第三方機密資訊禁止輸入另一個 AI 服務。
- 晨間簡報由伺服器與さくらのAI Engine 生成，不是 Muse 的功能；Muse 在本案負責登記、查詢與週日整理建議。
- 不推定 Grok Bot 或 ChatGPT dots 可用相同方式接上自架 MCP。

## 驗收與可重現性

- 可驗收：所有寫入都有 API 紀錄、無 AI 直接改檔；推播只在新增時發出；週日建議表每列有理由且未經同意不執行。
- 本庫未重現。
