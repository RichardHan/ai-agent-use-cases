# UC-706：沒有 API 的 Muse 怎麼加入 Claude／Antigravity 開發團隊：共享雲端資料夾交接、唯讀讀正本、只准走 PR，兩週從查資料變成遊戲製作的進度負責人

- 情境：開發
- 標籤：多代理、交接、權限、驗收、核准
- 網站標題：Muse 不能被外部呼叫，就用「大家都讀得到的資料夾＋唯讀倉庫＋PR 審查＋人最後按下去」把它接進多 AI 開發團隊
- 一句話用途：日文作者 40dai_papa 在 Qiita 自述，用多個 AI 做手機瀏覽器小遊戲網站：Muse 負責進度與營運、Claude 負責設計／文案／審查、Antigravity 負責調查與圖像；因 Muse 沒有 API／CLI／MCP 可供外部呼叫、也讀不到 Mac 本機資料夾，改用一個由 Muse 自己建立的雲端共享資料夾交接（一件一檔、回覆用追加、完成就移走），讓 Muse 以唯讀方式讀倉庫正本，之後在另一個倉庫才開寫入但禁止直推主線、一律走 PR；兩週後 Muse 變成寫需求、實際試玩、經使用者核准後合併的進度負責人。
- 核心目標：把一個「只能靠人開口才會動」的代理安全地接進多代理流程，先窄權限、寫好撤退條件，等有成果再放寬。
- 分類／標籤：多代理協作／無 API 代理接入／檔案交接
- 目標使用者：同時用多個 AI 代理開發與營運小型網站，想把 Muse 這類無外部 API 的代理納入分工的個人開發者
- 實作門檻：進階開發
- 工具：Meta Muse（進度、試玩、合併）／Claude 桌面版與 Claude Code（設計、審查；Claude 以 Computer use 在 Muse 輸入框打字）／Antigravity（調查、圖像）／另一開發環境的程式 AI（實作、開 PR）／雲端共享資料夾／Git 倉庫
- 首次收錄／最近查證：2026-11-25 08:40（台灣時間）
- 證據狀態：`author-demo`（作者 Qiita 自述，附成品網站與踩坑對照表；交接檔與指示原文未公開）
- 是否獨立重現：否

## 輸入與預期輸出

- 輸入：雲端共享資料夾中寫給特定代理的需求檔（收件人必須寫明是 Claude 桌面版或 Claude Code）；倉庫正本（唯讀）；指定要讀的版本。
- 輸出：Muse 的調查結果與第二意見（視為二次資料，數字由 Claude 用一次資料查證前標「未驗證」）；後期為 Muse 寫的實作需求、試玩確認紀錄，以及經審查與使用者核准後合併的 PR。

## 來源版本

### 來源A：40dai_papa／Qiita（日文）

- 原始網址：[API のない AI エージェント Muse を、Claude・Antigravity と同じ開発チームに入れるまで](https://qiita.com/40dai_papa/items/07ece7fe474f926ba60b)，2026-11-25 09:31 JST（台灣時間 08:31）；原文語言：日文。本庫經 Qiita 公開 API 讀全文。前篇分工與需求檔寫法在作者 note（[「報告は証拠ではない」](https://note.com/moneystock/n/n3c57a76d7800)，本輪未讀）。
- 取得內容（中文摘要）：
  1. 作者確認（2026 年 11 月時）Muse 能讀寫檔案、網頁搜尋、操作 PC 與 Chrome、接備忘錄與郵件，但沒有可從外部呼叫的 API／CLI／MCP。考慮過三案：不用、用檔案交接（採用）、讓它用瀏覽器直接發文與上架（不採用：核准界線難畫，且會與其他 AI 的瀏覽器操作衝突）。
  2. 交接位置：原本放在 Claude 的工作資料夾，但 Muse 讀不到 Mac 本機檔案，要讀就得給大範圍權限；改成由 Muse 建一個雲端共享資料夾，全員都看那裡。追加規則：收件人要寫明是哪一個 Claude（桌面版與 Claude Code 不共享記憶）；改不了既有檔案狀態的參與者用新檔回報完成，由能改的人代為更新；不改寫別人寫的段落，訂正一律用追加。
  3. 讀正本不讀副本：起初把原稿副本放進共享資料夾，結果每次修改後副本過時，第二意見針對的是舊版。改讓 Muse 唯讀讀倉庫正本，不給寫入（權限無法只限一個資料夾、且多個 AI 都往主線寫會衝突）；代價是需求送出前要先推上去，並在需求寫明要讀哪一版。登錄前先用「金鑰形狀的字串」搜尋全部歷史差異確認 0 筆，之後秘密值、購買者資料、正式環境 ID 不進倉庫。後來另一個倉庫交給 Muse 合併遊戲變更時才開寫入，但禁止直推主線，一律走 PR、審查通過才合併。
  4. 最後一步要有人「開口」：由人對 Muse 說「處理共享資料夾裡給 Muse 的」，或由 Claude 用 Mac 畫面操作在 Muse 輸入框打字。後者的坑：背景輸入每次點擊後只進十幾個字，曾送出殘缺句子，現改為 12 字以內分段輸入，送出前放大輸入框確認。Claude 的排程工作用瀏覽器時段，不讓 Muse 操作瀏覽器。
  5. 起初只給三個「只讀」任務：網頁調查、原稿第二意見、社群趨勢觀察；並先寫撤退條件：委託 3 件若無 1 件經得起查證就停用；只要有一次寫到範圍外或對外發送就停。前 3 件約 5 分鐘回來，Muse 找到已有同題付費文章；需登入的列表取不到；第二意見有 5 點被採用。
  6. 兩週後的流程：使用者給方針與核准 → Muse 寫需求 → 另一開發環境的 AI 實作並開 PR → 審查 AI 初審 → Muse 實際試玩 → 使用者核准 → 合併。原本 Claude 夾在中間轉寫需求，因每次都有轉寫成本與延遲，改成 Muse 直連實作端。改名時 Muse 一次替換共享資料夾 25 個檔名與 4 個 PR 標題並在全員收件匣放通知。Muse 的雲端瀏覽器過不了機器人驗證，那一步交還人，不讓 AI 突破。
- 作者報告結果：成品網站上線（[まいにち10秒ゲーム](https://game.money-stock.com/)）；前 3 件委託未觸發撤退條件；無成本或時間節省統計。
- 缺口：需求檔格式、Muse 指示原文、審查 AI 的檢查清單未公開；「Muse 不能讀本機檔案、沒有外部 API」是作者在 2026 年 11 月的觀察，本庫未查官方文件。

## 建議操作流程（依來源整理並由本庫補成步驟；未實測）

1. 先列出要接入的代理能做與不能做的事，特別是「能否被外部呼叫」「能讀哪些位置」。
2. 選一個所有代理都讀得到的交接位置；規定一件一檔、回覆追加、完成移到完成區，收件人寫到具體實例。
3. 正本放倉庫並唯讀給該代理；需求前先推送、需求內寫明版本。開放前先掃描歷史中的金鑰形字串。
4. 先只給只讀任務並寫好撤退條件（例如 3 件中 0 件可查證就停、越界一次就停），輸出一律標二次資料。
5. 有成果再放寬：給寫入時只准開 PR，由審查代理初審、該代理實測、人核准後才合併；機器人驗證、對外發送等交還人。
6. 若用另一個代理代為輸入，分段輸入並在送出前確認全文；排開與其他代理共用瀏覽器的時段。

## 可複製提示詞（本庫原創，未實跑；改寫自來源流程）

> 請檢查共享資料夾〔路徑〕中收件人寫「Muse」的需求檔，逐件處理：只讀倉庫〔名稱〕的〔指定版本〕，不要寫入倉庫、不要對外發送或發文；結果以新檔追加在同一需求下，不改寫別人寫的段落，數字一律標「未驗證」並附來源網址。若需要登入、機器人驗證或範圍外的操作，停下並在回覆中寫明需要人處理的步驟。處理完把需求檔移到完成區，並列出本次讀過的檔案與版本。

## 所需連接、權限與限制

- 需要一個所有代理都能讀寫的雲端共享資料夾，以及可唯讀分享的倉庫；給寫入時要能在倉庫端禁止直推主線（分支保護）。
- 唯讀分享仍會把倉庫完整複製到對方，先清掉歷史中的秘密值。
- 由另一個代理代打字是脆弱的介面（本例有輸入截斷），只適合低頻觸發。
- 不推定 Grok Bot 或 ChatGPT dots 的外部呼叫能力與本例相同。

## 驗收與可重現性

- 可驗收：每件需求是否寫明收件人與版本；Muse 的輸出是否標二次資料並經查證；寫入是否全經 PR、審查與人核准；撤退條件是否被觸發與記錄。
- 本庫未重現。
