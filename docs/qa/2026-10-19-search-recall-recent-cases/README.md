# 2026-10-19：近期案例（UC-357–359）搜尋召回品質與同義詞補強

對象是在案例庫中搜尋「crypto / 加密貨幣晨報」、「播放清單 / 歌單」、「退追 / 取關 / 粉絲名單」的使用者。本輪針對 PR #58 新增的 UC-357、UC-358、UC-359 補充精準同義詞群組與自然語言查詢正規化，補齊缺失的搜尋回歸測試，解決最新案例難以用常見習慣用語檢索到的斷層。

## 問題、方案與範圍

基準 `eab8c92`（含前輪 combined-recovery 紀錄與 PR #58 的 357–359 新增），工作樹乾淨。此 repo 無適用 AGENTS.md。

問題證據：
1. **UC-357（加密貨幣晨報、來源查證）檢索斷層**：搜尋常見英文 `crypto` 或 `cryptocurrency`，因內文使用「加密貨幣」且無同義詞映射，完全漏掉 UC-357；搜尋中文日常「早報」，現有日報群組缺少「早報」與「morning-brief」，無法召回 UC-357 與晨報相關條目；長句「每天早上印出一頁加密晨報」、「加密新聞一手來源確認」、「點名舊聞重發」缺乏正規化。
2. **UC-358（YouTube 每日推薦影片與非公開播放清單）檢索斷層**：搜尋「playlist」或「歌單」無法召回 UC-358（播放清單）；搜尋「播放清單」無法跨召回 UC-172（歌單）；「訂閱頻道整理成試算表」、「挑10支影片非公開播放清單」、「不想被首頁演算法牽著走」等查詢缺乏正規化。
3. **UC-359（社群粉絲與關注名單條件篩選）檢索斷層**：台灣與社群常見用語「退追」、「退追蹤」、「unfollow」、「互粉」搜尋結果全為 0 筆，完全找不到 UC-359；「依條件篩粉絲該不該回關」、「檢查關注名單哪些可以取關」、「強烈建議取關」、「條件篩選與人工決定」缺乏正規化。
4. **測試缺口**：`tests/search.test.cjs` 既有 2500+ 行斷言僅覆蓋至 UC-356，完全沒有涵蓋 UC-357–359 的搜尋意圖。

- 方案 A：僅在案例正文中硬補關鍵字。會破壞案例原文自述真實性，且無法解決跨案例同義詞互通。
- 方案 B（採用）：在 `SYNONYM_GROUPS` 新增精確同義詞映射，在 `tokenize` 加入複合自然語言查詢正規化，並在 `tests/search.test.cjs` 補齊完整回歸斷言。精準且零副作用。

## 獨立審查

未負責實作的角色獨立審查 diff：
- 檢查相容性：新同義詞群組詞彙均具高領域專屬性，未對既有查詢（如生活、旅遊、薪資、排程等）產生誤傷或污染。
- 錯誤處理：空查詢、未知 token 與異常字元均安全處理，不改變現有 fallback 機制。
- 邊界情境：大小寫敏感度（`crypto` vs `Crypto`）、繁簡中文（`退追` vs `取關`）與複合標點符號均能平滑分詞。
- 資料隱私：未涉及個人密碼、金鑰、私密通訊或未公開機密。
