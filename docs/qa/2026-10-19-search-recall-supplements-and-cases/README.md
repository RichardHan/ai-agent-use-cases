對象是在案例庫首頁直接搜尋特定工作流程或情境關鍵字的訪客與維護者。本輪針對 PR #58（20:40 批次）新增的 3 項案例補充（UC-082 單一教練、UC-178 掃描轉 EPUB、UC-067 雲端電腦快照失效與備份 Bot）及近期案例（UC-357 加密晨報、UC-358 YouTube 非公開清單、UC-359 取關條件篩選、UC-355 原創檢討）在自然語言搜尋與複合詞比對時的漏詞問題，補強同義詞映射與分詞正規化，並補齊完整回歸測試。

## 問題、方案與範圍

基準 `fa2a6c4`（`origin/main`），工作樹乾淨。

問題證據：
1. **UC-082（健身教練與早晨喚醒補充 S-082B）**：
   - 搜尋「健身教練」時，因中文複合詞「健身教練」未分詞，而正文為「健身」與「教練」分開出現，導致 0 筆結果。
   - 搜尋「每天早上5點喚醒」、「每天5點喚醒教練」、「5K跑走計畫」時，整串文字被保留為單一長 token，無法命中 S-082B 之 5 點固定喚醒與 5K 計畫自述。
2. **UC-178（掃描版 PDF 轉重排 EPUB 與校對紀錄）**：
   - 搜尋「掃描轉EPUB」時，分詞為 `['掃描轉', 'epub']`，無法命中。
   - 搜尋「EPUB目錄重排」時，無法命中 UC-178 來源B（有目錄、可重排的 EPUB）。
3. **UC-067（雲端電腦快照回滾失效與備份 Bot 補充）**：
   - 搜尋「快照回到數週前」、「雲端電腦快照失效」時為 0 筆結果。
   - 搜尋「單一職責備份Bot」時，因正文為「只負責把重要資料複製出電腦的備份 Bot」及「單一職責」，無法直接命中。
4. **UC-357（加密貨幣晨報與一手來源確認）**：
   - 搜尋「比特幣晨報」、「虛擬貨幣晨報」時無法直接命中 UC-357。
   - 搜尋「一手來源查證」時，因原正規表達式強求包含「新聞」，導致未帶新聞的查詢無法分詞命中。
5. **UC-358（YouTube 訂閱頻道試算表與非公開清單）**：
   - 搜尋名詞短語「訂閱頻道試算表」時，因原正規式要求「整理成／做成」，導致直接搜尋名詞時漏詞（0 筆）。
   - 搜尋「YouTube非公開清單」時分詞為 `['youtube', '非公開清單']`，無法命中 UC-358。
6. **UC-359（粉絲名單與發水文帳號取關）**：
   - 搜尋「水文帳號取關」、「AI發水文帳號取關」時無法直接命中 UC-359。
7. **UC-355（原創與轉發檢討）**：
   - 搜尋「原創與轉發檢討」時，因原正規式強求「每天／每日」，導致缺少頻率詞的查詢分詞為 `['原創', '轉發檢討']` 而漏詞。

- 方案 A：在各案例 Markdown 正文中硬塞關鍵字。會破壞原始作者自述研究真實性，且無法解決整體搜尋分詞之通用問題。
- 方案 B（採用）：在 `SYNONYM_GROUPS` 擴充領域同義詞群組（健身、epub/電子書），在 `tokenize` 補齊自然語言複合短語分詞正規化，並於 `tests/search.test.cjs` 建立完整端到端回歸斷言。
