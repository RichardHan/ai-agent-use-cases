# 2026-11-07 進階複合篩選與門檻交集空結果智慧導引、情境問題保留探索與 E2E 瀏覽器回歸健全

## 1. 問題證據與目標使用者

### 問題證據
1. **空結果問題推薦遭無情遮蔽**：在 `assets/app.js:1900` 中，`if(!options.length && !combined.length && terms.length)` 設下過嚴門檻。當訪客已選定情境（如「生活」）或實作門檻（如「入門對話（免寫程式）」），若搜尋詞在資料庫其他分類存在但在目前條件下為 0 筆（例如生活＋代碼審查、生活＋出差報銷、入門對話＋微服務），系統會算出單一放寬條件（如「移除使用情境『生活』」），導致 `options.length > 0`，進而將所有 `.empty-problem-suggestions` 痛點問題捷徑全部隱藏。訪客只被引導「放棄目前情境」，無法得知在目前選定的情境或門檻下究竟有哪些可行的真實案例（如生活＋免寫程式下的旅遊、日報、比價、發票、郵件等十餘種問題）。
2. **缺乏情境內探索出口**：訪客被推到「移除情境」單一選項，造成體驗斷崖。
3. **E2E 瀏覽器整合驗收缺口**：先前的瀏覽器回歸（如 `tests/visitor-problem-browser.cjs`）僅覆蓋關鍵字與單純情境切換，未覆蓋「實作門檻＋情境＋關鍵字」的真實三維複合交集空結果與點擊復原驗證。

### 目標使用者
- 第一次造訪網站、依自身能力門檻（如「免寫程式」）或特定情境（如「生活」或「工作」）探索 AI Agent 案例的訪客。
- 在組合多種篩選與關鍵字時遇到 0 筆結果，希望留在目前情境／難度內嘗試其他真實可行問題的使用者。

## 2. 方案評估與取捨

- **方案 A（僅放寬 problemSuggestions 顯示門檻，無條件一律在下方列出所有問題）**：
  - *價值*：修改最少。
  - *取捨*：當移除條件選項已多時，若下方無條件堆疊過多按鈕，會使手機版畫面高度暴增，資訊過載。
- **方案 B（採用：智慧分層空結果引導＋情境內可行問題保留探索＋雙軌提示文案＋E2E 複合測試防線）**：
  - *價值*：
    1. 調整 `renderSearchFeedback`：只要在保留目前活躍篩選下仍有 >0 個可行問題捷徑，就在「放寬條件」按鈕下方獨立呈現「或保留目前篩選，探索此條件下有收錄的常見問題：」，提供即刻可點擊的落地捷徑（如在「生活＋入門對話」下展示「🏖️ 旅遊」、「🏷️ 比價」、「🧾 發票」等），確保點擊後必有結果。
    2. 優化提示文案：若同時有條件放寬與情境內問題推薦，清楚告知「可調整指定條件查看更多案例；或直接點選下方推薦問題，保留目前條件繼續探索。」
    3. 建立先紅後綠的端到端瀏覽器整合驗收腳本與單元測試，完整涵蓋 Chromium 桌面 1440、手機 390 與窄手機 320 尺寸，並跑 axe 零違規檢查。
  - *取捨*：需精確計算在各篩選組合下的問題候選數量，維持 DOM 清爽與無障礙分群（`aria-label`、`role="group"`）。
