# 2026-11-07 訪客問題檢索精準化、排班同義詞解耦與自然問句召回優化

## 1. 背景與問題證據

基準 commit：`a7155c0`（main 最新，PR #248 合併後）。原工作樹存在未提交修改，本輪使用隔離 worktree 操作。

### 核心問題
1. **排班（Shift Roster）同義詞過度連通與心智模型斷裂**：
   `assets/app.js` 的 `SYNONYM_GROUPS` 原將 `排班` 歸入 `workflow`（與 `自動化`、`cron`、`pipeline`、`排程` 同組）。訪客搜尋「排班」或「如何排班」時直接回傳高達 253 筆結果（佔全庫半數），前排全為 Facebook 發文、價格監看等無關自動化腳本；而真正處理員工班表與工時對帳的 UC-338、UC-155、UC-454 被徹底淹沒。
2. **高意圖問題自然問句與複合詞 0 筆空結果斷崖**：
   - 「如何準備面試」：分詞落入 `['準備面試']`，案例庫有 19 筆求職面試案例（UC-152、UC-035 等），但精確匹配直接回傳 0 筆。
   - 「我要審核採購合約」：未過濾「我要」且「採購合約」未切分，回傳 0 筆（全庫有 UC-154、UC-101、UC-021 等採購合約案例）。
   - 「我想報銷出差費用」：未切分「報銷出差費用」，回傳 0 筆（全庫有 UC-263、UC-103 等出差報銷案例）。
   - 「社群文案」／「社群行銷」／「文案撰寫」：未切分 `社群` 與 `文案`，回傳 0 筆（全庫有 10 筆同時命中社群與文案的高品質案例，包含 UC-268、UC-023、UC-006、UC-409 等）。
   - 「資料庫查詢」：未切分 `資料庫` 與 `查詢`，回傳 0 筆（而搜尋 `SQL查詢` 有 9 筆，`資料庫` 有 49 筆）。
   - 「履歷健檢」：未將求職履歷與健檢適當分詞，導致求職者找不到 UC-035。
3. **首頁捷徑與空結果推薦一致性缺漏**：
   首頁常見痛點缺少「社群文案」與「員工排班」；空結果推薦 `empty-problem-suggestions` 未包含社群文案與排班晶片。

## 2. 方案評估與決策

- **方案 A（選定）**：
  1. 將 `排班` 從 `workflow` 群組解耦，獨立建立專屬輪班同義詞群 `['排班', '班表', '輪班', '值班', '排班表', 'roster', 'shifts', 'shift']`。
  2. 補齊 `['文案', '文案撰寫', '撰寫文案', 'copywriting', 'copywriter', '貼文文案']` 同義詞群。
  3. 擴充 `tokenize()`：支援社群文案、採購合約、出差費用、資料庫查詢、求職面試、履歷健檢等複合詞無損切分；強化自然問句前綴過濾，並經獨立審查兩輪審核，嚴格保護實義關鍵字「發票」、「寫作」、「審核」不被前綴動詞誤截斷。
  4. 首頁與空結果推薦補齊「社群文案」與「員工排班」入口。
- **方案 B（捨棄）**：引入大型前端語意向量檢索（WASM / Embeddings），破壞 GitHub Pages 極簡秒開架構且有巨大回歸風險。
