## 2. 方案評估與取捨

- **方案 A（盲切 CJK Bigram 分詞退避）**：
  - *價值*：自動切分任意漢字為雙字。
  - *取捨*：盲切分詞嚴重破壞語意邊界，產生大量無關假陽性命中（False Positives），並破壞既有 420 項單元測試與精準同義詞規則，回歸風險極高。
- **方案 B（採用：問題預處理管線精準量詞與修飾語消除、痛點複合詞映射、擴充同義詞庫、首頁與空結果推薦、E2E 瀏覽器驗收防線）**：
  - *價值*：
    1. 在 `assets/app.js` 擴充 `preprocessProblemQuery` 預處理管線，對「一份／兩份」、「一次性」、「兩週一次／每週」、「做／整理／寄送」等修飾量詞在問題名詞前後進行語意抽取與安全消除。
    2. 在 `SYNONYM_GROUPS` 新增重構與優化群組（`重構`、`優化`、`結構重組`、`refactor`、`clean-code` 等），並將「審閱」納入合約群組。
    3. 首頁常見痛點導航補齊「代碼重構」、「發票辨識」等捷徑，空結果推薦同步擴充相應問題按鈕。
    4. 建立先紅後綠的單元與回歸測試，並在 Chromium 1440 桌面、390 手機與 320 窄手機三尺寸執行完整情境走查與 axe 零違規檢測。
  - *取捨*：正則必須設定邊界，避免誤傷專有數字（例如「5k 跑走」或「5點 喚醒」）。
