# 完整問句的搜尋退回

## 問題與對象

目標：第一次造訪、不知道工具名稱，直接把問題打成一句話的讀者。

`tokenize()` 只按空白與標點切詞，`filterEntries()` 又要求每個詞都是字面子字串，所以一句中文問句通常整段變成單一 token，必然查無結果。在基準 `eb155649` 的本機 Pages 相容預覽（`scripts/preview.py`，509 筆）以 28 句日常問句（無篩選）逐句輸入 `#query`：**25／28 顯示 `0 / 509`**，例如：

- 「怎麼讓 AI 幫我檢查合約有沒有問題」→ 0（站上「合約」24 筆）
- 「我想把家裡的帳單自動記帳」→ 0（「記帳」14、「帳單」57）
- 「有沒有工具可以幫我自動排班」→ 0（「排班」5）

既有空結果畫面只提供通用任務捷徑，以及品質不一的「只移除關鍵字… → 查看 372 筆」選項，沒有說明為什麼整句沒中。

## 兩個方案

| 方案 | 價值 | 成本與取捨 |
| --- | --- | --- |
| A：整句零結果時，用站上既有詞彙（同義詞表＋案例標籤）比對句中字面出現的詞，以最多兩個詞同時符合重查，沿用既有說明列與「只找完整句子」切換 | 直接從問句回到有結果的探索；沿用既有 UI 與歷史／網址行為，不動資料與排序 | 需限制誤判：只在整句零結果、無篩選、無引號、句長 ≥10 字時生效；結果必須窄於全庫 1/3 |
| B：只把可用詞放進空結果建議清單，維持 0 筆第一印象 | 改動更小、零誤判風險 | 多一次點擊，且要先看到 0 筆；無法改善第一印象 |

選 A，但把風險鎖在原本就沒有結果的情境；`tokenize()`、同義詞表、排序、案例資料全部未改。

## 實作

`assets/app.js`

- `libraryVocabulary(items)`：同義詞鍵＋案例標籤（2–12 字），依 `items.length` 快取。
- `sentenceCandidates(items, text, spaced, filters)`：句中出現、且站上有結果的詞；以 `termVariants` 去重（同一同義詞組只留一個），排序為詞長→結果少→出現位置，取前 5。英數字詞必須是完整 token（`ev` 不得在 `review` 內命中，沿用 PR 查詢既有的字詞邊界規則）；中文詞比對字面子字串。
- 配對時略過彼此包含的詞（`pull request`＋`request` 只是同一個詞），避免說明列重複同一概念。
- `sentenceQueryFallback(items, query, terms, filters)`：沿用 `tokenize()` 的 token 判斷是否含案例／線索編號（`uc-012`、`uc-314`、`p-002`），因此 `UC 012`、`UC_012`、`UC:012`、`UC.012`、`#314` 都會停用退回；`C# 12` 這類版本號不會被誤判（tokenizer 只在 `#` 開頭成 token 時視為編號）。
- `sentenceQueryFallback(items, query, filters)`：守門條件（≥40 筆已載入、無任何篩選、無引號、去空白後 ≥10 字、含中文）；單詞需窄於全庫 1/3 才可單獨作答，過寬的詞只能與另一個詞組成更窄的交集；回傳 `{source, segments, terms, count, mode:'words'}`。
- `searchExpansion(items, query, terms, filters)`：唯一決定點，整句已命中就回 `null`，否則依序嘗試既有 `compoundQuerySplit`（相鄰拆詞）與新退回。
- `showSearchSplitNote()`：`mode:'words'` 使用「句中包含站上既有的詞…這是字面比對，不是語意理解」文案，按鈕在展開時為「只找完整句子」、抑制時為「改用句中詞」。

`index.html`、CSS、網址參數、歷史行為未改：說明列與切換鈕沿用既有 `#search-split`，網址仍只保留訪客輸入的原句，分享連結與重新整理會重現同一狀態。

`.github/workflows/website-qa.yml`：既有 Chromium 步驟增加一行 `node tests/sentence-fallback-browser.cjs`，不新增 workflow。

## 已知限制

- 仍是字面比對，不是語意理解：句中沒有站上詞彙（或詞彙同義詞組過寬，例如「程式碼」「測試」展開後接近半個資料庫）仍為 0 筆。這是同義詞組本身的廣度，與本輪無關。
- 過寬的詞只能與另一個詞配對，因此少數問句結果仍偏寬（「分析」＋「報表」162 筆、「客戶」100 筆）；排序與說明如實反映，未宣稱精準。
- 未量測低階手機、實機、螢幕閱讀器；未做真人使用者研究；本機預覽與正式站可能因部署時間差不同版。
- 3 個既有空結果建議仍有「只移除關鍵字… → 查看 372 筆」這類偏寬選項，本輪未處理。
