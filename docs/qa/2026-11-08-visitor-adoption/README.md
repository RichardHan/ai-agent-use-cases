## 本輪改善與具體價值

1. **多條件自然語言問句連詞切分**：
   - 解決訪客使用自然連詞問句（如「合約審查且風險」、「客服且人工」、「合約審查同時風險」、「客服以及人工」、「客服 和 人工」）時，分詞器因中文未分詞而連同後續字詞視為單一 token（如 `且風險`、`且人工`）或強制要求文字包含連詞本身，導致 0 筆空結果的嚴重缺陷。
   - 引入詞邊界條件切分（`[\u4e00-\u9fa5]{2,}`），將「且」、「而且」、「並且」、「以及」、「還有」、「同時」及帶空白的「和」、「跟」、「與」精準斷開為多詞交集（AND），還原用戶多條件檢索意圖。
2. **職場高頻問題精準檢索與導流**：
   - 支援「合約比對」（24 筆，首筆 UC-234 比對核准提案與合約附件）、「法務審查」（6 筆，含 UC-154、UC-021）、「報表比對」（24 筆，首筆 UC-129 缺貨報表與庫存快照比對）、「電子報製作」（20 筆，含 UC-093、UC-382）、「庫存管理」（24 筆，前三筆含 UC-129、UC-130）。

   - 在 `SYNONYM_GROUPS` 建立「法務／法律／legal」與「電子報／newsletter／edm」同義詞組。
3. **手機端空狀態長卷軸牆收斂**：
   - 過去手機尺寸（390px/320px）遇到複合篩選空結果時，47 個全寬按鈕在空狀態堆疊出高達 2,474px 的長卷軸牆，遮蔽下方「修改關鍵字」與重設操作。

## 獨立 Reviewer 邊界修正落實

1. **連詞切分詞邊界限制**：要求連詞兩側必須具備至少 2 個中文字詞邊界（`[\u4e00-\u9fa5]{2,}`），避免將有效詞彙（如 `尚且`、`苟且`、`暫且`、`同時區`）截斷，並確保單獨搜尋 `同時` 或 `且` 時不會被清空成空字串。
2. **WCAG 2.5.3 標籤一致性（Label in Name）**：`.reader-safety-shortcut` 的 `aria-label` 開頭必須包含可見文字「查核依據與安全採用」，確保語音輸入與螢幕閱讀器使用者體驗一致。
3. **E2E 自動化滾動與焦點斷言補強**：在端到端走查中落實點擊後實際滾動位移量（scrollTop > 50px）與焦點轉移至證據說明區的嚴格斷言。
