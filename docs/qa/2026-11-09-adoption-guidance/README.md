## 問題與目標使用者

目標使用者是**讀完案例、準備動手的人**。案例詳情有一張「💡 本庫入門建議：怎麼開始與注意事項（非實測結果）」卡，內容由 `assets/app.js` 的 `extractActionableGuidance()` 從案例 Markdown 抽取：找一個標題、取該節前兩個步驟，或第一行。

這個函式認的是**固定的標題字串**。語料在 10 月之後陸續改用同義標題（`怎麼試（本庫設計，未測）`、`建議步驟（本庫設計，未實測）`、`小範圍試法（整理者設計，未實測）`、`可重用操作設計（本庫原創、未執行）`、`權限、費用與驗收`、`共通方案、可用性與權限`…），沒認到就退回通用句：

| | 顯示案例自己的內容 | 退回通用句 |
| --- | --- | --- |
| 怎麼開始 | 449 | **57（11.3%）** |
| 要注意什麼 | 409 | **97（19.2%）** |

（同一份 `corpus.json`，`assets/copy.json` 的 20 筆人工文案一併計入。）

通用句是「先閱讀原始報告與限制，再用小範圍、去敏資料設計自己的測試」。它不假，但**讀起來像這個案例的建議**，而案例自己寫的五個步驟就在同一份 Markdown 裡沒有出現；卡片只說「本庫入門建議」，沒說這一句是通則。以 UC-111 為例，檔案有 `## 建議步驟（本庫設計，未實測）` 五步，詳情頁卻顯示通用句。

反方向也有錯：少數案例的第一個候選行是**來源引用**（`[Meet dots](https://…)…2026-10-16 查閱`、`SemicolonExpected，英文，2026-09-22：…`），被當成「要注意什麼」印出來；卡片不渲染 Markdown，讀者看到的是 `[…](https://…)` 原文。

## 兩個方案

- **A（採用）把標題詞彙整理成有順序的表，加上守門條件，不改版面。** 一級是詳情頁承諾的字（`怎麼開始`、`建議操作流程`…），二級是語料實際使用的同義字（`怎麼試`、`小範圍試法`、`建議步驟`…、`權限、費用與…`…），三級保留原本的流程節後援。**層級互斥**：一級有標題命中時就只在一級裡找，不會因為那一節是空的就退到「作者實作」。守門：行首（含短前綴）的引用不當建議；標題同時寫「流程／步驟／實作」的節不當限制節；輸出一律去掉 Markdown 連結只留連結文字。
- **B 改資料：把 57 個以上案例的標題逐一改成函式認識的字串。** 一次性有效，但下批研究仍會用新寫法，而且會改寫作者／批次留下的原始標題。

選 A：這是「同一件事有多種寫法」的解析問題，該由程式吸收；B 把維護成本推進內容檔。

## 已知限制

- 本機無法讀取影像，視覺結論以 DOM 文字與幾何為準；截圖只作人工核對。
- 解析仍是**標題字串比對**，不是語意理解；全新寫法仍會退回通用句，全語料掃描測試會在新增案例時抓到。
- 「怎麼開始」只取該節前兩個步驟（沿用原設計）；巢狀 H3 子節內的步驟仍不支援（`181` 是例子）。
- 剩 11／5 個案例顯示通用句，都是沒有可辨識步驟／限制節的案例；未改寫任何案例原文。
- 未改計數口徑、證據標記或任何案例內容。
