## 方案

- **A（採用）三種狀態各自具名，共用 `coreGoalView(item)`。**
  - 宣告：頁首 `核心目標`／`目標`／`問題` 任一皆讀，卡片 `🎯 解決痛點：`（`data-core-goal-source="declared"`）、詳情「核心目標」區塊使用該句原文。
  - 章節：正文有 `## 問題…` 時，詳情在「可以幫你做什麼」下加註「核心目標｜案例頁未在頁首宣告核心目標；正文有以「問題」為題的〈那一節〉一節，請往下閱讀原文。」——只描述頁面自己有的章節標題，不代寫一句、也不宣稱那一節回答了問題。
  - 缺漏：其餘條目在相同位置寫「案例頁未宣告核心目標；可先讀這一段的用途說明與原始來源。」
  - 價值：把 9 句被丟掉的宣告補回畫面，並讓 285 個沒有宣告的條目不再用空白冒充「沒問題」。成本：`app.js` 一個 helper 加兩個渲染點、`style.css` 一行、README／範本各一段、兩支測試。
- **B 只修 parser，不動詳情。** 少寫一段文案，但 285 個條目仍是靜默缺漏，與同頁其他欄位的誠實標準不一致。不採用。
- **C 從 47 篇的 `## 問題…` 章節摘一句當核心目標。** 摘句等於本庫新寫一句主張，違反本輪目的。不採用。

選 A：問題不是「沒有目標」，而是「有宣告的看不到、沒宣告的看不出來」。具名比代寫或留白都更接近事實。
