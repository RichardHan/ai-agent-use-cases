## 問題證據

目標使用者是**讀完一篇案例、想知道「下一篇該看什麼」的人**，特別是從分享連結直接進來、沒有搜尋條件的人。

- 全庫 508 個案例頁，在「沒有搜尋條件」的情境（分享直鏈、或從完整清單開啟）下，**205 頁（40.4%）**的「延伸閱讀」只顯示一句：「目前條件下，沒有共同標籤或相同分類的其他主要案例。可關閉閱讀後調整搜尋條件。」正式站 `63f4f375` 實測 UC-005、UC-024、UC-002、UC-514 四頁都是這句話；UC-001 有 2 筆。
- 成因有兩個，都量測過：
  1. `relatedEntries()` 只接受**至少兩個**共同標籤的案例（`assets/app.js:1404`）。
  2. 作為第二層的「同分類」幾乎不存在：508 頁宣告了 **345 種**主題分類，其中 **343 種只有一頁使用**；因此全庫只有 **17 筆**建議是靠同分類產生（其餘 715 筆靠兩個以上共同標籤）。
- 直接把門檻降成「一個共同標籤」不可行：標籤分布極偏，`驗收` 150 頁、`每日` 83 頁、`核准` 70 頁、`多代理` 54 頁、`排程` 50 頁。實測放寬到單一標籤會讓 **498/508（98%）**的頁面都有建議，等於用半個資料庫共用的模板標籤湊數。
- 因此真正的問題不是「沒有相關案例」，而是「只有共同標籤較多或同分類才算數，其餘一律留白」。

## 兩個方案

- **A（採用）在既有兩層之間，加一層「只在少數案例共用的單一標籤」。**
  - 規則：第一層不變（≥2 個共同標籤）；第二層不變（頁首宣告的同分類）；第三層新增：剛好 1 個共同標籤，且該標籤在全庫案例頁出現次數 ≤ 2%（508 頁時為 10 頁）。每列都寫出原因（`共同標籤：`／`同分類：`／`相關標籤：`），第三層只填空位，不覆蓋既有建議。
  - 價值：205 頁的空白降到 **41 頁**；**沒有任何一頁失去原本的建議**（逐頁比對：遺失 0 頁、259 頁變多）。門檻由標籤實際使用次數決定，`驗收`、`每日` 這類模板標籤永遠不會單獨成為理由。
  - 成本：`assets/app.js` 一個函式與三段文案、`README.md` 一句、4 支測試、1 個 workflow path filter。
  - 取捨：第三層是「同一個具體標籤」而不是「同一件事」，所以每一列都標明是 `相關標籤`，並保留原本「標籤相同不保證用途或成效相同」的提醒。
- **B 保留規則，只改寫空白狀態，提供情境與搜尋入口。**
  - 最保守、零內容風險；但讀者拿到的仍是「沒有」，而畫面上方已經有「探索更多『生活』案例 →」，等於重複同一個出口。不採用。

選 A：錯誤的本質是「把一個具體但只出現一次的共同標籤當成沒有關係」，而不是「缺少出口」。用標籤實際使用次數當門檻，可以只修這一半，不動既有排序與既有建議。

## 邊界情況（同一支腳本，合成語料）

| 情況 | 結果 |
| --- | --- |
| 頁面沒有任何標籤 | 不建議（沒有共同標籤） |
| 兩頁都只共用同一個標籤，且全庫只有這 2 頁 | 不建議（該標籤等於整個結果集，2% 門檻不成立） |
| 分類是 `未分類` | 不產生 `同分類` 列 |
| 目前結果只有 1–2 筆 | 不建議（沒有其他主要案例／門檻不成立） |
| 結果集混入經驗頁與待查線索 | 一律不建議，只建議 `kind==='case'` |
| 全形與大小寫差異（`ＯＢＳＩＤＩＡＮ`／`obsidian`） | 視為同一個標籤（`norm()` 比對） |
| 201 頁語料中 4 頁共用（4／201 > 2%） | 不建議 |

## 已知限制

- 本環境**無法讀取截圖影像**（`Image reading is disabled`），視覺結論一律來自 DOM 文字、`getBoundingClientRect`、computed style 與 axe；截圖只供人眼核對。
- 只驗 Chromium；Firefox／WebKit 未跑（與基準相同的本機限制），雲端三引擎由 PR 上的 workflow 覆蓋。
- 2% 門檻是**規則選擇**，不是研究結果：它讓 41 頁維持空白（標籤全為模板標籤或全庫唯一），也讓 572 列屬於「單一具體標籤」。沒有量測讀者是否真的點擊這些列，也沒有做真人研究。
- 第三層的「相關」只代表共用一個少見標籤，不代表任務或成效相同；畫面上以 `相關標籤：` 與既有提醒區分，但本輪沒有逐列人工審查 572 列的語意品質。
- 2% 門檻以**目前結果集**計算，不是全庫：窄搜尋（例如 `?q=會議` 的 27 筆）門檻只有 0.54，因此單一標籤層在小結果集幾乎不會觸發。這是刻意的——在 27 筆裡共用一個標籤佔 3.7%，不構成關係；本輪的收益集中在「沒有搜尋條件」的完整清單與分享直鏈。
- 沒有改案例內容、搜尋語意、篩選、計數口徑、來源分類或既有排序。
