# 2026-11-15 詳情頁入門建議抽取邊界修復（子節步驟與複合限制標題）

## 問題證據與目標使用者

目標使用者是**開啟案例詳情評估「怎麼開始／要注意什麼」並判斷是否適合自己採用的訪客**。

全庫 524 個來源檔掃描與正式站實測（1440×900、390×844、320×740）確認 `assets/app.js` 的 `extractActionableGuidance()` 在處理以下結構時存在提取遺漏，導致案例頁退回通用預設句（`先閱讀原始報告與限制，再用小範圍、去敏資料設計自己的測試。` / `本庫尚未獨立重現；先確認權限與驗收方式，不把案例報告當成成效保證。`）：

1. **`UC-181`（出貨標籤與訂單履約準備）**：
   - 案例內有明確的合成資料檢查 5 步驟，但其位於 `## 可參考步驟（自行設計，未執行）` 下的 `### 合成資料檢查` 子標題。先前 `HOW_HEADINGS` 未收錄 `合成資料檢查`，使該案例的步驟提取落空，詳情頁第一屏只顯示通用預設句。
2. **`UC-072`（電話任務揭露與交接）與 `UC-430`（太陽能餘電充電配合）**：
   - `UC-072` 的 `## 費用、權限與可用性` 第一項為包含 Markdown 連結的服務條款/計費說明，前版在尋找 `safetyItem` 時未先過濾 `GUIDANCE_CITATION`，導致第一筆符合安全字眼但同時為 citation 的項目被選出，後續在 `pickGuidance()` 又因 citation 檢查被整項丟棄，遺漏了後方的「電話號碼、通話內容、錄音或逐字稿會涉及對外資料處理；需要最小必要資料與明確接收方。憑證不得貼進一般聊天、公開repo或提示詞。」實質安全限制。
   - `UC-430` 的 `## 官方支持、權限與費用` 前兩行亦帶官方文件連結，同樣因 safetyItem 優先選中了帶連結的 citation 而被整段排除，遺漏了「作者的方案、用量、硬體、第三方服務費及所在地費率未核，不能寫免費或固定成本。電力合約、回售規則與設備相容性均須按實際場域確認。」。
3. **`UC-278`（加工中心構型概念 3D 比較）**：
   - 案例內之 `## 實作與限制` 包含「不能推論機構可製造、剛性足夠、軸行程正確、無碰撞或可產生安全加工程式」之核心安全警示，但其標題因包含「實作」被 `LIMIT_HEADINGS` 的 `heading => /流程|步驟|操作順序|實作|指令|試法|練習/.test(heading)` 排除。

## 兩個可行方案與取捨

- **方案 A（採用）**：
  1. 在 `HOW_HEADINGS` 補充 `合成資料檢查`，使 `UC-181` 正確提取其步驟。
  2. 在 `safetyItem` 尋找時加上 `!GUIDANCE_CITATION.test(item)`，使帶連結的 citation 不會截斷後續合法的純文本安全限制條目（修復 `UC-072` 與 `UC-430`）。
  3. 校準限制標題排除條件為 `/(?:流程|步驟|操作順序|指令|試法|練習)/.test(heading) || (/實作/.test(heading) && !/限制/.test(heading))`，使同時具備「實作」與「限制」之標題（如 `實作與限制`）保留給限制提取。
  4. 擴充 safetyItem 針對機構/安全程式的邊界識別（`不能推論機構|不能推論可製造|安全加工程式`），精確捕捉 `UC-278` 第 4 點核心邊界。
- **方案 B（不採用）**：
  - 修改 4 篇案例 Markdown 的段落標題與文本排版。
  - 取捨：違反「尊重原始來源文件與標記」原則，且容易在多分支維護中引發非必要的文本衝突。
