# 2026-11-15 案例庫行內可貼指令結構化子標題提升 QA 紀錄

## 1. 訪客問題與目標使用者

- **目標使用者**：開啟案例詳情、點擊「前往方法與步驟 ↓」查看操作流程，並希望能直接一鍵複製完整提示詞／可貼指令進行試用與驗收的訪客。
- **痛點與證據**：全庫掃描盤點確認，全庫共有 13 篇案例（`UC-002`, `UC-003`, `UC-005`, `UC-006`, `UC-023`, `UC-024`, `UC-030`, `UC-041`, `UC-049`, `UC-073`, `UC-089`, `UC-314`, `UC-340`）共 15 處在章節段落中直接以 `可貼指令：…` 行內文字記錄完整且高度結構化、去敏安全的驗收／試法指令。然而因為這些指令未提升為獨立的 Markdown `###` 子標題，導致：
  1. `assets/reader.js` 的 `promptSections()` 僅按 Heading 切割章節，使這些指令無法產生獨立章節，無法被 `selectCopySections()` 捕捉為複製候選；
  2. 訪客在閱讀器中完全看不到「複製本段（含標題）」按鈕，必須手動拖曳長段文字；手動複製時極易誤選前後的分析說明或遺漏停止條件與去敏限制；
  3. 造成全庫「提示詞複製按鈕」在這些精確設計了可貼指令的章節覆蓋率缺失。

## 2. 方案取捨與選擇

- **方案 A（修改前端 reader.js 支援段落行內指令自動切割）**：
  - 價值：無需修改 Markdown 原文。
  - 成本與風險：必須在客戶端解析 AST 或以正則拆解段落節點，破壞原有標題與段落層級關係，容易因中英冒號或不同排版產生誤切或破壞段落 Markdown 語義；且增加前端執行期解析開銷與回溯風險。
- **方案 B（採用：將 13 篇案例之 15 處行內指令提升為標準 `### 可貼指令（…）` 子標題）**：
  - 價值：遵循既有 Markdown 規範，保持指令與上下文的清晰層次，精確附帶原創/未測/自設之資格限制標記，使閱讀器能原生識別並提供一鍵複製按鈕，既有 `reader.js` 零需修改。
  - 成本與取捨：需微調 13 個案例檔案，並更新 `tests/prompt-copy.test.cjs` 的斷言基準（573 → 588）。

## 4. 三大核心訪客情境實走驗收

1. **情境 1（新訪客不知道工具名稱，從問題找到適用案例）**：
   - 訪客輸入自然問題「宣傳動畫」，精確召回包含 `UC-002`（15秒產品動畫）在內的適用案例。
2. **情境 2（使用者組合搜尋與篩選，遇到空結果後恢復探索）**：
   - 輸入無匹配查詢「動畫xyz123不存在」，頁面正常呈現友好空結果提示與候選標籤；清除關鍵字後立即恢復全庫完整探索（450+ 案例）。
3. **情境 3（使用者開啟分享的詳情連結，判讀證據、查看來源並返回探索）**：
   - 訪客開啟直鏈 `?case=UC-002#explore`，進入詳情後直接見到 5 個包含資格限制標記的「複製本段（含標題）」按鈕，可一鍵複製且文字與限制齊全；點擊關閉按鈕（`#close-detail`）平順返回列表並保留原瀏覽位置。
