# 2026-11-19 主題分類說明移到選單旁

## 問題

目標使用者：在手機上打開「篩選、排序與常用搜尋」，想用「主題分類」找一組做法的人。選項是各頁自己的分類原文，不是共用主題清單。

上一輪把這句話寫進所有篩選共用的 `#facet-count-hint`。正式站 `de6247c0`、320×640、面板打開並把 `#category` 捲進畫面後：

| 項目 | 值 |
| --- | --- |
| 說明高度 | 508px |
| 說明相對視窗 | top −607、bottom −99，不在畫面內 |
| `#category` | top 310、bottom 354，在畫面內 |
| 說明是否在選單之前 | 是 |
| 水平溢出 | 無 |

第一屏看不到 `#category`，是因為 ≤760px 時面板預設收合，而且搜尋區在英雄區與抽卡之後，不是這 508px 造成的。本輪不重排首頁。

## 方案

- 採用：形狀句改寫到 `#category-shape`，放在「主題分類」選單正下方，並加入該選單的 `aria-describedby`。該段是 `<p>`，不是 `<label>` 的內容，避免點說明就打開數百個選項。共用說明不再重複這句。≤760px 用 flex `order` 把下拉列與分類名稱搜尋排到共用說明之前。說明留在文件流裡，把下一列推開，不用絕對定位，避免 761–1000px 的兩欄排版蓋住「結果排序」。
- 不採用：只把形狀句搬過去、規則牆留在原位。320px 的牆有 508px，形狀句大約 88px，剩下的規則仍擋在第一個下拉之前。
- 不採用：窄螢幕把整段說明收進另一層 disclosure。工具、來源類型與門檻的規則會被藏起來，回歸比本輪大。

## 限制

preview 不是 Jekyll。未用實體手機、讀屏或 Firefox／WebKit。影像未逐像素目視。CSS `order` 只改窄螢幕的視覺順序，線性閱讀順序仍是 DOM 順序；聚焦選單時 `aria-describedby` 仍會唸共用說明。說明留在文件流，寬螢幕上「主題分類」那一格會比旁邊的選單高，下一列因此往下移，不再用絕對定位蓋住排序。
